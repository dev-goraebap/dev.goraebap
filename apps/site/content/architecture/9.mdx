이 절은 Webcraft 지침과 레퍼런스 키트를 만들고 고치며 내린 결정과 기각한 대안을 구조, 화면, 지침 운영으로 나누어 모읍니다. 규칙 절 본문에는 결정 날짜와 이력을 섞지 않습니다. 결정에 이른 경위(증상·원인·확인)는 그 변경의 커밋과 PR 본문에 남깁니다. 날짜나 판이 붙은 결정은 그 기록과 판 이력에서 확인한 것이고, 나머지는 지침 본문이 이유와 함께 밝힌 결정입니다.

개별 프로젝트가 내린 되돌리기 어려운 기술 선택은 그 프로젝트의 기록에, 지침과 다르게 정한 예외는 `AGENTS.md`의 프로젝트 규칙 표에 남깁니다. 프로젝트 정의서의 이 절은 그 기록에서 채웁니다.

## 9.1 구조

| 결정 | 내용 |
| :--- | :--- |
| 모듈형 모놀리스 출발 | 필요한 경계를 가진 모듈형 모놀리스에서 시작합니다. 서비스·큐·캐시·복제·추상화를 처음부터 두는 안은 구체적인 요구와 운영 비용이 확인되기 전에는 쓰지 않습니다. |
| 피처별 Facade 하나 | 피처가 제공하는 계약은 `XxxFacade` 하나로 모으고 전용 입력·결과는 `Param`·`Result`에 중첩합니다. 같은 피처를 QueryFacade·CommandFacade·ViewFacade로 나누는 안과, 소비 서비스와 Facade 사이에 의미 없는 중계 포트·어댑터를 두는 안은 기각했습니다. |
| 피처별 Service 하나 | 피처마다 `XxxService` 하나에 읽기·쓰기 메서드를 둡니다. `XxxQueryService`와 명령 서비스로 나누는 안은 기각하고, 읽기·쓰기 분리는 처리 경로로 지킵니다. 기존 QueryService는 그 피처를 고칠 때 합칩니다. |
| Spi 도입 조건 | Spi는 세 조건(소유 모듈의 불변식 검증에 필요, 자기 데이터로 판정 불가, 호출 인자로 전달 불가)을 모두 만족할 때만 둡니다. 편의 조회를 위한 Spi와 양방향 참조를 숨기려고 인터페이스를 늘리는 안은 기각했습니다. |
| 피처가 조회를 소유 | 화면 조회 포트 `XxxQuery`는 소유 서비스와 같은 피처에 1:1로 두고 구현은 package-private `JooqXxxQuery`에 둡니다. 여러 피처의 SQL을 공통 조회 저장소에 모으는 안과, 포트 전용 Row와 화면 DTO 사이에 값 복사만 하는 중간 타입은 기각했습니다. |
| 동기 결과는 Facade로 | Event는 업무 사건을 전달하는 데만 씁니다. 동기 호출 결과가 필요한 유스케이스를 이벤트로 우회하는 안은 기각했습니다. |
| 서버가 계약의 원본 | API를 바꾸면 OpenAPI·생성 클라이언트 타입·호출자를 같은 변경에서 맞춥니다. 전역 success/data 래퍼를 기본으로 두는 안은 기각하고 HTTP 상태 코드와 `application/problem+json`으로 표현합니다. |

## 9.2 화면

| 결정 | 내용 |
| :--- | :--- |
| 분기점 하나(`64rem`) | 휴대폰과 데스크톱을 한 분기점으로 가르고 사이드바↔하단 탭, 팝오버↔바텀시트, 대화상자↔페이지가 모두 그 점에서 바뀝니다. 768px 같은 분기점을 섞는 안은 768~1024px에서 휴대폰 틀에 데스크톱 부품이 놓여 기각했습니다. |
| 셸 전환에서 부모 요소 유지 (2026-11-05) | 반응형 분기점이나 셸 배치를 바꿔도 페이지의 `Card` 부모 요소를 유지하고 변형과 배치 props만 바꿉니다. `Card`와 `VStack` 사이에서 부모 요소 종류가 바뀌면 페이지가 다시 마운트되어 작성 중인 초안이 사라졌습니다. |
| 첫 화면 규칙 (2026-11-08) | 앱 코드가 오기 전 첫 화면을 빌드 때 HTML에 넣습니다. 로그인 뒤 업무 앱은 첫 방문 덮개(`BootCover`), 공개 문서·랜딩은 실제 본문을 미리 그린 SSG입니다. 스크립트와 테마 CSS가 오기 전에 빈 화면이나 테마 없는 화면이 보였습니다. 덮개 그림은 제품마다 자기 표시로 바꾸고 다른 제품의 그림은 옮기지 않습니다. |
| 가리는 막 없는 전환 (0.8.0) | 화면 이동에서 본문을 가리는 막 대신 카드 위쪽 진행 표시와 준비된 화면 사이의 교차 페이드를 씁니다. 화면 전체 스켈레톤은 모양이 바뀌는 본문과 높이가 맞지 않고, 영역별 덮개는 같은 판정이 화면마다 늘어나며, 콘텐츠 막은 상세 안 사이드바까지 덮고 재방문에서도 떠 기각했습니다. 캐시는 즉시 그리고 150ms가 넘는 대기만 진행 표시로 알립니다. |
| 리치 본문 16px (0.8.0) | 본문 칸과 상세 본문을 데스크톱·휴대폰 모두 16px, 줄 높이 1.7로 둡니다. 조밀한 목록·도구용 본문 토큰(13px·15px)과 긴 글을 읽고 쓰는 영역의 가독성 요구를 나누고, 작성 칸과 상세 본문의 크기를 맞췄습니다. |
| 넓은 사이드바 | 사이드바는 열 때 340px, 220~380px로 조절합니다. 다른 제품·지침의 기본(250~320px)보다 넓은 것은 메뉴 이름과 하위 항목을 말줄임 없이 보이기 위해서입니다. |
| 메뉴 글자색 | 메뉴 글자는 보조 글자색, 포인터가 올라온 항목과 현재 항목만 본문 글자색으로 둡니다. 메뉴가 40개를 넘는 가이드에서 무겁게 보였는데, 가이드에서만 바꾸는 안은 키트와 가이드의 모양이 갈라져 기각하고 키트 테마에서 바꿨습니다. |
| 마스킹은 양식에만 | 목록 위 대화상자(라우트 마스킹)는 자기 주소가 있는 작성·수정 양식에 쓰고, 읽는 대상의 상세는 자기 페이지로, 목록을 보며 훑는 것은 미리보기 패널로 엽니다. 닫기에서 브라우저 뒤로가기만 무조건 호출하는 안은 이전 기록이 없을 때 갈 곳이 없어 쓰지 않습니다. |

## 9.3 지침 운영

| 결정 | 내용 |
| :--- | :--- |
| 사본 없는 연결 | 프로젝트는 지침 사본을 두지 않고 `AGENTS.md` 하나로 사용자 범위에 설치한 플러그인을 따릅니다. 플러그인 하나를 갱신하면 연결된 모든 프로젝트가 새 지침을 따릅니다. 예전 사본 방식(`.agents/skills`의 지침 사본과 동기화 스크립트·시작 훅)은 걷어내고, 사본에서 고친 부분은 프로젝트 규칙으로 옮기는 전환 절차를 둡니다. |
| 키트는 골라서 채택 | 레퍼런스 키트는 설계와 코드의 스냅샷이며 제품 전체를 생성하는 템플릿이 아닙니다. 설치·동기화로 제품 코드를 복사하거나, 공통 변경을 이미 채택한 프로젝트에 자동 적용하는 안은 기각했습니다. |
| 견본은 가이드 안 iframe (2026-11-07) | Storybook을 걷어내고 가이드 문서 안에 실제 키트 견본을 iframe으로 띄웁니다. 정적 그림·캡처는 조작할 수 없고 키트가 바뀔 때마다 다시 떠야 하며, 별도 Storybook은 가이드 테마 선택을 따르지 않아 기각했습니다. 조작 검증은 견본과 떼어 테스트 파일로 옮겼습니다. |
| 기기 전환으로 휴대폰 견본 대체 | 휴대폰 견본을 따로 두지 않고 견본 틀에서 데스크톱(1024px)·휴대폰(390px)을 바꿔 같은 견본을 봅니다. 내용이 같던 휴대폰 견본 13개를 지우고, 검사는 모든 견본을 두 기기로 그립니다. |
| 견본 범주(Patterns·Playground) | 여러 화면이 지키는 동작 계약은 Patterns에 두고 그 견본은 Playground 앱을 해당 상태로 띄웁니다. 사용 패턴 범주를 없애는 안은 화면에 묶이지 않는 여는 방식을 찾을 수 없어서, 모두 템플릿으로 만드는 안은 같은 계약이 여러 템플릿에 흩어져서 기각했습니다. |
| 가이드를 React SPA로 (2026-11-08) | 가이드 사이트를 Astro에서 키트와 같은 React·Vite·TanStack Router SPA로 옮겼습니다. 처음에는 작업이 크고 정적 HTML을 잃는다는 이유로 기각하고 Astro 클라이언트 라우터를 썼지만, 테마 스타일 유실과 셸 재마운트를 막는 우회가 쌓여 전환했습니다. 지침 문서는 스킬 Markdown을 사본 없이 그대로 빌드하며, 문서별 정적 HTML은 공개할 때 프리렌더로 붙입니다. |
| 지침 제안은 원본 저장소 이슈로 (0.8.0) | 공통 지침 제안을 Webcraft 원본 저장소 이슈로 일원화합니다. 프로젝트 세션에서 바로 PR을 올리는 안은 다른 저장소 체크아웃·글쓰기 위임·판 올리기가 끼어 무거워서, 로컬 제안함은 다른 사용자의 제안을 받을 수 없어서 기각했습니다. 프로젝트 규칙 표에는 이슈 번호나 제안 표시를 붙이지 않습니다. |
| 규칙과 경위 분리 | 규칙 절에는 지금 지키는 규칙과 이유, 예시만 두고 결정 날짜·이력·실행 명령은 쓰지 않습니다. 에이전트가 다시 시도할 만한 기각안은 꼬리 구획 "근거"나 이 절의 표에 두고, 경위는 커밋과 PR 본문에 남깁니다. 스킬마다 개선 기록 파일(`notes.md`)을 두던 방식은 이 절·커밋과 내용이 겹치고 그 파일을 읽는 지침이 없어 2026-11-11에 걷었습니다. |
| Astryx 권장 우선 (2026-11-11) | Astryx가 권장하는 방식이 이 지침과 다르면 Astryx를 따르고 지침과 키트를 맞춥니다. 우리 규칙을 갈아엎게 되더라도 그렇게 합니다. 지침 원본(Webcraft)을 먼저 고치고, 그 뒤에 이를 따르는 프로젝트에 적용합니다. Astryx 0.6~0.7은 관리 블록·통합 패키지·템플릿·`doctor` 검사로 에이전트를 직접 이끄는데, 이 지침이 Astryx 명령과 순서를 따로 적어 두면 버전마다 낡기 때문입니다. 키트 스타일은 같은 이유로 StyleX(`xstyle`, `stylex.props`)로 옮기며, 일반 CSS 경로를 유지하는 안은 Core 템플릿이 모두 StyleX라서 기각했습니다. |
| shadcn 레지스트리로 전환 (2026-11-12) | 화면 부품 기반을 Astryx에서 shadcn/ui(Base UI) + Tailwind CSS v4로 바꾸고, 레퍼런스 키트를 shadcn 레지스트리 `@webcraft`로 배포합니다. 사용자가 결정했습니다. shadcn 쪽 화면이 더 깔끔했고, 부품을 레지스트리로 받아 프로젝트가 소유하는 방식이 "필요한 파일만 옮겨 소유한다"는 기존 원칙과 맞습니다. 규칙의 뜻과 수치는 유지했습니다. Astryx를 유지하고 프로젝트 예외로 shadcn을 허용하는 안은 지침과 실제 구현이 갈라져 기각했습니다. 바로 위 "Astryx 권장 우선"은 이력으로 남깁니다. |
| arc42 메뉴 (0.9.0) | 가이드 메뉴를 arc42 1~9절로 다시 묶고 모든 지침 Markdown에 `arc42` 번호를 붙입니다. 지침을 읽는 사람과 프로젝트 정의서를 쓰는 에이전트가 같은 절 구조에서 규칙과 화면 해설을 찾고 연결하게 하기 위해서입니다. |

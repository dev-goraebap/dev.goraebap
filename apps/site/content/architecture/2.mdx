이 절은 Webcraft를 따르는 앱이 설계와 구현에서 벗어나지 않는 기술 조합과 작업 방식을 다룹니다. 기본 스택은 React·TypeScript·Vite·TanStack Router/Query와 Astryx, Java·Spring Boot·jOOQ 모듈형 모놀리스, Flyway로 관리하는 관계형 DB입니다. 다만 기존 프로젝트가 이미 다른 기술이나 디자인을 택했다면 그 선택과 `AGENTS.md`의 프로젝트 규칙이 우선하며, 기능 작업 중에 스택 전환을 끼워 넣지 않습니다.

## 2.1 기술 제약

새 프로젝트나 지정이 없는 영역은 아래 조합을 기본으로 씁니다. 버전과 패키지 루트, 실제 DB 엔진은 프로젝트가 정합니다.

| 영역 | 제약 | 이유 |
| :--- | :--- | :--- |
| 프론트엔드 기반 | React·TypeScript·Vite | 레퍼런스 키트와 실행 견본이 같은 조합으로 만들어져 있어 필요한 파일을 그대로 옮겨 쓸 수 있습니다. |
| 라우팅·서버 상태 | TanStack Router와 TanStack Query | 서버 데이터는 Query, 확정 조건은 Router의 검증한 URL이 소유하고, loader와 페이지가 같은 `queryOptions`·캐시를 씁니다. 라우트 마스킹과 전환 전 준비도 이 조합에 맞춰 정해져 있습니다. |
| 프론트 파일 구조 | 공식 `feature-sliced-design` 스킬의 레이어·슬라이스·공개 API | Webcraft가 FSD 규칙과 검사기를 따로 유지하지 않고 공식 지침을 따릅니다. |
| 화면 부품과 아이콘 | Astryx 부품과 Solar 아이콘. 화면은 의미 이름(`search`, `back`)으로 아이콘을 부르고 Solar 매핑은 생성 스크립트 한 곳에 둡니다. | 부품·테마·아이콘을 한 원본에서 가져와 화면마다 다시 그리지 않습니다. 프로젝트가 정한 디자인이 있으면 그것이 먼저입니다. |
| 반응형 분기점 | 휴대폰과 데스크톱을 `width < 64rem` 하나로 가릅니다. | 사이드바↔하단 탭, 팝오버↔바텀시트, 대화상자↔페이지가 같은 점에서 바뀌어야 합니다. 768px 같은 분기점을 섞으면 768~1024px에서 휴대폰 틀에 데스크톱 부품이 놓입니다. |
| 글꼴 | Pretendard와 JetBrains Mono를 앱 진입점의 base.css에서 불러옵니다. | 이름만 부르고 파일을 불러오지 않으면 운영체제 기본 글꼴로 대체됩니다. |
| 백엔드 | Java·Spring Boot·jOOQ, 모듈형 모놀리스 | 필요한 모듈 경계를 갖춘 한 애플리케이션에서 시작하고, 별도 서비스·큐·캐시는 요구와 운영 비용이 확인될 때만 둡니다. |
| 도메인 코드 | 프레임워크에 의존하지 않는 순수 Java. 엔티티는 업무 메서드로만 바꿉니다. | 업무 불변식이 프레임워크나 Setter로 우회되지 않게 합니다. |
| DB와 마이그레이션 | Flyway 마이그레이션과 jOOQ 코드 생성. 공유 환경에 적용한 마이그레이션은 고치지 않고 다음 버전을 더합니다. 생성 파일은 손으로 맞추지 않습니다. | 스키마 이력과 생성 코드가 한 원본에서 나오게 합니다. 엔진은 프로젝트가 정하며 특정 엔진을 모든 프로젝트에 강제하지 않습니다. |
| HTTP 계약 | 서버가 계약의 원본입니다. HTTP 상태 코드를 쓰고 전역 success/data 래퍼를 두지 않으며, 오류는 `application/problem+json`, 절대 시각은 UTC로 보냅니다. | OpenAPI에서 생성한 클라이언트 타입과 실제 호출자를 같은 변경에서 맞출 수 있습니다. |

## 2.2 조직·작업 제약

사람이든 에이전트든 Webcraft를 따르는 프로젝트에서 일할 때 다음 작업 방식을 지킵니다.

| 제약 | 내용 | 이유 |
| :--- | :--- | :--- |
| 프로젝트 규칙 우선 | `AGENTS.md`의 "프로젝트 규칙" 표가 플러그인 지침보다 우선합니다. 요청이 지침과 부딪히면 그때만 한 번 "이 프로젝트만 예외", "지침을 고치자(제안)", "지침대로 하기" 중에서 사용자에게 묻습니다. | 제품 제약·기존 시스템·팀 합의를 공통 지침이 덮어쓰지 않게 합니다. |
| 지침 사본 금지 | 프로젝트에는 지침 사본을 두지 않고 `AGENTS.md` 하나만 둡니다. 개인 설치 경로나 플러그인 내부 파일 경로도 적지 않습니다. 길어진 예외만 `.agents/rules/<지침>.md`에 지침과 다른 부분만 씁니다. | 플러그인을 갱신하면 연결된 모든 프로젝트가 새 지침을 따릅니다. |
| 판 확인 | 작업 시작 때 `AGENTS.md`의 최소 판과 설치된 플러그인 판을 비교합니다. 낮거나 지침을 읽을 수 없으면 추측으로 진행하지 않고 저장소 밖에 이어받기 문서를 남깁니다. | 맞지 않는 지침으로 만든 변경을 막습니다. |
| 요청받은 일만 내보내기 | 커밋·푸시·게시·배포·플러그인 설치는 사용자가 요청하거나 허용한 범위에서만 합니다. 다중 에이전트, 자동 커밋·병합을 전제하지 않습니다. | 되돌리기 어렵거나 밖으로 나가는 일은 사람이 정합니다. |
| 비밀값과 업무 데이터 | 비밀값은 실행 환경의 비밀 저장 수단으로 관리합니다. 계정·접속 정보·업무 데이터를 공통 지침·시드·견본·이어받기 문서에 넣지 않습니다. | 공개 지침과 키트로 비밀이 새지 않게 합니다. |
| 운영 데이터 | 운영 DB와 운영 데이터를 검증용으로 바꾸지 않습니다. 운영 데이터 삭제나 되돌리기 어려운 변환은 사용자가 승인한 범위를 확인합니다. | 검증이 사고가 되지 않게 합니다. |
| 공통 지침 변경 | 여러 프로젝트에 맞는 개선은 일반화한 이슈 본문을 사용자에게 보이고 승인을 받아 Webcraft 원본 저장소 이슈로 올립니다. 받아들일지는 플러그인 관리자가 정합니다. | 공개 게시라 되돌리기 어렵고, 한 프로젝트의 우연한 구현을 공통 규칙으로 올리지 않기 위해서입니다. |
| 키트 코드 채택 | 레퍼런스 키트는 설치·동기화만으로 제품 소스에 복사되지 않습니다. 실제로 쓸 파일만 프로젝트 소유 코드로 옮기고, 공통 원본과 프로젝트 사이의 변경을 자동으로 전파하지 않습니다. | 채택한 코드는 그 프로젝트가 소유하고 책임집니다. |

## 2.3 프로젝트가 정하는 것

Webcraft가 값을 정하지 않는 항목은 비워 두지 않고 프로젝트가 정해 `AGENTS.md`의 프로젝트 설명이나 프로젝트 기록에 적습니다. 지침과 다르게 하는 결정만 프로젝트 규칙 표에 적습니다.

| 항목 | 근거 지침 |
| :--- | :--- |
| 언어·프레임워크 버전, 백엔드 패키지 루트, DB 엔진과 버전 | backend, database |
| 업무 도메인, 모듈 목록, 단일 조직·다중 조직 같은 제품 범위 | architecture |
| 개발 경로·포트·개발용 로그인 방법·검사 명령, lint와 경로 별칭 | frontend, goraebap-mode |
| API 경로 접두사와 식별자 형식, OpenAPI 생성 명령과 경로 | api |
| 숨겨야 하는 대상의 존재 노출 정책, 업무 시간대 | api |
| 외부 연동 대상과 그 타임아웃·재시도·멱등성 계약 | architecture |
| 인프라·호스트·태그·배포 권한, 백업과 복구 수단 | architecture, database |
| 키트와 다른 디자인 선택, 특정 Astryx 버전의 버그와 우회 | design-system |
| 기록 위치와 이슈 도구 | goraebap-mode |

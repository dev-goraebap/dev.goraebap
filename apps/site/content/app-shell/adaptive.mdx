좁은 화면(휴대폰·태블릿 세로)에서 앱 셸의 탐색·도구·상세·오버레이를 어떤 부품과 주소 규칙으로 바꿀지 정합니다. 이 가이드에서 반응형은 같은 화면 요소를 폭에 맞춰 줄이는 것이고, 적응형은 같은 주소와 데이터를 기기 폭에 맞는 다른 부품으로 보여 주는 것입니다. NN/g가 정의하는 적응형은 서버에서 기기를 감지해 다른 화면을 내려주는 방식이지만, 여기서는 클라이언트에서 창 폭을 기준으로 부품을 바꿉니다. Linear와 Plane은 웹에서 휴대폰 전용 탐색과 오버레이 전환을 따로 설계하지 않았으므로(Linear는 2025년 10월 네이티브 앱에 하단 툴바를 두었고 웹 모바일 설계는 없으며, Plane은 768px 미만에서 사이드바만 접히고 하단 탭은 확인되지 않음), 이 페이지의 규칙은 대부분 `[고래밥]` 결정입니다.

규칙의 성격은 `[관례]`(여러 제품·지침이 수렴한 기준), `[고래밥]`(관례가 없거나 관례와 다르게 정한 결정), `[선호]`(취향으로 고른 모양)로 표시합니다. 구분 기준은 [읽는 법](/#규칙의-세-가지-표시)을 따릅니다.

## 1024px 분기점 하나에서 부품을 함께 바꾼다

- `[관례]` 전환 분기점은 하나로 통일하고, 기기 종류가 아니라 창 크기([Android Window size classes](https://developer.android.com/develop/ui/compose/layouts/adaptive/use-window-size-classes))로 판단합니다.
- `[고래밥]` 분기점은 `1024px`(`64rem`)입니다. 지침마다 전환 폭은 다르지만([Atlassian Navigation system layout](https://atlassian.design/components/navigation-system/layout/examples) 1024px 미만 오버레이, [Primer PageLayout](https://primer.style/components/page-layout) 768px, Android 600px·840px), 1024px보다 작게 잡으면 태블릿 세로 화면에서 데스크톱 사이드바와 터치 조작 크기가 섞입니다.

창 폭이 1024px 미만이 되면 아래 요소를 같은 지점에서 함께 바꿉니다. 사이드바와 하단 탭은 동시에 보이지 않으며, 휴대폰에는 데스크톱의 셸 배치 구분(Inset·Split)이나 팝오버를 두지 않습니다. 창 폭이 바뀌어 분기점을 넘나들어도 페이지의 부모 요소 종류는 바꾸지 않아 작성 중인 초안이 다시 마운트되지 않게 합니다.

| 역할 | 데스크톱 (1024px 이상) | 휴대폰 (1024px 미만) | 관련 규칙 |
| --- | --- | --- | --- |
| 주 탐색 | 왼쪽 사이드바 | 하단 탭 (앞 4곳 + 더보기 바텀시트) | [셸과 사이드바](/app-shell/shell-and-sidebar/) |
| 그 자리에서 값 고르기·도구 메뉴 | 팝오버 | 바텀시트 | [필터와 표시](/app-shell/filters-and-display/), [표현 고르기](/app-shell/choosing-presentation/) |
| 짧은 양식·라우트 마스킹 | 대화상자 | 전체 화면 페이지 | [표현 고르기](/app-shell/choosing-presentation/), [라우트 마스킹](/app-shell/route-masking/) |
| 미리보기 패널(`?peek=`) | 목록 옆 비모달 패널 | 대상의 전체 화면 페이지로 전환(`replace`) | [미리보기 패널](/app-shell/peek/) |
| 표 | 다중 열 표 | 핵심 속성만 남긴 행 목록 | [컬렉션](/app-shell/collections/) |
| 보드 | 여러 열 나란히 표시 | 열 하나씩 넘김 | [컬렉션](/app-shell/collections/) |

표의 휴대폰 전환에서 [NN/g(Mobile tables)](https://www.nngroup.com/articles/mobile-tables/)는 머리글과 첫 열을 고정하고 가로로 스크롤하는 방식을 다루며, 표를 행 목록으로 바꾸는 방식은 별도 출처가 확인되지 않은 관행이므로 `[고래밥]` 규칙으로 둡니다.

## 주 탐색을 하단 탭과 더보기 시트로 둔다

1. `[관례]` 휴대폰의 주 탐색은 화면 아래에 고정된 하단 탭입니다. 탭은 4~5칸으로 두고 항상 보이며, 아이콘과 이름을 함께 표시합니다. 같은 목적지를 넓은 화면에서는 왼쪽 탐색으로, 좁은 화면에서는 하단 바로 보여 줍니다([Android: Build adaptive navigation](https://developer.android.com/develop/adaptive-apps/guides/build-adaptive-navigation), [NN/g: Mobile navigation patterns](https://www.nngroup.com/articles/mobile-navigation-patterns/)). 햄버거 메뉴처럼 숨긴 탐색은 발견성이 가장 낮고 사용률이 절반 가까이 떨어지므로([NN/g: Hamburger menus](https://www.nngroup.com/articles/hamburger-menus/) 실험에서 숨긴 메뉴 27% 대 보이는 메뉴 48%) 주 탐색으로 쓰지 않습니다.
2. `[고래밥]` 하단 탭은 현재 메뉴 공간의 앞 네 곳과 다섯 번째 `더보기` 탭으로 구성합니다. `더보기`를 누르면 탭에 없는 나머지 메뉴 목적지를 바텀시트로 열며, 내 계정·관리 같은 하위 공간에 있을 때는 그 공간 이름과 돌아가기 동작을 함께 둡니다. [Apple HIG(Tab bars)](https://developer.apple.com/design/human-interface-guidelines/tab-bars)는 More 탭 같은 오버플로를 피하라고 권고하고 Android와 NN/g는 5개 상한만 안내하지만, 업무 도구는 주 메뉴 목적지가 5개를 넘는 경우가 많고 숨긴 메뉴보다 눈에 보이는 `더보기`가 낫다고 판단했습니다.
3. `[선호]` 하단 탭 높이는 `3.5rem`에 기기 홈 표시줄(안전 영역) 높이를 더한 값으로 두고, 현재 선택된 탭은 진한 글자와 채운 아이콘([아이콘](/common/icons/))으로 표시합니다.

## 일반 페이지와 상세·작성 화면의 구성을 나눈다

| 화면 | 구성 |
| --- | --- |
| 일반 페이지 | 최소 `60px` 머리 줄 하나에 현재 이름(위 단계로 가는 `←`)과 오른쪽 끝의 앱 도구(검색·알림·내 메뉴), 필요하면 툴바, 본문, 하단 탭 |
| 상세·작성·대화 | 앱 도구와 하단 탭을 치운 전체 화면. 맨 위에 `←`·이름·자기 도구, 화면 바닥에 고정 동작 줄 |

- `[고래밥]` 상세 본문, 작성 양식, 대화 화면처럼 내용 자체에 집중하거나 가상 키보드를 쓰는 화면에서는 하단 탭과 앱 수준 도구를 숨깁니다. 대신 화면 맨 위에 `← 이름`과 그 화면의 도구를 두고, 화면 바닥에 제출·주요 동작 줄을 둔 전체 화면으로 엽니다([머리 줄과 툴바](/app-shell/header-and-toolbar/) 참고).
- `[고래밥]` 이 규칙은 [Apple HIG(Tab bars)](https://developer.apple.com/design/human-interface-guidelines/tab-bars)의 "탭 바를 숨기거나 비활성화하지 말라(모달이 덮을 때만 예외)"는 지침과 반대되며, 상세 화면에서 탭을 숨기라는 외부 근거 자료도 확인되지 않았습니다. 그럼에도 휴대폰 웹은 브라우저 주소창과 가상 키보드 때문에 세로 공간이 더 부족하고 화면 바닥에 제출 동작이 와야 하므로 하단 탭을 숨깁니다.
- `[관례]` 휴대폰에서 새 항목 만들기 버튼은 하단 탭 위에 떠 있는 버튼(FAB, `56px` 정사각·아이콘 `24px`)으로 둡니다([선호 화면](/app-shell/preferred-screens/) 참고). 목록 맨 끝에는 떠 있는 버튼과 하단 탭에 마지막 행이 가려지지 않도록 그 높이와 간격만큼 여백을 둡니다. 상세 화면과 작성 화면에는 떠 있는 만들기 버튼을 두지 않습니다.

## 팝오버를 바텀시트로 바꾸고 조작 범위를 제한한다

데스크톱에서 버튼 곁에 팝오버로 열던 값 고르기(상태, 담당자, 날짜), 필터, 표시 옵션, 행 메뉴는 휴대폰에서 언제나 바텀시트로 엽니다. 바텀시트는 [NN/g(Bottom sheets)](https://www.nngroup.com/articles/bottom-sheet/) 기준과 조합 부품 규칙에 따라 아래 기준을 지킵니다.

1. `[관례]` 끌어 내리기(스와이프) 제스처에만 의존하지 않고 시트 안에 눈에 보이는 닫기 버튼을 함께 둡니다. 시트 안 내용은 값을 고른 뒤 스스로 닫을 수 있도록 닫기 동작을 전달받습니다.
2. `[관례]` 짧은 선택이나 조작만 담습니다. 입력이 길어지거나 단계가 나뉘면 시트가 아니라 주소를 가진 전체 화면 페이지로 엽니다([Primer: Dialog guidelines](https://primer.style/product/components/dialog/guidelines/)).
3. `[관례]` 바텀시트 위에 다른 바텀시트를 겹쳐 쌓지 않습니다.
4. `[관례]` 바텀시트 안에서 다른 페이지나 화면 단계로 이동하지 않습니다.
5. `[고래밥]` 시트 높이는 내용 길이에 맞춥니다. 선택지가 짧으면 내용만큼만 올라오게 열어 화면 대부분을 가리지 않게 하고, 검색이 있거나 목록이 길면 가상 키보드를 고려해 높게 엽니다. 시트 맨 위 손잡이 영역(`24px`) 아래에서 본문을 시작하고 좌우 `12px`, 아래 `20px` 여백을 공통으로 두어 시트마다 여백을 다시 만들지 않습니다.

## 뒤로가기와 방문 기록을 주소 유무로 나누어 처리한다

휴대폰에서는 브라우저나 운영체제의 뒤로가기 제스처를 자주 씁니다. 열린 화면이나 시트에 고유 주소가 있는지에 따라 뒤로가기 처리 방식을 나눕니다.

### 의미 있는 상태는 주소에 두고 방문 기록으로 돌아간다

1. `[고래밥]` 사용자가 공유하거나 새로고침해도 유지되어야 하는 모든 의미 있는 상태는 주소(경로 또는 쿼리)를 갖습니다. 페이지, [라우트 마스킹](/app-shell/route-masking/) 대상, 탭·뷰, [필터와 표시](/app-shell/filters-and-display/), [미리보기 패널](/app-shell/peek/)(`?peek=`)이 여기에 해당합니다.
2. `[고래밥]` 휴대폰 폭에서는 라우트 마스킹 대화상자와 미리보기 패널을 그리지 않습니다. 마스킹 대상은 처음부터 자기 페이지로 이동하고, `?peek=대상ID` 주소로 진입하거나 화면이 줄어들면 방문 기록을 쌓지 않고(`replace`) 대상 페이지 주소로 바꿉니다.
3. `[관례]` 목록에서 상세 페이지로 들어갔다가 뒤로가기로 돌아오면 이전 목록의 스크롤 위치와 이미 불러온 행을 그대로 복원합니다([TanStack Router: Scroll restoration](https://tanstack.com/router/latest/docs/framework/react/guide/scroll-restoration)).

### 주소가 없는 바텀시트는 Esc와 바깥 누름으로 닫는다

- `[고래밥]` 주소가 없는 바텀시트(값 고르기, 필터, 표시, 행 메뉴, 더보기)는 키트의 시트(Drawer, Base UI)로 열며, 키보드 `Esc`와 바깥 누름으로 닫힙니다. 주소와 방문 기록을 건드리지 않고 열린 시트만 닫습니다. 바텀시트는 중첩해 쌓지 않습니다.
- `[고래밥]` 안드로이드 뒤로가기는 주소가 있는 화면(페이지, 마스킹 대화상자)이 맡습니다. 주소가 없는 시트가 안드로이드 하드웨어 뒤로가기로 닫히는지는 확인하지 못했습니다([구현 메모: shadcn](/app-shell/implementation-notes/) 참고).
- `[고래밥, 2026-11-07 결정]` 시트의 열림 상태를 URL 쿼리에 넣는 방식은 쓰지 않습니다. 짧은 조작마다 방문 기록이 쌓이고, 페이지를 새로고침했을 때 시트가 다시 열리는 부작용이 있기 때문입니다.
- `[고래밥, 2026-11-07 결정]` 뒤로가기를 실행하면 시트가 닫히는 대신 이전 페이지로 이동할 수 있습니다. 이 대가를 받아들이고, 대신 아래 두 가지 조건을 함께 지킵니다.
  1. 시트마다 눈에 보이는 닫기 버튼을 둡니다.
  2. 시트에는 잃으면 아까운 긴 입력을 담지 않습니다.

## 입력 글자 크기, 터치 영역, 안전 영역을 지킨다

- `[관례]` 휴대폰 입력 칸의 글자 크기는 `16px` 이상으로 지정합니다(iOS 브라우저의 자동 확대 방지).
- `[관례]` 터치 대상은 `44px` 이상으로 잡습니다.
- `[고래밥]` 시트 안의 동작·선택·시간 목록은 휴대폰에서 `48px` 행·`15px` 글자·`20px` 아이콘으로 두고, 둥근 도구·뷰 알약은 데스크톱 `28px`에서 휴대폰 `44px`(`2.75rem`)로 키웁니다. 작성·상세 화면의 속성 알약은 보이는 높이를 데스크톱 `24px`, 휴대폰 `44px`로 맞춥니다. 완료·취소·저장·다음 같은 텍스트 실행 버튼은 모바일에서 최소 `88px` 너비를 확보합니다. 아이콘 전용 버튼과 툴바 알약에는 이 너비를 적용하지 않습니다.
- `[관례]` `viewport-fit=cover` 환경에서 페이지 위·좌우와 하단 탭·바닥 고정 줄이 기기 안전 영역(노치, 홈 표시줄)을 피하도록 여백을 둡니다. 입력 칸에 초점이 갈 때 바닥 고정 동작 줄이 가상 키보드에 가려지지 않는지 실제 기기에서 확인합니다.

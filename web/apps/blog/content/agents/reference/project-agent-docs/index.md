## 기본 원칙

- **공통 구현 기준**은 `fullstack` 플러그인(`goraebap-mode`, `frontend-engineering`, `frontend-uiux`, `backend-engineering`)이 소유합니다.
- **저장소 고유 지침**은 각 프로젝트의 `AGENTS.md`(얇은 라우터)와 `docs/`가 소유합니다.
- 충돌 시 우선순위는 **프로젝트 규칙(`AGENTS.md` · `docs/`) > `fullstack` 플러그인 기준 > 일반 관례**입니다.

## `AGENTS.md` 구성 규칙

`AGENTS.md`는 모든 세션의 기본 컨텍스트에 올라가므로 얇게 유지합니다.

| 구획 | 담는 내용 | 담지 않는 내용 |
| --- | --- | --- |
| 개요 · 경로 표 | 프로젝트 한 줄 설명과 핵심 폴더 역할 | 긴 배경 설명, 히스토리 |
| 필수 읽기 라우팅 표 | 작업 경로·유형별 `docs/guides/*.md` 매핑 | 가이드 본문 전문 |
| 실행 · 배포 원칙 | 로컬 실행 명령, 커밋·푸시·배포 승인 범위 | 장황한 배포 트러블슈팅 |
| 구현 기준 · 프로젝트 규칙 | 사용 스택 목록과 공통 지침 예외 사유 | 공통 지침 내용 복사 |

### 필수 읽기 라우팅 표 작성 규칙

단순 참고 목록으로 두면 에이전트가 작업 중 건너뛸 수 있으므로, **경로 또는 작업 조건 + 필수 읽기 지시** 형태로 작성합니다.

```markdown
## 프로젝트 가이드 (작업 전 필수 읽기)

아래 경로·작업을 수정하기 전에 해당하는 가이드를 반드시 먼저 읽습니다.

| 대상 경로 · 작업 | 먼저 읽을 문서 |
| --- | --- |
| `web/apps/blog/` 화면·메뉴·빌드·배포 | `docs/guides/blog.md` |
| `docs/` 또는 콘텐츠 문서 작성 | `docs/guides/diataxis.md` |
```

## `docs/` vs 프로젝트 로컬 스킬 선택 기준

| 상황 | 권장 위치 | 이유 |
| --- | --- | --- |
| 저장소 고유의 빌드·배포·문서·도메인 규칙 | `AGENTS.md` + `docs/guides/` | 에이전트별 사본 동기화가 필요 없고 사람도 일반 문서로 읽기 쉬움 |
| 아키텍처 결정 기록과 용어 정의 | `docs/adr/`, `GLOSSARY.md` | 변경 이력과 PR 리뷰에 적합 |
| 사용자가 슬래시 명령(`/명령`)으로 직접 트리거해야 하는 프로젝트 전용 자동화 | 프로젝트 로컬 스킬 (예외적 사용) | 명시적 슬래시 진입점이 반드시 필요한 경우에만 도입 |

## 에이전트 진입 파일

- 루트 `AGENTS.md`를 단일 원본으로 둡니다.
- Claude Code 호환을 위해 루트 `CLAUDE.md`에는 `@AGENTS.md` 한 줄만 둡니다.
- 프로젝트 가이드만 `docs/`로 관리하는 저장소에서는 `.claude/skills/` 동기화 스크립트나 SessionStart 복사 훅을 두지 않습니다.

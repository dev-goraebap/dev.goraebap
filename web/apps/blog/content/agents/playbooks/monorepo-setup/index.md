프론트엔드 단독 저장소나 백엔드 단독 저장소는 각 도메인 스킬의 `프로젝트 구성` 플레이북을 바로 실행합니다. 한 제품을 만들기 위해 프론트엔드와 백엔드를 단일 저장소(모노레포)에 함께 둘 때 이 플레이북을 따릅니다.

- 기준 구조: [모노레포 디렉토리 구조](../../reference/monorepo-structure/index.md)

## 1. 저장소 루트와 공통 골격 초기화

1. [모노레포 디렉토리 구조](../../reference/monorepo-structure/index.md)에 맞춰 루트 폴더(`web/`, `server/`, `deploy/`, `docs/`)를 준비합니다.
2. `.gitignore`에 빌드 산출물, 의존성 폴더, 로컬 환경변수(`.env`), 로컬 데이터 디렉토리를 등록합니다.
3. 루트에 환경변수 키와 설명을 담은 `.env.example`을 두고, 실제 비밀값은 버전 관리에 포함하지 않습니다.

## 2. 백엔드 세팅 위임 (`server/`)

`server/` 아래 백엔드 서버 구성은 `backend-engineering` 스킬의 [백엔드 프로젝트 구성](../../../backend/playbooks/project-setup/index.md) 플레이북을 따라 진행합니다.

- 모노레포에서는 백엔드 소스를 저장소 루트가 아닌 `server/` 아래에 배치합니다.
- 로컬 개발 서버 포트를 고정하고 프론트엔드 개발 프록시와 맞춥니다.

## 3. 프론트엔드 세팅 위임 (`web/`)

`web/` 아래 프론트엔드 워크스페이스 구성은 `frontend-engineering` 스킬의 [프론트엔드 프로젝트 구성](../../../frontend/playbooks/project-setup/index.md) 플레이북을 따라 진행합니다.

- 모노레포에서는 프론트엔드 앱·공용 패키지를 `web/` 아래에 배치합니다.
- 개발 서버의 API 프록시를 `server/`의 로컬 포트로 연결합니다.
- 디자인 시스템을 출발점으로 채택한다면 `frontend-uiux` 스킬의 [디자인 시스템 받기와 갱신](../../../design-system/packages.mdx) 플레이북을 이어서 실행합니다.

## 4. 통합 실행 스크립트와 CI 연결

1. 루트에 개발 서버를 한 번에 띄우는 실행 스크립트(예: `dev.sh`)를 두어 백엔드와 프론트엔드를 함께 기동할 수 있게 합니다.
2. CI 워크플로는 `server/` 검증(포맷·린트·정적 분석·테스트)과 `web/` 검증(린트·타입 검사·빌드)을 병렬 job으로 실행하게 구성합니다.

## 5. 프로젝트 에이전트 문서 구성

[프로젝트 에이전트 문서 구성](../project-agent-docs/index.md) 플레이북에 따라 루트 `AGENTS.md`, `CLAUDE.md`, `docs/`를 세팅하고 이 저장소의 스택과 예외 규칙을 기록합니다.

## 6. 동작 확인

- [ ] `server/`의 린트·테스트·빌드가 오류 없이 통과하는가?
- [ ] `web/`의 린트·타입 검사·빌드가 오류 없이 통과하는가?
- [ ] 통합 실행 스크립트로 백엔드와 프론트엔드를 함께 띄웠을 때 API 프록시와 헬스체크가 정상 응답하는가?
- [ ] 루트 `AGENTS.md`에 실제 폴더 구조, 실행 명령, 스택이 정확히 반영되어 있는가?

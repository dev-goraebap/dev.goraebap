프로젝트마다 공통 지침(`fullstack` 플러그인) 외에 그 저장소에만 해당하는 빌드·배포·도메인·문서 규칙이 필요합니다. 별도 프로젝트 스킬을 복제·동기화하는 대신 `AGENTS.md`와 `docs/`로 관리하는 표준 절차입니다.

- 상세 규약: [프로젝트 AGENTS.md와 docs 규약](../../reference/project-agent-docs/index.md)

## 1. 프로젝트 전용 가이드 분리 (`docs/guides/`)

저장소 고유의 반복 작업(예: 배포 절차, 도메인 문서 작성 규칙, 특수 빌드·검사 방법)을 `docs/guides/<주제>.md` 파일로 작성합니다.

1. 파일 하나에 한 가지 작업 영역만 담습니다.
2. 사람과 에이전트가 함께 읽는 문서이므로 숨김 폴더가 아닌 일반 `docs/` 아래에 둡니다.
3. 되돌리기 어려운 아키텍처 결정은 `docs/adr/`에, 프로젝트 도메인 용어는 루트 `GLOSSARY.md`에 둡니다.

## 2. 루트 `AGENTS.md`를 얇은 라우터로 작성

루트 `AGENTS.md`에는 모든 규칙 본문을 길게 쓰지 않고, 에이전트가 매 턴 부담 없이 읽을 수 있는 최소 맥락과 라우팅 표만 둡니다.

1. 프로젝트 한 줄 소개와 핵심 폴더 역할 표
2. **작업 전 필수 읽기 표**: 어느 경로·작업을 다룰 때 어떤 `docs/guides/*.md` 문서를 반드시 먼저 읽어야 하는지 명시
3. 로컬 실행·검증 명령과 커밋·푸시·배포 원칙
4. 사용 스택 목록과 공통 지침 예외를 적는 프로젝트 규칙 표

## 3. 에이전트별 진입 파일 연결

1. 루트 `CLAUDE.md`에 `@AGENTS.md` 한 줄만 두어 Claude Code가 같은 진입 파일을 읽게 합니다.
2. Codex, Antigravity 등은 루트 `AGENTS.md`를 바로 읽으므로 별도 동기화 스크립트나 사본 폴더를 두지 않습니다.

## 4. 확인

- [ ] `AGENTS.md`가 100줄 안팎의 얇은 라우터로 유지되는가?
- [ ] `AGENTS.md`의 라우팅 표에 적힌 모든 `docs/` 경로가 실제 파일로 존재하는가?
- [ ] `CLAUDE.md`가 `@AGENTS.md`를 가리키는가?
- [ ] 공통 지침과 다르게 정한 예외가 있다면 프로젝트 규칙 표에 이유와 함께 적혀 있는가?

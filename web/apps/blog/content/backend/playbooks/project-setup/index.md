스택별 명령과 설정 코드는 상단의 스택 탭을 따릅니다.

- [표준 라이브러리](../../reference/standard-libraries/index.md)
- [디렉토리·패키지 구조](../../reference/directory-structure/index.md)

## 1. 런타임과 빌드 초기화

1. 언어 런타임 버전을 프로젝트 설정 파일에 명시해 로컬·CI·배포 환경을 일치시킵니다.
2. 프로젝트 이름, 패키지 매니저(또는 빌드 래퍼), 배포 산출물 이름을 고정합니다.

## 2. 표준 라이브러리 등록

[표준 라이브러리](../../reference/standard-libraries/index.md) 기준에 맞춰 웹 API, 인증·인가, 입력 검증, 데이터 접근, 마이그레이션, API 명세, 테스트 의존성을 추가합니다.

- 기능이 아직 필요하지 않은 선택 영역(실시간 통신, 메일, 오브젝트 스토리지 등)은 필요한 시점에 추가합니다.

## 3. 스키마 마이그레이션과 데이터 접근 연결

1. 초기 스키마 마이그레이션 파일을 만들고 버전 순서대로 관리합니다.
2. 스키마 기반 코드 생성을 사용하는 경우 빌드 시 자동 생성되게 연결하고, 생성 산출물은 버전 관리에서 제외합니다.

## 4. 코드 품질 도구 설정

포맷터, 린트·컨벤션 검사, 정적 분석 도구를 빌드에 연결합니다.

- 경고 허용치를 0으로 두어 검사 실패가 바로 드러나게 합니다.
- 자동 생성된 코드는 검사 대상에서 제외합니다.

## 5. 환경 설정과 프로필 분리

1. 공통 기본 설정 파일과 로컬 개발 전용 설정 파일을 분리합니다.
2. 배포 환경마다 달라지는 값(포트, DB 접속 정보, CORS 허용 출처, 외부 키 등)은 환경변수로 바인딩합니다.
3. 필요한 환경변수 키와 설명을 담은 `.env.example`을 저장소에 두고, 실제 `.env`와 로컬 데이터 디렉토리는 `.gitignore`에 추가합니다.

## 6. 기본 구조와 경계 테스트 구성

1. [디렉토리·패키지 구조](../../reference/directory-structure/index.md)에 맞춰 `shared/`(공통 예외 처리, 공통 응답 형식, 헬스체크)와 첫 컨텍스트 뼈대를 만듭니다.
2. 컨텍스트·계층 간 의존성 경계를 자동으로 검사하는 테스트 또는 린트 규칙을 추가합니다.
3. 빠른 단위 테스트와 외부 연동·DB를 쓰는 통합 테스트를 분리해 실행할 수 있게 구성합니다.

## 7. 동작 확인

1. 포맷·린트·정적 분석·단위 테스트·통합 테스트를 모두 실행해 통과하는지 확인합니다.
2. 로컬 개발 프로필로 서버를 띄워 헬스체크 엔드포인트와 OpenAPI 명세 응답을 확인합니다.

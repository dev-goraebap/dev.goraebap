영역별 실제 채택 라이브러리는 상단의 스택 탭을 따릅니다.

## 표준 지정 영역

| 구분 | 영역 | 역할 |
| --- | --- | --- |
| 기반 | 런타임·빌드 | 언어 버전 고정, 웹 프레임워크, 빌드·의존성 관리 |
| 핵심 | 웹 API | HTTP 라우팅, 요청·응답 직렬화 |
| 핵심 | 인증·인가 | 요청 인증, 세션·토큰 검증, 권한 제어 |
| 핵심 | 입력 검증 | 진입 계층 요청 스키마·필드 유효성 검사 |
| 핵심 | 데이터 접근 | DB 쿼리 실행, 타입 안전한 결과 매핑 |
| 핵심 | 스키마 마이그레이션 | 버전 기반 DDL 변경 이력 관리 |
| 핵심 | API 명세 | 코드 기반 OpenAPI 스펙 자동 생성 |
| 선택 | 실시간 통신 | WebSocket 또는 SSE 연동 (필요 시) |
| 선택 | 메일 발송 | SMTP 등 외부 메일 발송 (필요 시) |
| 선택 | 오브젝트 스토리지 | 파일 업로드·사전 서명 URL 발급 (필요 시) |
| 품질 | 코드 품질 | 포맷터, 컨벤션 린트, 정적 결함 분석 |
| 품질 | 테스트 | 단위 테스트, HTTP·보안 슬라이스 테스트, 통합 테스트 |

## 공통 원칙

- 같은 역할을 하는 라이브러리를 한 프로젝트 안에서 중복 도입하지 않습니다.
- 선택 영역 라이브러리는 실제 요구사항이 생겼을 때 추가합니다.
- 스키마나 API 명세에서 자동 생성된 코드는 포맷·린트·정적 분석 대상에서 제외합니다.
- DB·파일 시스템·외부 네트워크를 사용하는 통합 테스트는 빠른 단위 테스트와 분리해 실행합니다.

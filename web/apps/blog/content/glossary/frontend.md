## 구조와 계층

### 레이어 (Layer)

- **id**: `layer`
- **정의**: 프론트엔드 소스 루트 바로 아래를 의존성 방향과 책임 범위로 나눈 최상위 계층(`app`, `pages`, `widgets`, `features`, `entities`, `shared`)입니다. 상위 레이어는 하위 레이어만 참조할 수 있습니다.
- **구분**: 모든 레이어를 처음부터 필수로 두지 않고, `app`·`pages`·`shared`를 기본으로 하되 `widgets`·`features`·`entities`는 실제 재사용 필요가 생길 때 추가합니다. `processes` 레이어는 공식 FSD v2.1에서 폐기되었습니다.

### 슬라이스 (Slice)

- **id**: `slice`
- **정의**: 레이어 내부를 도메인·기능 또는 URL 경로 단위로 격리한 폴더 묶음입니다. 같은 레이어에 속한 다른 슬라이스는 참조할 수 없습니다.
- **구분**: 전역 설정을 맡는 `app`과 업무 지식이 없는 `shared`는 슬라이스 없이 세그먼트를 바로 둡니다.

### 세그먼트 (Segment)

- **id**: `segment`
- **정의**: 슬라이스 내부를 코드의 기술적 역할(`ui`, `model`, `api`, `lib`, `config`)에 따라 나눈 하위 폴더입니다.
- **구분**: `components`, `hooks`, `types`처럼 문법적 종류만 드러내는 이름보다, 화면(`ui`), 상태·도메인 로직(`model`), 서버 통신(`api`)처럼 목적을 드러내는 이름을 씁니다.

### 공개 API (Public API)

- **id**: `public-api`
- **정의**: 슬라이스가 외부에 노출할 심볼만 명시적으로 선택해 다시 내보내는 진입 파일(`index.ts`)입니다. 외부에서는 슬라이스 내부 파일 경로를 직접 참조하지 않고 공개 API만 import합니다.
- **구분**: `export *` 와일드카드 재내보내기나 `shared/` 전체를 묶는 거대 배럴 파일은 캡슐화와 트리셰이킹을 해치므로 피합니다.

### 크로스 임포트 (Cross-Import / `@x`)

- **id**: `cross-import`
- **정의**: 같은 레이어의 다른 슬라이스를 불가피하게 참조해야 할 때, FSD v2.1에서 예외를 명시적으로 드러내기 위해 도입한 전용 공개 API 표기(`entities/A/@x/B`)입니다.
- **구분**: 기본 원칙은 동층 슬라이스 간 참조 금지이며, `@x`는 도메인 엔티티 간 관계처럼 구조적으로 피하기 어려운 경우에만 제한적으로 씁니다.

### 라우트 슬라이스 (Route Slice)

- **id**: `route-slice`
- **정의**: `pages` 레이어에서 애플리케이션 URL 경로 하나와 1:1로 대응하는 폴더 단위입니다. 폴더 트리만 보고 앱의 주소 구조를 파악할 수 있습니다.
- **구분**: 같은 층의 형제 라우트 슬라이스끼리는 참조하지 않으며, 자기 폴더와 조상 라우트 폴더의 코드만 참조합니다.
- **스택 매핑**:
  - React · TanStack: `src/pages/` 아래 `page.tsx`(화면)와 `route.tsx`(레이아웃·가드·로더)를 두는 파일 기반 라우트 폴더
  - Angular: `src/pages/` 아래 `routes.ts`(라우트 정의)와 `ui/`(화면 컴포넌트)를 두고 부모 `routes.ts`가 `loadChildren`으로 연결하는 폴더

### 경로 없는 레이아웃 (Pathless Layout)

- **id**: `pathless-layout`
- **정의**: URL에 새 경로 조각을 추가하지 않으면서, 하위 주소들에 공통 레이아웃·인증 가드·초기 데이터 준비를 묶어 적용하는 부모 라우트 경계입니다.
- **스택 매핑**:
  - React · TanStack: `_app/route.tsx`처럼 밑줄(`_`)로 시작하는 폴더의 `route.tsx`
  - Angular: `path: ""`에 `canActivate`와 셸 `component`를 걸고 `children`으로 하위 라우트를 잇는 `routes.ts`

### 코로케이션 (Colocation)

- **id**: `colocation`
- **정의**: 함께 변경되는 화면·상태·API 코드를 멀리 흩어 놓지 않고 사용하는 자리 가까이에 모아 두는 배치 원칙입니다.
- **구분**: 한 화면에서만 쓰는 조각은 처음부터 `features`나 `entities`로 빼지 않고 해당 `pages` 라우트 슬라이스 안에 먼저 둡니다.

### 앱 셸 경계 (App Shell Boundary)

- **id**: `app-shell-boundary`
- **정의**: 내비게이션 메뉴, 권한 분기, 공간 전환처럼 제품의 업무 문맥을 알고 화면 외곽을 감싸는 틀의 레이어 경계입니다.
- **구분**: 업무 지식이 없는 순수 레이아웃 뼈대는 `shared` UI 키트에 두고, 업무 문맥을 아는 앱 셸은 `app` 또는 상위 라우트 슬라이스에 둡니다.
- **자동 연결**: 앱 셸

### 아토믹 디자인 (Atomic Design)

- **id**: `atomic-design`
- **정의**: 브래드 프로스트(Brad Frost)가 제안한 UI 설계 방법론으로, 인터페이스를 `Atoms → Molecules → Organisms → Templates → Pages` 다섯 단계의 시각적 조합 단위로 나눕니다.
- **구분**: 디자인 시스템이나 순수 UI 컴포넌트 조합에는 유용하지만, 앱 전반의 상태·API·도메인 간 의존성 규칙은 다루지 않습니다.

## 구성 요소와 실행 흐름

### 라우트 경계 (Route Boundary)

- **id**: `route-boundary`
- **정의**: URL 진입 시 주소 매칭, 검색 파라미터 검증, 인증·권한 가드, 진입 전 데이터 프리로드를 맡는 실행 진입점입니다.
- **구분**: 화면 마크업이나 폼 상태는 `ui/` 컴포넌트에 위임하고 라우트 진입 파일은 얇게 유지합니다.
- **스택 매핑**:
  - React · TanStack: `route.tsx` · `page.tsx`의 `createFileRoute` (`validateSearch`, `beforeLoad`, `loader`)
  - Angular: `routes.ts`의 `Routes` 정의, 함수형 `canActivate` · `resolve`, `withComponentInputBinding()`

### 서버 상태 (Server State)

- **id**: `server-state`
- **정의**: 백엔드 API가 원본(Source of Truth)을 소유하고, 프론트엔드가 캐시 형태로 읽어 쓰는 비동기 데이터입니다.
- **구분**: 로컬 UI 상태와 달리 컴포넌트에 복사해 두지 않고 캐시 계층이 소유하며, 변경(Mutation) 뒤 관련 키를 무효화해 갱신합니다.

### 로컬 UI 상태 (Local UI State)

- **id**: `local-ui-state`
- **정의**: 모달·드로어 열림, 탭 선택, 저장 전 입력 초안처럼 특정 화면이나 컴포넌트 수명 안에서만 의미가 있는 클라이언트 전용 상태입니다.
- **구분**: URL로 공유해야 하는 검색·필터 조건(URL 상태)이나 백엔드 원본 데이터(서버 상태)와는 소유를 분리합니다.

### 조회 옵션 (Query Options)

- **id**: `query-options`
- **정의**: 서버 데이터를 식별하는 캐시 키(`key`), 요청 함수(`fetch`), 신선도 유지 시간(`staleTime`)을 하나로 묶은 정의 객체입니다.
- **구분**: 라우트 가드·로더와 화면 컴포넌트가 같은 조회 옵션을 공유해 중복 요청과 캐시 키 불일치를 막습니다.
- **스택 매핑**:
  - React · TanStack: TanStack Query의 `queryOptions()`
  - Angular: `queryOptions()` + `ServerState`

### 통신 기반 (Transport Layer)

- **id**: `transport-layer`
- **정의**: `fetch`나 `HttpClient`를 감싸 인증 자격 증명, 공통 헤더, HTTP 상태 코드별 `ApiError` 변환을 일원화하는 최하단 통신 어댑터(`shared/api`)입니다.
- **구분**: 업무 규칙이나 토스트·리다이렉트 같은 UI 흐름 제어는 포함하지 않습니다.

## 상태 관리와 데이터 흐름

### URL 상태 (URL State)

- **id**: `url-state`
- **정의**: 경로 파라미터, 확정된 검색어·필터, 정렬, 페이지 번호, 선택 탭처럼 라우터가 검증하고 브라우저 주소가 원본을 소유하는 상태입니다.
- **구분**: 적용 버튼을 누르기 전의 임시 필터 선택(로컬 UI 상태)과 구분하며, 새로고침·뒤로가기·링크 공유에서도 동일하게 복원됩니다.

### 입력 초안 (Input Draft)

- **id**: `input-draft`
- **정의**: 사용자가 편집 중이지만 아직 서버에 확정 저장하지 않은 로컬 임시 입력값입니다.
- **구분**: 서버 상태 캐시와 분리해 백그라운드 재조회가 입력 중인 내용을 덮어쓰지 않게 보호합니다. 저장 중 편집을 허용할 때는 요청 판본과 현재 판본을 비교합니다.

### 캐시 무효화 (Cache Invalidation)

- **id**: `cache-invalidation`
- **정의**: 생성·수정·삭제(Mutation) 요청이 성공한 뒤 영향받는 서버 상태 캐시 키를 오래된 상태로 표시해 최신 데이터를 다시 불러오게 하는 갱신 절차입니다.
- **구분**: 저장 요청 자체의 성공과 뒤따른 재조회 실패는 분리해 처리합니다.

### 스테일-와일-리밸리데이트 (Stale-While-Revalidate / SWR)

- **id**: `stale-while-revalidate`
- **정의**: 캐시에 저장된 데이터가 신선도 기준을 지났더라도 먼저 즉시 화면에 표시하고, 뒤에서 서버에 재조회해 조용히 최신 상태로 갱신하는 전략입니다.
- **구분**: 읽고 있는 본문처럼 갑자기 교체되면 혼란을 주는 영역은 즉시 덮어쓰지 않고 갱신 안내를 띄웁니다.

### 디바운스 (Debounce)

- **id**: `debounce`
- **정의**: 검색어 입력처럼 짧은 간격으로 반복 발생하는 이벤트를 묶어, 입력이 일정 시간(`200~300ms`) 멈춘 뒤 한 번만 실행하는 제어 기법입니다.
- **구분**: 요청 횟수는 줄여 주지만 네트워크 응답 순서는 보장하지 않으므로 요청 취소와 함께 씁니다.

### 요청 취소 (Request Cancellation)

- **id**: `request-cancellation`
- **정의**: 새 검색이나 화면 이탈, 계정 전환으로 더 이상 필요 없어진 진행 중 HTTP 요청을 중단(`AbortController` 등)해 늦게 도착한 이전 응답이 최신 상태를 덮어쓰지 못하게 막는 처리입니다.

## 라우팅과 렌더링

### 인텐트 프리패치 (Intent Prefetch)

- **id**: `intent-prefetch`
- **정의**: 사용자가 앱 내부 링크에 포인터를 올리거나 키보드 초점을 맞출 때 클릭 전에 다음 화면의 코드와 데이터를 미리 준비하는 기법입니다.
- **구분**: 링크마다 개별 등록하지 않고 문서 수준에서 위임 감지하며, 같은 주소는 일정 시간(10초) 동안 중복 호출하지 않습니다.

### 라우팅 마스크 (Route Masking)

- **id**: `route-masking`
- **정의**: 데스크톱에서 목록 맥락을 유지한 채 대화상자로 상세·작성 화면을 열면서, 브라우저 주소창에는 대상의 실제 URL을 표시하는 라우팅 계약입니다.
- **구분**: 직접 진입·새로고침·휴대폰 환경에서는 마스크를 풀고 대상의 독립 페이지 전체로 엽니다.

### 뷰 트랜지션 (View Transition)

- **id**: `view-transition`
- **정의**: 같은 문서 안의 화면 전환에서 이전 화면과 준비된 새 화면의 스냅샷을 부드럽게 교차 전환하는 브라우저 API(`View Transitions API`)입니다.
- **스택 매핑**:
  - React · TanStack: TanStack Router `defaultViewTransition: true`
  - Angular: `provideRouter(routes, withViewTransitions())`

### 지연 로딩 (Lazy Loading)

- **id**: `lazy-loading`
- **정의**: 초기 번들 크기를 줄이기 위해 라우트 단위 화면 코드나 대형 컴포넌트(리치 에디터·차트 등)를 필요한 시점에 동적으로 내려받는 분할 기법입니다.
- **구분**: 레이아웃이 밀리거나 전환 중 깜빡이지 않도록 라우트 준비 단계에서 데이터와 함께 미리 불러둡니다.

### 스플래시 화면 (Splash Screen)

- **id**: `splash-screen`
- **정의**: 로그인 뒤 업무 앱의 최초 진입과 새로고침 때 세션·권한 등 필수 초기 데이터가 준비될 때까지 표시하는 가벼운 초기 오버레이입니다.
- **구분**: 첫 진입에만 사용하며, 이후 앱 내부 화면 전환에는 쓰지 않고 지연 진행 막대를 사용합니다.

## 코드 스타일과 반응성

### 파생 상태 (Derived State)

- **id**: `derived-state`
- **정의**: 기존 입력(props/`input`), 서버 상태, 로컬 상태로부터 순수하게 계산해 낼 수 있는 값입니다.
- **구분**: 별도 상태 변수에 복제해 부수 효과로 동기화하지 않고 렌더링 중 직접 계산하거나 반응형 파생 식(`computed`)으로 유지합니다.

### 부수 효과 (Side Effect)

- **id**: `side-effect`
- **정의**: DOM 이벤트 리스너, 타이머, `localStorage`, 외부 라이브러리처럼 컴포넌트 렌더링 그래프 바깥의 시스템과 동기화하는 동작입니다.
- **구분**: 등록한 자원·구독은 반드시 정리 함수(`cleanup`, `onCleanup`, `DestroyRef`)로 해제하며, 파생값 계산이나 사용자 명령 실행에 쓰지 않습니다.

### 메모이제이션 (Memoization)

- **id**: `memoization`
- **정의**: 입력이 바뀌지 않았을 때 이전 계산 결과나 함수 참조를 재사용하는 최적화 기법입니다.
- **구분**: 모든 값에 습관적으로 붙이지 않고, 측정된 계산 비용이 크거나 참조 안정성이 필요한 경계에만 적용합니다.

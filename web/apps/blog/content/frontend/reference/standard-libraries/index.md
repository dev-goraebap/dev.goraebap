영역별 실제 채택 라이브러리는 스택 전환(`React · TanStack` · `Angular`)을 따릅니다.

## 표준 지정 영역

| 구분 | 영역 | 역할 |
| --- | --- | --- |
| 기반 | 패키지·빌드 | 패키지 매니저, TypeScript 컴파일러, 개발 서버·번들러 |
| 핵심 | 라우팅 | 주소 매핑, 코드 분할, 라우트 가드·데이터 준비 |
| 핵심 | 서버 상태 · HTTP | API 요청, 캐싱, 재조회·무효화, 로딩·오류 상태 관리 |
| 핵심 | 스타일 · 디자인 시스템 | 유틸리티 CSS, 디자인 토큰·스타일 레시피, 헤드리스 UI 프리미티브 |
| 선택 | 폼 · 스키마 검증 | 복잡한 입력 상태와 클라이언트 검증 (필요 시) |
| 선택 | 아이콘 | 제품 전반의 일관된 아이콘 어댑터 |
| 품질 | 코드 품질 | 포맷터, 정적 린트, 미사용 코드·의존성 검사, 타입 검사 |

## 공통 원칙

- 같은 역할을 하는 라이브러리(예: 라우터 2종, CSS 프레임워크 2종)를 한 앱 안에 중복 도입하지 않습니다.
- 시각 토큰과 스타일 레시피는 프레임워크에 무관한 디자인 시스템 패키지를 단일 원본으로 쓰고, 상호작용 프리미티브만 프레임워크 어댑터에 맡깁니다.
- 선택 영역 도구는 실제 복잡도가 생겼을 때 추가합니다.
- 라우트 트리처럼 빌드 플러그인이 자동 생성하는 파일은 포맷·린트 검사 대상에서 제외합니다.

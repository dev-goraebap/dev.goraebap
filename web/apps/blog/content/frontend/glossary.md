# 프론트엔드 용어집

프론트엔드 플레이북·아티클·레퍼런스 전반에서 같은 개념을 같은 이름으로 부르기 위해 정리한 용어입니다.

## 구조와 계층

### 레이어 (Layer)

- **id**: `layer`
- **정의**: 프론트엔드 소스 루트 바로 아래를 의존성 방향과 책임 범위로 나눈 최상위 계층(`app`, `pages`, `widgets`, `features`, `entities`, `shared`)입니다. 상위 레이어는 하위 레이어만 참조할 수 있습니다.
- **구분**: 모든 레이어를 처음부터 필수로 두지 않고, `app`·`pages`·`shared`를 기본으로 하되 `widgets`·`features`·`entities`는 실제 재사용 필요가 생길 때 추가합니다. `processes` 레이어는 공식 FSD v2.1에서 폐기되었습니다.

### 슬라이스 (Slice)

- **id**: `slice`
- **정의**: 레이어 내부를 도메인·기능 또는 URL 경로 단위로 격리한 폴더 묶음입니다. 같은 레이어에 속한 다른 슬라이스는 참조할 수 없습니다.
- **구분**: 전역 설정을 맡는 `app`과 업무 지식이 없는 `shared`는 슬라이스 없이 세그먼트를 바로 둡니다.

### 세그먼트 (Segment)

- **id**: `segment`
- **정의**: 슬라이스 내부를 코드의 기술적 역할(`ui`, `model`, `api`, `lib`, `config`)에 따라 나눈 하위 폴더입니다.
- **구분**: `components`, `hooks`, `types`처럼 문법적 종류만 드러내는 이름보다, 화면(`ui`), 상태·도메인 로직(`model`), 서버 통신(`api`)처럼 목적을 드러내는 이름을 씁니다.

### 공개 API (Public API)

- **id**: `public-api`
- **정의**: 슬라이스가 외부에 노출할 심볼만 명시적으로 선택해 다시 내보내는 진입 파일(`index.ts`)입니다. 외부에서는 슬라이스 내부 파일 경로를 직접 참조하지 않고 공개 API만 import합니다.
- **구분**: `export *` 와일드카드 재내보내기나 `shared/` 전체를 묶는 거대 배럴 파일은 캡슐화와 트리셰이킹을 해치므로 피합니다.

### 크로스 임포트 (Cross-Import / `@x`)

- **id**: `cross-import`
- **정의**: 같은 레이어의 다른 슬라이스를 불가피하게 참조해야 할 때, FSD v2.1에서 예외를 명시적으로 드러내기 위해 도입한 전용 공개 API 표기(`entities/A/@x/B`)입니다.
- **구분**: 기본 원칙은 동층 슬라이스 간 참조 금지이며, `@x`는 도메인 엔티티 간 관계처럼 구조적으로 피하기 어려운 경우에만 제한적으로 씁니다.

### 라우트 슬라이스 (Route Slice)

- **id**: `route-slice`
- **정의**: `pages` 레이어에서 애플리케이션 URL 경로 하나와 1:1로 대응하는 폴더 단위입니다. 폴더 트리만 보고 앱의 주소 구조를 파악할 수 있습니다.
- **구분**: 같은 층의 형제 라우트 슬라이스끼리는 참조하지 않으며, 자기 폴더와 조상 라우트 폴더의 코드만 참조합니다.
- **스택 매핑**:
  - React · TanStack: `src/pages/` 아래 `page.tsx`(화면)와 `route.tsx`(레이아웃·가드·로더)를 두는 파일 기반 라우트 폴더
  - Angular: `src/pages/` 아래 `routes.ts`(라우트 정의)와 `ui/`(화면 컴포넌트)를 두고 부모 `routes.ts`가 `loadChildren`으로 연결하는 폴더

### 경로 없는 레이아웃 (Pathless Layout)

- **id**: `pathless-layout`
- **정의**: URL에 새 경로 조각을 추가하지 않으면서, 하위 주소들에 공통 레이아웃·인증 가드·초기 데이터 준비를 묶어 적용하는 부모 라우트 경계입니다.
- **스택 매핑**:
  - React · TanStack: `_app/route.tsx`처럼 밑줄(`_`)로 시작하는 폴더의 `route.tsx`
  - Angular: `path: ""`에 `canActivate`와 셸 `component`를 걸고 `children`으로 하위 라우트를 잇는 `routes.ts`

### 코로케이션 (Colocation)

- **id**: `colocation`
- **정의**: 함께 변경되는 화면·상태·API 코드를 멀리 흩어 놓지 않고 사용하는 자리 가까이에 모아 두는 배치 원칙입니다.
- **구분**: 한 화면에서만 쓰는 조각은 처음부터 `features`나 `entities`로 빼지 않고 해당 `pages` 라우트 슬라이스 안에 먼저 둡니다.

### 앱 셸 (App Shell)

- **id**: `app-shell`
- **정의**: 내비게이션 메뉴, 권한 분기, 공간 전환처럼 제품의 업무 문맥을 알고 화면 외곽을 감싸는 틀입니다.
- **구분**: 업무 지식이 없는 순수 레이아웃 뼈대는 `shared` UI 키트에 두고, 업무 문맥을 아는 앱 셸은 `app` 또는 상위 라우트 슬라이스에 둡니다.

### 아토믹 디자인 (Atomic Design)

- **id**: `atomic-design`
- **정의**: 브래드 프로스트(Brad Frost)가 제안한 UI 설계 방법론으로, 인터페이스를 `Atoms → Molecules → Organisms → Templates → Pages` 다섯 단계의 시각적 조합 단위로 나눕니다.
- **구분**: 디자인 시스템이나 순수 UI 컴포넌트 조합에는 유용하지만, 앱 전반의 상태·API·도메인 간 의존성 규칙은 다루지 않습니다.

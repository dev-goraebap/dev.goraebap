프로젝트 디자인·기존 컴포넌트·사용자가 준 참고 화면이 있으면 그것을 우선합니다. 지정이 없을 때는 이 디자인 시스템을 레지스트리에서 받아 출발점으로 씁니다. 레지스트리 목록은 `https://dev.goraebap.xyz/r/registry.json`이며, 항목은 스타일 레시피 전체(`design-system`)와 프레임워크별 어댑터(`ui-<스택 id>`)입니다. 어댑터는 모두 같은 레시피를 써서 프레임워크가 달라도 생김새가 같습니다.

## 받기

1. Git status와 staging, 현재 UI와 디자인 기록을 확인합니다. 프로젝트가 이미 가진 디자인 결정이 있으면 받기 전에 사용자에게 묻습니다.
2. `design-system`과, 프로젝트 AGENTS.md의 goraebap-webapp 블록에 적힌 스택과 같은 이름의 어댑터 하나를 받습니다. 그 스택의 어댑터가 없으면 `design-system`만 받고 레시피를 프로젝트 컴포넌트에 직접 입힙니다.
3. 항목 JSON의 `files`를 고르지 않고 모두 `target` 경로에 그대로 씁니다. 받은 파일은 `src/shared/ui/goraebap/` 아래에 모이고, 그 안의 import는 상대 경로라 경로 별칭을 따로 맞추지 않아도 됩니다. 항목의 `dependencies`는 프로젝트의 패키지 도구로 설치합니다. 레지스트리 형식을 읽는 도구가 있으면 그것으로 받아도 됩니다.
4. 전역 스타일에서 받은 테마 CSS(`design-system/styles/base.css`와 테마 파일 하나)를 불러오고, 스타일 도구가 받은 폴더의 클래스를 찾도록 그 경로를 등록합니다.
5. 받은 폴더마다 있는 `goraebap-ui.json`(원본 저장소와 커밋)은 지우지 않습니다. 갱신할 때 비교 기준입니다.
6. 프로젝트의 테마·모바일 탐색·오버레이를 연결한 뒤 실제 화면에서 확인합니다. 타입 검사만으로 시각적 재현을 보장하지 않습니다.

## 테마 적용

테마 파일은 `theme-app.css`, `theme-editorial.css`, `theme-ocean.css`, `theme-forest.css`, `theme-terracotta.css` 다섯 가지입니다. 불러온 테마는 요소의 `data-ds-theme` 값(`app`·`editorial`·`ocean`·`forest`·`terracotta`)으로 영역마다 고르고, 다크 모드는 `html` 같은 상위 요소에 `dark` 클래스를 붙여 바꿉니다. 테마마다 어디에 쓰는지는 테마 지침을 따릅니다.

```html
<html class="dark" data-ds-theme="app">
  <body>
    <article data-ds-theme="editorial">...</article>
  </body>
</html>
```

## 받은 파일 다루기

- 받은 폴더는 직접 고치지 않습니다. 다시 받으면 같은 파일을 덮어쓰기 때문입니다. 프로젝트마다 다르게 할 것은 테마 변수를 덮어쓰거나, 받은 컴포넌트를 감싸는 컴포넌트를 제품 공용 폴더에 만들어 냅니다.
- 제품이 직접 만든 공용 컴포넌트는 받은 폴더 밖에 둡니다. 그래야 받은 것과 만든 것이 폴더로 구분됩니다.
- 받은 부품이 부족하거나 틀리면 고쳐 쓰지 않고 [지침 제안](../../../../../../plugins/webapp/skills/onboarding/references/proposals.md)으로 원본을 고칩니다. 급한 예외는 감싸는 컴포넌트로 막고 프로젝트 규칙에 이유를 적습니다.
- 라우터·세션·API·메뉴·저장 계약은 프로젝트가 연결합니다. 받은 컴포넌트는 링크 요소를 직접 받아 라우터에 이어지므로 루트에 링크 Provider를 두지 않습니다.

## 갱신

`goraebap-ui.json`의 `commit`과 `registry.json`의 `commit`이 다르면 같은 항목을 다시 받아 덮어씁니다. 덮어쓴 뒤 Git 차이로 바뀐 파일을 확인하고, 감싸는 컴포넌트와 테마 덮어쓰기가 여전히 맞는지 실제 화면에서 봅니다. 공통 변경을 프로젝트에 자동으로 적용하지 않고, 갱신은 사용자가 요청할 때 합니다.

## 원본 고치기

이 절은 원본 저장소(`dev-goraebap/dev.goraebap`)에서 디자인 시스템을 관리할 때만 씁니다. 새 경험을 얻으면 증상 → 바뀐 기준 → 영향받는 패턴 → 확인 결과를 근거로 지침과 디자인 시스템을 함께 고칩니다. 한 프로젝트의 우연한 구현이나 결함을 공통 규칙으로 올리지 않습니다. 레시피나 컴포넌트 계약을 바꾸면 모든 어댑터와 스택 글의 발췌를 같은 변경에서 맞춥니다. 레지스트리는 사이트를 빌드할 때 원본 패키지에서 다시 만들어집니다.

테마는 색·글자·간격·면·경계·모서리와 컴포넌트 변형의 기본값을 한 곳에서 정합니다. 프로젝트가 값을 정하지 않았으면 [레지스트리로 받은](../../../../../../../plugins/webapp/skills/frontend-design-system/references/reference-kit.md) 디자인 시스템의 테마 CSS에서 출발합니다. 토큰은 테마 파일 하나에 라이트와 다크로 정의하고, 스타일 도구가 그 토큰을 유틸리티로 쓰게 노출합니다. 화면은 유틸리티와 의미 토큰으로만 칠하며, 화면별 CSS 파일·CSS 모듈·다른 스타일 도구를 섞지 않습니다.

## 테마를 고르는 기준

업무 앱(로그인 뒤의 업무 화면)은 먹색 강조의 App 테마를 기본으로 씁니다. 디자인 시스템의 나머지 색 테마(Editorial·Ocean·Forest·Terracotta)는 랜딩·문서처럼 브랜드 색조가 필요한 공개 화면의 출발점입니다. 업무 화면 안에서 테마를 바꿔 색조를 입히지 않습니다.

레지스트리로 받은 디자인 시스템은 문서 루트에 붙인 색 테마 속성(`data-ds-theme`)과 다크 표시(`dark` 클래스)로 테마와 모드를 정합니다.

## 기준 색에서 파생한다

라이트·다크 쌍으로 정하는 기준 색은 바닥(body)·페이지 면(surface)·옅은 채움(muted)·글자 둘·보조 아이콘·강조색뿐입니다. 나머지는 `color-mix`로 글자색을 면 위에 섞어 만듭니다. 화면마다 색을 덧칠해 다른 테마를 만들지 않습니다.

강조색은 글자색과 같은 먹색입니다. 앱 크롬에 브랜드 색조를 두지 않고, 색은 업무 데이터의 분류·상태·그림의 강조에만 씁니다. 업무 데이터의 색(사용자가 고른 색, 분류 색)과 UI 테마 색은 따로 관리합니다.

| 역할 | 토큰의 역할 | 기본값(라이트/다크) |
| --- | --- | --- |
| 내부 구분선: 행·표·툴바·카드 테두리 | 내부 구분선 | 글자 9% / 8% |
| 바깥 경계: split 선·inset 페이지 외곽·하단 막대 위·입력 칸·필터 칩 | 바깥 경계 | 글자 18% / 16% |
| 포인터 아래 | 포인터 채움(목록 줄은 줄 전용 포인터 채움) | 글자 4% / 5% |
| 고른 값·켜진 도구 채움 | 고른 채움, 메뉴의 지금 자리는 눌림 채움 | 글자 10% / 13%, 눌림 채움은 7% / 8% |
| 키보드 초점 | 초점 선 | 강조색 72%, 컴포넌트 경계 안쪽 2px |
| 조작 면: secondary·도구·보기 탭·속성 칩·셀렉트·필터 | 조작 면 네 토큰 | 글자 5%·9%·14%·11%([Primitives](../../../../../../../plugins/webapp/skills/frontend-design-system/references/basic-components.md#조작-면)) |

두 경계를 하나로 합치면 inset 페이지 외곽과 안쪽 카드 테두리가 같은 무게가 되어 면 단계가 흐려집니다. 대화상자·팝오버 같은 뜬 면은 두 토큰 대신 가는 테두리(글자 10%)를 씁니다.

## 상태의 표현

| 상태 | 표현 |
| --- | --- |
| hover | 행·메뉴·칩은 포인터 채움(목록 줄은 줄 전용 포인터 채움), 버튼 변형은 한 단계 진한 채움과 진한 글자 |
| 선택·눌림·열림·현재 위치 | 같은 아이콘의 선택 형태와 고른 보기 변형(한 단계 진한 칩, 가는 테두리), `aria-pressed`·`aria-current`·`aria-expanded`를 함께 둡니다 |
| 키보드 초점 | 2px 초점 선. hover 채움으로 대신하지 않습니다. 종이 위에 글을 쓰는 칸(테두리 없는 제목·본문)은 깜빡이는 커서가 초점을 보이므로 초점 선을 더하지 않고, 제출 검사에서 빠진 항목만 붉은 밑줄로 알립니다 |
| 비활성 | 50% 불투명도와 기본 커서(컴포넌트 라이브러리 기본). 흐림 정도를 컴포넌트마다 다르게 정하지 않습니다 |

상태와 선택 여부를 색 하나로만 전달하지 않습니다. 모양(채움 아이콘), 이름, 접근 가능한 상태 속성을 함께 둡니다. 모든 상태를 라이트·다크에서 확인합니다.

눌림은 `aria-pressed`와 버튼의 고른 보기 변형으로 표현합니다. 버튼 변형의 쓰임은 [Primitives](../../../../../../../plugins/webapp/skills/frontend-design-system/references/basic-components.md), 분류·라벨은 라벨 컴포넌트로 그립니다.

## 휴대폰 크기와 라이트·다크

휴대폰 크기는 테마 토큰 파일의 `@media (width < 64rem)` 구획과 컴포넌트의 휴대폰 분기 스타일로 정합니다.

라이트·다크는 문서 루트의 테마 속성 하나가 정하며, 스타일 도구의 다크 변형도 이 속성을 봅니다. 색은 토큰에서만 바꾸고 화면에서 다크 변형으로 색을 덮어쓰지 않습니다. 화면 안에 별도 테마 전환을 두지 않습니다. 아이콘을 고르는 기준은 [아이콘](../icons/index.mdx), 면의 단계는 [면과 경계](../surfaces.mdx)가 소유합니다.

## 모바일 주변 영역과 테마

PWA를 제공하면 앱 안의 면과 상태바·제스처 영역의 색을 함께 확인합니다. 문서의 `theme-color`와 앱이 그리는 세이프 영역 배경을 현재 테마의 실제 면 색에 맞춥니다. manifest의 기본 색만 고정하고 다크 모드에서도 그대로 쓰지 않습니다. 첫 화면 전에 저장한 모드를 적용하고, 시스템 모드를 쓸 때는 기기의 모드 변경도 따라가게 합니다. 색 값의 원본은 테마 한 곳에 두며 특정 제품의 색을 공통 값으로 복사하지 않습니다.

앱이 그리는 세이프 영역은 `env(safe-area-inset-top)`·`env(safe-area-inset-bottom)`으로 공간을 확보합니다. 브라우저나 OS가 그리는 영역의 최종 표현은 실제 설치 앱에서 확인하고, 브라우저 화면만 확인한 결과와 구분합니다.

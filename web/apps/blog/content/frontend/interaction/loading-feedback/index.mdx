## 입력 디바운스와 요청 취소

한 글자를 입력할 때마다 결과가 바뀌면 화면이 계속 흔들리고, API를 호출하는 화면에서는 쓰지 않을 요청이 쌓입니다. 늦게 보낸 요청의 응답이 먼저 도착하면 지금 입력한 검색어와 다른 결과가 화면에 남을 수 있습니다.

<Demo>
  <DebounceDemo />
</Demo>

입력이 멈추고 200~300ms 뒤에 검색을 실행합니다. 입력을 지우면 기다리지 않고 바로 되돌리고, Enter를 누르면 대기 없이 지금 검색어로 즉시 실행합니다. API를 호출할 때는 새 요청을 보내기 전에 이전 요청을 취소합니다. 디바운스는 요청 수를 줄일 뿐 응답 순서를 보장하지 않으므로 취소를 함께 써야 합니다.

## 대화상자의 데이터 준비

대화상자가 빈 상태로 작게 열렸다가 데이터가 도착하면서 갑자기 커지면 화면이 크게 튑니다. 반대로 금방 끝나는 응답에도 스피너를 즉시 띄우면 불필요한 깜빡임만 늘어납니다.

  <LoadingFeedbackDemo />
</Demo>

바깥 창과 준비 영역의 최소 높이를 먼저 잡아 두고, 응답이 150ms를 넘길 때만 이름 있는 원형 진행 표시를 보여 줍니다. 화면 전환의 진행 막대와 같은 시점입니다. 한 번 표시한 진행 표시는 최소 300ms 둔 뒤 내리고, 필요한 데이터가 준비되면 내용을 한 번에 표시합니다. 대화상자를 열고 닫을 때는 페이지 전환 효과를 쓰지 않습니다.

준비 확인 작업이 새로 생겼다는 이유만으로 캐시에 있는 내용을 가리지 않습니다. 필요한 조회가 실제 캐시에 남아 있는지 확인하고, 있으면 기다리지 않고 바로 그립니다. 실패는 무한 로딩 대신 실패 상태와 다시 시도로 끝납니다.

## 내용 변화에 따른 높이 전환

`height: auto`에는 CSS 전환이 걸리지 않아, 검색 결과 개수가 바뀔 때마다 대화상자 높이가 중간 과정 없이 한 번에 바뀝니다.

`ResizeObserver`로 바뀐 높이를 재고 앞 높이부터 200ms 동안 부드럽게 움직입니다. 움직임 줄이기 설정이 켜져 있으면 전환 없이 바로 바꿉니다.

```ts
const observer = new ResizeObserver(() => {
  if (motion) return;
  const next = element.offsetHeight;
  if (Math.abs(next - last) <= 1 || reduced.matches) {
    last = next;
    return;
  }
  motion = element.animate(
    [
      { height: `${last}px`, overflow: "hidden" },
      { height: `${next}px`, overflow: "hidden" },
    ],
    { duration: 200, easing: "cubic-bezier(0.2, 0, 0, 1)" },
  );
  motion.onfinish = () => {
    motion = undefined;
    last = element.offsetHeight;
  };
});
```

## 사진 자리를 먼저 잡기

사진을 올릴 때는 브라우저가 대표색과 원본 가로·세로를 재어 업로드 요청에 함께 보냅니다(64px로 줄여 색을 묶어 세고, 가장 많은 묶음의 평균색). 측정은 한 번에 하나씩, 3초 제한이며, 실패하면 측정값 없이 올립니다. 서버는 파일과 함께 저장해 첨부 정보로 돌려주고, 리치 본문은 사진 블록 속성에도 넣습니다.

보여 줄 때는 원본 비율과 대표색으로 자리를 먼저 칠해 내용이 밀리지 않게 하고, 받아야 하는 사진만 0.4초에 걸쳐 나타냅니다. 이 페이지에서 이미 받았거나 브라우저 캐시에 있는 사진은 바로 보입니다. 스켈레톤은 실제 배치와 같을 때만 씁니다.

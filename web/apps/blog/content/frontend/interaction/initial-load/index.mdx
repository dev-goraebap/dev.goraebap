## 빌드 때 넣는 첫 화면

앱 코드가 오기 전에도 빈 화면이나 테마 없는 화면을 보이지 않습니다. 빌드할 때 HTML에 첫 화면을 넣습니다.

| 화면 | 빌드 때 넣는 것 |
| --- | --- |
| 공개 문서·랜딩처럼 검색과 스크립트 없는 읽기가 필요한 화면 | 실제 본문을 미리 그린 HTML(SSG·프리렌더) |
| 로그인 뒤 업무 앱 | 스플래시 화면: 앱 표시의 정지 그림과 "불러오는 중입니다" |

## 폰트 로딩과 흔들림 방지

`font-display: swap`만 쓰면 새로고침 직후 시스템 폰트로 먼저 그려졌다가 웹폰트가 도착하면서 글자 폭과 줄바꿈이 흔들립니다. 반대로 폰트가 끝날 때까지 무조건 기다리면 느린 네트워크에서 빈 화면이 길어집니다. `document.fonts.ready`와 짧은 타임아웃(180ms)을 함께 두면 캐시·빠른 환경에서는 흔들림 없이 한 번에 표시하고, 느린 환경에서도 빈 화면에 갇히지 않습니다.

```html
<link rel="preconnect" href="https://cdn.jsdelivr.net" crossorigin />
<link rel="preconnect" href="https://fonts.googleapis.com" />
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin />

<style>
  html.fonts-loading { opacity: 0; }
  html { transition: opacity 120ms ease-out; }
</style>
<script>
  (() => {
    const root = document.documentElement;
    root.classList.add("fonts-loading");
    const reveal = () => root.classList.remove("fonts-loading");
    const timer = setTimeout(reveal, 180);
    if (document.fonts && document.fonts.ready) {
      document.fonts.ready.then(() => {
        clearTimeout(timer);
        reveal();
      });
    } else {
      reveal();
    }
  })();
</script>
```

CDN 호스트에 `rel="preconnect"`를 먼저 선언하고, 한국어 웹폰트는 다이나믹 서브셋을 써서 첫 로드 용량을 줄입니다. 스크립트가 실패하더라도 화면이 가려지지 않도록 짧은 타임아웃 폴백을 반드시 함께 둡니다.

## 스플래시 화면

로그인 세션, 권한, 워크스페이스 목록처럼 화면 골격을 결정하는 초기 데이터가 도착하기 전에 앱을 그대로 그리면, 빈 메뉴 → 권한별 리다이렉트 → 본문 스켈레톤이 연달아 깜빡이며 완성도가 떨어져 보입니다. 초기 부트 단계에서 가벼운 스플래시 화면을 유지했다가 필수 데이터와 폰트가 준비된 뒤 완성된 첫 화면을 한 번에 드러냅니다.

스플래시 화면은 다음 순서로 동작합니다.

1. 빌드 플러그인이 HTML의 앱 자리에 오버레이를 넣습니다. 색은 테마의 바닥·보조 글자 값을 `light-dark()`로 직접 적습니다. 앱 CSS가 오기 전이기 때문입니다.
2. 앱 스크립트보다 먼저 실행되는 짧은 스크립트가 저장한 라이트·다크를 문서에 적용합니다.
3. 앱이 뜨면 같은 모양의 오버레이가 그 자리를 이어받아, 첫 경로의 데이터가 준비될 때까지 보입니다. 너무 빨리 걷혀 깜빡이지 않도록 최소 0.3초 보이고, 0.7초에 걸쳐 걷습니다. 오버레이 아래의 첫 화면은 이미 다 그려져 있습니다.
4. 그 뒤의 화면 전환에는 스플래시 화면을 다시 쓰지 않고 [페이지 전환과 대기](../page-transition/index.mdx)를 따릅니다.

인증 실패나 네트워크 오류 때는 로딩에 갇히지 않고 오류 화면이나 로그인으로 바로 전환합니다.

토큰과 스타일은 빌드한 CSS 파일이라 실행 중에 스타일을 넣는 단계가 없습니다. 스플래시 화면 플러그인은 CSS를 읽기 전에 저장한 모드(문서 루트의 테마 속성)를 정하고 오버레이를 그 모드의 면 색으로 칠합니다. 빌드 때는 창 폭을 모르므로, 휴대폰·데스크톱 첫 배치는 CSS 미디어 쿼리로 가르거나 오버레이 뒤에서 정합니다. 그림은 각 제품이 자기 표시로 바꿉니다. 다른 제품의 그림을 옮기지 않습니다.

## 전환 기준과 표면 고르기

화면이 좁아졌다고 모든 오버레이를 같은 방식으로 바꾸면 짧은 안내가 과하게 커지거나, 하는 일과 맞지 않는 표면이 열립니다. 어떤 상호작용을 어느 표면에서 할지는 하는 일로 정합니다. 개별 도구의 동작은 [검색·필터·표시](../../../../../../../plugins/webapp/skills/frontend-design-system/references/search-filter.md), 대화상자의 배치는 [공통 다이얼로그](../../../../../../../plugins/webapp/skills/frontend-design-system/references/dialog.md), 제목·본문 작성은 [생성 양식](../../../../../../../plugins/webapp/skills/frontend-design-system/references/creation-form.md)이 소유합니다.

| 리소스의 상세·생성·수정 | [리소스 화면 패턴](../../../../../../../plugins/webapp/skills/frontend-design-system/references/resource-patterns.md)이 정한 곳(오른쪽 칸·자기 페이지·목록 위 대화상자) | 자기 페이지 |
| 주소가 필요 없는 기록 한 줄의 사실 | 옆 패널 | 바텀시트 |

전환 경계는 64rem 미만 하나입니다. 휴대폰에서 고르는 창(값 고르기·메뉴·짧은 양식·확인)은 모두 바텀시트로 엽니다. 시트 머리는 왼쪽에 제목, 오른쪽에 둥근 닫기 버튼을 둡니다. 대화상자와 팝오버는 경계에 따라 자동으로 바뀌는 공용 래퍼를 쓰고, 선택·메뉴·콤보박스·컨텍스트 메뉴는 휴대폰 판별로 나눠 바텀시트를 직접 조합합니다.

## 대화상자를 바텀시트로

데스크톱 중앙 대화상자를 휴대폰에 그대로 띄우면 위쪽 닫기 버튼에 엄지가 닿기 어렵고 좌우 여백 때문에 입력 영역이 좁아집니다. 필터 설정이나 선택지는 화면 아래에서 올라오는 시트로 엽니다. 그래야 한 손으로 조작하고 끌어내려 닫을 수 있습니다.

## 팝오버를 바텀시트로

트리거 옆에 뜨는 팝오버는 좁은 화면에서 좌우 가장자리에 잘리거나, 선택지가 여러 줄일 때 손가락에 가려 고르기 어렵습니다. 반대로 한두 줄짜리 짧은 도움말까지 시트로 열면 화면 흐름이 끊깁니다.

## 선택·메뉴·콤보박스를 바텀시트 목록으로

데스크톱 드롭다운은 항목 높이가 좁아 터치 오입력이 잦고, 검색 입력이 있는 콤보박스는 가상 키보드가 올라오면 결과 목록이 가려집니다. 우클릭으로 여는 컨텍스트 메뉴는 터치 기기에서 접근 경로 자체가 사라집니다.

## 되돌리기 어려운 확인

삭제·탈퇴·초기화처럼 되돌릴 수 없는 확인도 휴대폰에서는 바텀시트로 엽니다. 실행 동작을 위, 취소를 아래에 세로로 쌓고, 두 버튼을 명확한 동사로 구분합니다. 데스크톱에서는 중앙의 확인 창으로 엽니다.

## 호버 대체와 누르는 영역

터치 기기에는 마우스 호버와 우클릭이 없습니다. 툴팁이나 미리보기 카드 안에 필수 안내나 실행 동작을 숨기면 휴대폰 사용자는 확인할 방법이 없고, 작은 아이콘 버튼이 몰려 있으면 옆 항목을 잘못 누르게 됩니다.

호버 전용 컴포넌트에는 보조 설명만 두고 필수 정보는 화면에 직접 드러냅니다. 완료·취소·저장·다음·제출처럼 짧은 이름을 가진 실행 버튼은 휴대폰에서 최소 88px 너비를 확보합니다. 전체 폭 버튼은 바텀시트와 양식 끝처럼 버튼이 세로로 쌓이는 곳에만 씁니다. 아이콘 전용 버튼, 보기·도구·속성 칩에는 이 너비를 적용하지 않고, 인접한 보조 버튼 사이에는 충분한 간격을 둡니다.

## 가상 키보드와 안전 영역

휴대폰 브라우저에서 `100vh`는 주소창과 가상 키보드 높이를 반영하지 못해 아래쪽 버튼이 화면 밖으로 밀리거나 키보드 뒤에 가려집니다. 노치와 홈 인디케이터 영역에 아래쪽 실행 막대가 겹치면 마지막 버튼을 누르기 어렵습니다.

오버레이와 고정 패널의 높이는 동적 뷰포트 단위(`dvh`)로 제한하고, 아래 여백에는 `env(safe-area-inset-bottom)`을 더합니다. 바텀시트는 최대 높이 85dvh, 내부 스크롤, 아래쪽 안전 영역 여백을 기본으로 적용하므로 화면 아래 고정 막대나 직접 만든 패널에만 추가로 지정합니다.

## 화면 폭 전환 때 입력 상태 유지

자동으로 바뀌는 대화상자와 팝오버는 64rem 경계를 넘을 때 대화상자·팝오버와 바텀시트를 서로 바꿔 그립니다. 열림 상태는 래퍼가 이어 주지만, 안쪽에 비제어로 둔 입력값이나 선택 초안은 사라지면서 초기화됩니다.

창 크기를 바꾸거나 기기 방향을 돌려도 작성 중인 값이 사라지지 않도록, 입력값과 필터 상태는 래퍼 바깥의 상태에 두고 제어 속성으로 넘깁니다.

## 전역 검색과 폼은 자기 페이지로

휴대폰에서 가상 키보드가 올라오면 화면의 절반 이상이 가려집니다. 입력이 필요한 폼이나 전역 검색을 바텀시트에 넣으면 스크롤과 끌어내려 닫기가 충돌하고, 주소가 없어 새로고침할 때 작업 맥락을 잃습니다.

필터와 선택지만 자동 전환 대화상자로 처리합니다. 전역 검색과 폼은 길이와 관계없이 자기 주소를 가진 페이지가 원본이며, 데스크톱에서는 지금 화면 위 대화상자로 열고 주소만 대상 페이지로 바꿉니다([라우팅 마스크](../route-masking/index.mdx)). 휴대폰에서는 바텀시트 없이 처음부터 페이지로 이동합니다.

## 누르는 대상

행·카드 전체를 누르면 그 대상을 엽니다. 행 안의 링크·사람·별·메뉴는 행을 열지 않고 자기 동작을 합니다. 화면 이동은 링크(`href`)로 해 새 탭·주소 복사가 되게 합니다. 펼치기·별처럼 행 안의 버튼은 행 링크로 번지지 않게 합니다.

페이지를 대화상자에서도 쓰도록 바꿀 때 행 전체의 링크를 제목 텍스트 링크로 줄이지 않습니다. 행의 빈 곳과 설명·아이콘을 눌러 같은 대상으로 열리는지 확인하고, 행 안의 별도 동작은 구분합니다.

## 선택 칸

작은 고정 선택지는 펼친 선택지 목록, 큰 목록에서 찾는 입력은 검색이 있는 고르기(처음 8개·최대 50개)입니다. 검색을 열면 입력에 초점을 두고, 고른 뒤나 Esc 뒤에는 열었던 칸으로 초점을 돌립니다. 검색 중에 보이지 않는 선택 항목도 지킵니다. 대기·결과 없음·추가 결과 안내를 구분합니다.

날짜는 공통 달력 하나를 쓰고, 시간은 직접 입력과 목록을 함께 줍니다. 종료 시각은 시작 이후의 값과 길이를 함께 보입니다. 입력 방식은 창 폭으로 정해 터치 노트북에서도 데스크톱 배치가 깨지지 않게 합니다.

## 키보드

| 키 | 동작 |
| --- | --- |
| Esc | 열린 메뉴·검색·대화상자를 닫고 연 요소로 초점을 돌립니다 |
| Ctrl/⌘+Enter | 작성 양식 제출 |
| Enter | 짧은 양식의 한 줄 칸 제출 |
| Ctrl/⌘+S | 명시 저장을 고른 본문 편집의 저장 |

모든 단축키는 한글 조합 중(`isComposing`)에는 무시하고, 입력 칸에 초점이 있을 때 페이지 전역 단축키를 실행하지 않습니다.

## 순서 바꾸기

같은 목록 안의 순서는 손잡이 끌기와 키보드(Alt+↑/↓)를 함께 줍니다. Esc로 취소하고, 이동할 때마다 위치를 읽어 주며, 실패하면 원래 순서로 돌립니다. 트리는 어느 부모 안에서 옮길 수 있는지를 먼저 정합니다. 위·아래 메뉴로 대신하지 않습니다.

스택별 명령과 설정 코드는 스택 전환(`React · TanStack` · `Angular`)을 따릅니다.

- [표준 라이브러리](../../reference/standard-libraries/index.md)
- [디렉토리 구조](../../reference/directory-structure/index.md)

## 1. 런타임 · TypeScript · 경로 별칭 초기화

1. 패키지 매니저와 Node.js 버전을 프로젝트 설정에 고정합니다.
2. TypeScript `strict` 모드를 켜고, 소스 루트를 가리키는 경로 별칭(`@/* → ./src/*`)을 등록합니다.
3. 모노레포 환경이라면 공통 의존성 버전은 워크스페이스 카탈로그로 맞춥니다.

## 2. 표준 라이브러리 등록

[표준 라이브러리](../../reference/standard-libraries/index.md) 기준에 맞춰 빌드 도구, 라우터, HTTP·서버 상태, 스타일링, 품질 검사 의존성을 추가합니다.

- 아직 요구사항이 없는 선택 영역 라이브러리는 미리 넣지 않습니다.

## 3. 스타일과 디자인 시스템 연결

1. Tailwind CSS v4와 디자인 시스템 토큰·스타일 레시피 패키지를 연결합니다.
2. 전역 스타일 진입 파일에서 디자인 토큰과 기본 테마 변수를 로드합니다.

## 4. 라우팅과 `pages/` 계층 연결

[디렉토리 구조](../../reference/directory-structure/index.md)에 맞춰 `src/pages/`가 앱의 URL 트리와 1:1로 대응하도록 라우터를 연결합니다.

- 파일 기반 라우팅을 쓰는 스택은 `src/pages`를 라우트 루트로 지정하고 슬라이스 세그먼트를 스캔에서 제외합니다.
- 설정 기반 라우팅을 쓰는 스택은 루트 라우트 파일에서 최상위 `pages/<slice>/routes.ts`를 지연 로딩으로 잇습니다.

## 5. API 프록시와 환경 설정 분리

1. 로컬 개발 서버에서 백엔드 API 경로(`/api` 등)를 프록시하도록 설정해 CORS와 쿠키 문제를 줄입니다.
2. 환경마다 달라지는 값(API 주소, 공개 키 등)만 환경변수로 빼고, 키 목록을 `.env.example`에 기록합니다.
3. 실제 `.env`와 빌드 산출물 폴더는 `.gitignore`에 추가합니다.

## 6. 기본 레이어 뼈대와 품질 검사 구성

1. `src/app/`, `src/pages/`, `src/shared/` 기본 뼈대를 만들고, 첫 화면과 공통 API 클라이언트·에러 처리 진입점을 둡니다. (`widgets/`, `features/`, `entities/`는 해당 슬라이스가 생길 때 추가합니다.)
2. 포맷터, 린트, 미사용 코드 검사, 타입 검사를 한 번에 돌리는 `check` 스크립트를 `package.json`에 등록합니다.
3. 자동 생성되는 라우트 트리나 빌드 산출물은 검사 대상에서 제외합니다.

## 7. 동작 확인

1. 포맷 검사, 린트, 미사용 코드 검사, 타입 검사, 프로덕션 빌드를 모두 실행해 경고·오류 없이 통과하는지 확인합니다.
2. 로컬 개발 서버를 띄워 첫 라우트 렌더링, 디자인 토큰 적용, API 프록시 응답을 확인합니다.

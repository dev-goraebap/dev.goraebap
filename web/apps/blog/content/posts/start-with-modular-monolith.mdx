## 구체적인 운영 비용이 확인되기 전에는 쪼개지 않는다

DB와 배포 단위를 미리 나누면 트랜잭션 경계, 아웃박스, 백업 시점 불일치 같은 분산 시스템 비용을 첫날부터 떠안게 됩니다. 반대로 경계 없이 한 덩어리로 짜면 몇 달 뒤 손대기 어려운 스파게티가 됩니다.

해법은 **배포와 DB는 하나로 두되, 코드의 참조 방향과 다른 컨텍스트의 테이블 접근을 자동화된 테스트로 강제하는 것**입니다. 나중에 정말 분리가 필요해질 때 떼어낼 수 있는 상태만 유지하면 충분합니다.

| 구분         | 초기 선택                   | 분리 시점                                |
| ------------ | --------------------------- | ---------------------------------------- |
| 배포 단위    | 모놀리스 1개                | 트래픽·배포 주기가 확연히 갈릴 때        |
| 데이터베이스 | 업무 DB 1개                 | 부하·보관 주기가 달라질 때 (예: 로그 DB) |
| 모듈 경계    | 공개 계약 + 아키텍처 테스트 | 처음부터 강제                            |

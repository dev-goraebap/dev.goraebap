# rich-document (web/src/shared/lib/rich-document)

문서 편집의 인쇄 배치는 `PrintLayout` 확장이 소유한다. 블록의 `printBreakBefore`·`printKeepWithNext`·`printKeepTogether`를 JSON 속성으로 저장한다. `printLayout`을 켠 문서 편집 화면에만 설정을 노출하고 Markdown 초안에는 노출하지 않는다. PDF는 각 문서를 항상 새 페이지에서 시작하며, 첫 블록의 새 페이지 설정으로 제목과 본문 사이를 다시 나누지 않는다. 과거 문서 루트의 `printStartOnNewPage`는 편집용 사본에서 첫 블록의 설정으로 옮긴다. 노드뷰가 있는 표·그림·도표에는 Decoration으로도 인쇄 속성을 적용한다. 편집 표식은 읽기·인쇄 결과에 나타나지 않는다. 새 제목은 2~4단계만 제공하며 기존 1단계 데이터는 호환을 유지한다.

문서의 페이지 보기는 호스트가 `extensions`(페이지 나누기 확장)와 `frame`(종이 틀)으로 붙이고, `onReady`로 받은 에디터에 늘 붙은 서식 막대(`DocumentFormatBar`)를 단다. 이 폴더는 페이지를 모른다(부품은 `shared/ui/paged-document`).

cowork의 본문 뷰어·편집기다. BIT 저장소의 `packages/rich-document`(커밋 61856a9, 2026-11-01)를 복사해 cowork가 소유한다. BIT 쪽 변경을 따라가지 않으며, 고칠 것은 이 폴더에서 고친다. 패키지 이름만 `@/shared/lib/rich-document`로 바꿨고 CSS 클래스(`.bit-rich-document` 등)는 그대로 둔다.

cowork 화면은 이 패키지를 직접 부르지 않고 `client/src/shared/ui/rich-body`를 거친다. 그곳이 읽기로 열고 편집 버튼으로 바꾸는 화면, 저장 큐(500ms 뒤 저장, 앞 응답의 version으로 하나씩, 1분 멈춤·5분 연속 입력이면 checkpoint, 409면 초안을 지키고 멈춤), 첨부 업로드(`attachment:<id>`)를 맡는다. 서버 저장 계약은 쓰는 도메인이 정한다.

## 경계와 사용

```tsx
import {RichDocument, type JSONNode} from '@/shared/lib/rich-document';

<RichDocument
  documentId={`${record.id}:${loadedVersionId}`}
  value={record.body}
  mode={isEditing ? 'edit' : 'read'}
  onChange={(body: JSONNode) => saveDraft(body)}
  upload={uploadAttachment}
/>
```

`value`는 documentId에 해당하는 초기 스냅샷입니다. 입력 중의 onChange를 다시 같은 value로 넘겨도 에디터를 재생성하지 않습니다. 외부 문서 열기·버전 복원처럼 원문을 교체할 때는 documentId를 바꿉니다. mode 전환은 인스턴스와 Undo를 보존합니다. 데이터 형식은 JSONNode, 현재 schemaVersion은 `RICH_DOCUMENT_SCHEMA_VERSION = 1`입니다. 스키마 버전은 사용하는 도메인이 저장합니다.

본문·읽기·블록 이동·서식·표·수식·Mermaid·미디어 표현과 업로드 UI가 이 패키지의 책임입니다. 제목·문서 목록·현재 사용자·권한·저장 시점·서버 API·파일 소유권은 포함하지 않습니다. 업로드 함수는 File, 진행 콜백, AbortSignal을 받고 `{url,name,mime,size}`를 반환합니다. URL은 호스트가 관리하는 상대 주소, HTTPS, 또는 수명이 호스트가 관리하는 blob URL을 지원하며 임의 HTML은 받지 않습니다. upload가 없으면 첨부 동작은 연결되지 않았다는 오류를 표시합니다.

버전 목록·과거 읽기·비교는 선택 UI이며 VersionPanel/VersionBanner/VersionChanges를 공개합니다. 보관·충돌 검사·복원 전 자동 보관의 원자성은 호스트의 저장 어댑터가 책임집니다. 순수 비교는 `@/shared/lib/rich-document/version-diff`으로 가져올 수 있습니다. 이 패키지는 실험 서버의 /api/documents 또는 /api/files를 호출하지 않습니다.

## 스타일과 아이콘

본문 내용(ProseMirror 노드·표·코드·인쇄 배치)의 규칙은 `styles.css` 하나에 전역 CSS로 둡니다(Tailwind로 쓸 수 없는 자손 규칙). 색은 테마 토큰(`var(--foreground)` 등)만 쓰고 Astryx `--color-*` 변수는 쓰지 않습니다. 종이 틀(`shared/ui/paged-document`)의 본문 간격·인쇄 규칙도 `[data-paged-canvas]`로 이 파일에 둡니다. 본문과 팝업 스타일은 `.bit-rich-document` / `.bit-rich-document-floating`에 제한합니다. 호스트의 테마 색과 color-scheme을 이어받고 밝은/어두운 색을 지원합니다. 본문 색상 선택값은 원문에 그대로 보존합니다. Pretendard와 UI 디자인 시스템은 호스트가 제공하고, 명조 Maru Buri 및 라이선스는 패키지가 번들합니다. KaTeX와 코드·수식 전용 글꼴은 유지합니다.

화면 아이콘은 Solar by 480 Design (CC BY 4.0)입니다. 24 격자의 원본 Linear 1.5 선을 보존하고, 호스트와 같이 오버플로만 Bold Duotone을 씁니다. 기본 도구16, 슬래시/본문 의미18, 상태20/24px로 정리했습니다. 의미 이름을 icons.ts로 공개하므로 문서 JSON에 아이콘 라이브러리가 섞이지 않습니다. 제목1~4는 Solar text-format 그림과 항목 이름으로 구분하며 Solar에 없는 Lucide 그림을 섞지 않습니다. `node packages/rich-document/scripts/generate-icons.mjs`는 호스트의 고정된 @iconify-json/solar를 사용해 선택 SVG만 생성합니다. NOTICE와 글꼴 LICENSE를 보존합니다.

글자색·배경색은 실제 A/색상 견본과 선택 표시를 가진 팔레트입니다. 방향키/Home/End로 이동하고 Enter/Space로 적용, Esc로 취소하고 원래 트리거로 돌아갑니다. 스크린리더 이름에는 색 이름을 유지합니다. 편집기 바깥 틀(단추·고르기·입력 칸·대화상자·툴팁)은 호스트의 shadcn/ui(Base UI) 키트(`@/shared/ui/*`)를 씁니다: 단추는 `Button.tsx`(키트 Button), 콜아웃 종류·코드 언어·미디어 너비는 `DocumentSelect`(짧으면 키트 Select, 길면 찾기 칸이 있는 OptionList), 수식·도표 원문은 `SourceArea`(키트 Textarea)입니다. 블록 메뉴·서식 도구·표 도구의 떠 있는 메뉴는 이 패키지의 것(menus.tsx)을 유지합니다: 하위 메뉴(색 · 종류 바꾸기)의 배치와 키보드를 `npm run editor-menu:check`가 검사합니다. 키트의 에디터 부품(`shared/ui/editor`)은 저장하는 색 값과 명령 목록이 달라 쓰지 않습니다. 업로드의 숨긴 file input은 브라우저 파일 선택 책임을 유지합니다.

## 댓글과 버전 — 모듈/브라우저 구현, 운영 서버 미연결

댓글 대화 자체와 본문상의 연결 위치를 분리합니다. 대화에는 문서ID·생성 버전·작성자·메시지·해결 이력을 두고, 위치에는 대상 버전ID·블록ID/범위·인용 원문·연결 상태를 둡니다. 버전마다 대화 전체를 복제하지 않습니다. 본문 버전은 불변이며 새 버전의 위치로 이전할 수 있을 때만 연결하고, 삭제/모호함은 분리 또는 연결 불가로 표시합니다. 과거 버전의 범위에 현재 offset을 그대로 적용하지 않습니다.

과거 시점의 대화/해결 상태를 재현하려면 댓글 이벤트의 시각 또는 별도 revision을 함께 조회해야 합니다. 본문 버전ID만으로 나중에 달린 댓글까지 과거에 존재했던 것처럼 표시하면 안 됩니다. 복원은 새 현재 버전을 만드는 작업이며 댓글을 삭제하지 않고 새 앵커를 계산합니다. 현재 모듈과 데모는 문장/블록 댓글 작성·답글·해결·위치 강조/이동과 브라우저 저장을 구현했습니다. 운영 BIT 댓글 API, 다중 사용자 동기화, 알림, 서버 권한 검사는 아직 연결하지 않았습니다. 데모 자료는 기존과 같이 사용자별 IndexedDB에 보존합니다.

## 본문 도구·목차·기록 창 (BIT-147)

`DocumentToolbar`는 본문 상단 우측에 글꼴과 읽기/편집·버전 기록을 원형 아이콘 버튼으로 모읍니다. 아이콘 버튼은 접근 가능한 이름과 툴팁을 유지하며 호스트의 chip 배경·테두리·radius 토큰을 사용합니다. 호스트 페이지 헤더의 슬롯이나 탐색 구조를 참조하지 않습니다. 데모의 개발 안내 메타 줄은 제거했습니다. 스크롤 중에는 도구막대가 본문 위에 유지되며, 호스트는 `--rd-toolbar-top`으로 자체 헤더 아래 여백을 지정할 수 있습니다. 문서 도구는 좁은 화면에서도 같은 본문 위치에 있습니다.

본문의 제목1~4에서 계층 목차를 자동으로 만듭니다. 우측 막대는 현재 읽는 제목을 강조하며 마우스가 350ms 머물면 목록을 160ms 동안 부드럽게 엽니다. 빠르게 스쳐 지나가면 예약을 취소하며 클릭/키보드는 즉시 엽니다. reduced-motion에서는 전환 효과를 없앱니다. 방향키/Home/End로 항목 탐색, Enter로 해당 제목으로 스크롤, Esc로 닫고 트리거에 포커스를 돌립니다. 제목 편집·삭제·Undo에 목록이 반응합니다. 접힌 토글 안 제목은 이동 시 토글을 펼칩니다. 읽기 위치 이동 자체가 텍스트 선택/편집 전환을 일으키지 않습니다.

`VersionHistoryDialog`는 자동 기록의 날짜·시각·종류를 나열하는 작은 대화상자(키트 Dialog)입니다. 본문 미리보기와 수동 저장 폼은 넣지 않습니다. 버전을 선택하면 창을 닫고 주 본문에 읽기 전용 과거 버전을 표시하며, 현재 초안과 Undo 인스턴스는 숨긴 채 보존합니다. 과거 본문의 배너에서 현재로 돌아가기·변경 비교·명시적 복원을 수행합니다. 닫기/Esc/바깥 클릭은 원문을 바꾸지 않고 호출한 컨트롤로 포커스를 돌립니다. 모바일도 목록만 보여주는 작은 창입니다.


## 댓글 사용과 위치 추적 (D-129)

읽기 화면에서는 문장을 드래그한 뒤 댓글 버튼, 블록에 마우스를 올린 뒤 왼쪽 댓글 버튼을 씁니다. 편집 화면에서는 텍스트 선택 서식 도구의 댓글, 블록 메뉴의 댓글 또는 다중 블록 선택 줄의 댓글 버튼을 씁니다. Ctrl/⌘+Alt+M도 지원합니다. 작성 창에서 Ctrl/⌘+Enter는 등록, 취소/Esc는 본문과 댓글을 바꾸지 않습니다. 본문 위 도구의 댓글 아이콘은 목록을 엽니다. 목록은 비모달이므로 열린 채 본문을 수정할 수 있고, 미해결/전체/연결 끊김 필터, 원문 위치 이동, 답글, 해결/다시 열기를 제공합니다. 원문 전체 폭을 밀지 않으며 작은 화면에서는 하단 카드로 표시합니다.

`RichDocument.comments`는 `CommentBindings`를 받습니다. host가 threads와 author, onCreate/onReply/onResolve를 공급하고 `openRequest`를 바꿔 목록을 열 수 있습니다. 읽기/편집은 본문의 수정 모드이고 댓글 작성 권한과는 별개입니다. `comments.readonly`는 과거 버전/권한 제한 댓글 보기이며 작성·답글·해결을 숨깁니다. 운영 호스트는 이 콜백에서 인증과 권한, 저장 성공/실패를 처리해야 합니다. `onChange(body, anchors)`의 두 번째 인자는 해당 본문 변경에 맞춘 현재 위치입니다. 데모는 둘을 같은 IndexedDB 레코드 갱신으로 저장합니다. 댓글 자체를 문서 JSON mark나 Undo 이력에 넣지 않습니다.

문장 앵커는 텍스트 블록의 안정 ID, ProseMirror UTF-16 범위, 현재 텍스트/주변 문맥과 작성 당시 인용을 보존합니다. 일반 편집은 transaction mapping을, 토글/열 사이 이동은 안정 ID를 사용합니다. 분할된 문장은 여러 범위로 추적할 수 있습니다. 전체 삭제는 연결 끊김으로 남기며 다른 곳의 같은 문장으로 옮겨 붙이지 않습니다. Undo와 버전 복원에서는 원래 ID/기록된 위치/문맥을 검증해 복구합니다. 일부 삭제와 모호한 문맥은 별도 상태로 표시합니다. 블록 댓글은 하나 이상 블록 ID를 추적합니다. 하이라이트는 decoration이므로 복사/본문 export에는 댓글 데이터가 섞이지 않습니다.

대화·메시지·해결 이벤트는 전역 댓글 sequence를 가진 별도 자료입니다. 각 버전에는 `CommentSnapshot {seq, anchors}`만 두며 대화 전체를 복제하지 않습니다. 과거 보기는 생성/답글/해결 sequence를 잘라 그 시점까지의 상태를 재현하고, 그 뒤 작성된 댓글이나 답글을 섞지 않습니다. 댓글 위치 기록이 없는 구버전은 과거 댓글을 추측해 표시하지 않습니다. 복원은 전체 현재 대화를 보존한 채 대상 버전의 저장된 앵커 또는 안정 ID/문맥으로 위치를 검증합니다. 현재보다 나중에 만든 댓글도 삭제하지 않으며 위치를 확인할 수 없으면 연결 끊김/확인 불가로 남깁니다. 데모의 sequence는 클라이언트 자료이고 운영의 권한/감사 원장이 아닙니다.


선택 서식 메뉴는 가장 가까운 스크롤 컨테이너를 따라 fixed로 배치하고, 위 공간이 부족하면 아래로 전환합니다. 호스트는 `--rd-selection-top`으로 고정 헤더/도구막대 아래의 상단 안전 여백을 지정할 수 있습니다. 기록된 앵커가 연결 끊김/모호함 상태였다면 해당 과거 버전 복원에서 같은 위치의 다른 문장에 다시 붙이지 않습니다.

## 표 모양과 표 둘레 편집 도구 (cowork, 2026-11-10)

표는 모서리를 둥글리지 않고 바깥 양옆 세로선 없이 그리며, 머리글 칸에 옅은 바탕을 둡니다. 화면 아래에 뜨던 표 도구 상자(`TableTools`)는 없애고 `TableControls`로 바꿨습니다. 포인터가 있는 칸(없으면 커서가 있는 칸)의 행 왼쪽·열 위쪽에 손잡이가 뜨고, 누르면 그 행·열의 메뉴(추가·옮기기·머리글 켜기/끄기·삭제)가 열립니다. 표 왼쪽 위 단추는 표 전체 메뉴(셀 병합·나누기·머리글·표 삭제), 오른쪽·아래의 + 막대는 끝에 열·행을 더합니다. 열 너비는 열 경계를 끌어 바꿉니다. Tiptap은 편집기가 만들어질 때 편집 가능해야만 너비 조절을 붙이는데 본문은 읽기로 열리므로, `schema.ts`의 `ResizableTable`이 늘 붙여 두고 `SyncedTableView`가 실행 취소 때 열 너비를 화면에서도 되돌립니다. 명령 하나는 실행 취소 한 단계입니다.

Tiptap의 Table Node UI는 유료(Start 플랜) 부품이라 쓰지 않고, 이미 있는 `prosemirror-tables` 명령(`moveTableRow`·`moveTableColumn` 포함) 위에 직접 만들었습니다. 행·열을 끌어 순서를 바꾸는 것과 행 높이 조절은 넣지 않았습니다. 병합된 칸이 섞인 표에서는 손잡이가 그 칸의 첫 행·열을 가리키며, 터치 화면에서는 커서가 있는 칸 기준으로만 뜹니다.

## 블록 메뉴 · 선택 서식 도구 · 파일 올리는 칸 (cowork, 2026-11-10)

떠 있는 메뉴는 `menus.tsx`의 부품(한 줄 `MenuItem`, 색 목록 `ColorList`, 종류 목록 `TurnIntoList`)을 함께 씁니다. 블록 손잡이 메뉴(`BlockMenu`)는 블록 종류를 제목으로 두고 색(글자색·배경색 하위 메뉴), 종류 바꾸기(하위 메뉴), 서식 지우기, 복제·복사·링크 복사, 위·아래로 옮기기, 삭제를 묶음별로 보입니다. 블록을 고른 채 Ctrl/⌘+D(복제), Ctrl/⌘+C(복사), Delete(삭제), Alt+↑/↓(옮기기)가 동작합니다. 링크 복사는 주소에 `#block-<id>`를 붙이고, 그 주소로 열면 그 블록으로 옮겨 갑니다. 목록 안의 글 위에서도 그 목록의 손잡이가 보입니다.

글을 고르면 뜨는 도구(`SelectionMenu`)는 블록 종류, 굵게·기울임·밑줄·취소선·코드, 링크, 색, 더 보기(위·아래 첨자, 줄 정렬, 내어쓰기·들여쓰기, 서식 지우기) 순서입니다. Markdown으로 저장하는 본문에는 밑줄·첨자·정렬을 보이지 않습니다. 위·아래 첨자는 `@tiptap/extension-superscript`·`subscript`를 더한 것이고, 서버의 Markdown 변환은 이 표시를 옮기지 않습니다(MCP에서는 해당 표시가 든 블록을 보존 표시로 유지함).

`/` 명령의 파일은 파일 고르기를 바로 열지 않고 본문의 그 자리에 올리는 칸(`upload-zone.ts`)을 띄웁니다. 칸은 화면 표시(decoration)라 문서에 저장되지 않으며, 누르거나 파일을 끌어다 놓으면 올리기 시작하고 닫힙니다. 예전의 색 고르기(`ColorPicker`)와 도구 안의 고르기 상자는 없앴습니다.

## 도표 · 사진 · 파일 블록의 모양 (cowork, 2026-11-10)

도표(Mermaid), 사진·동영상, 파일 블록에서 위에 붙던 머리 띠와 상자 틀, 사진 아래의 이름 줄을 없앴습니다. 도구(크게 보기 · 너비 · 원문 복사 · 편집 · 내려받기)는 포인터를 올리거나 초점이 들어올 때 블록 오른쪽 위에 뜹니다(`.media-tools`). 사진은 높이 한도(`--media-max-block`, 32rem) 안에서 원본 비율대로 가운데에 놓이고, 이어 놓인 사진의 너비를 25%·50%로 줄이면 한 줄에 나란히 놓입니다. 파일은 종류(`file-kinds.ts`: PDF·워드·한글·엑셀·발표 자료·압축·코드 등)의 색을 띤 카드로 보입니다. 본문에 올릴 수 있는 형식은 서버의 `UploadPurpose`가 정하며, 카드의 종류 표시는 올릴 수 없는 형식의 것도 미리 갖고 있습니다.

## 링크 입력 · 문서 언급 · HTML 파일 (cowork, 2026-11-10)

링크는 대화상자 대신 서식 도구 아래의 입력 칸(`SelectionMenu`의 `LinkPanel`)에서 건다. 주소를 붙여 넣거나(`example.com`은 `https://`를 붙임), 호스트가 넘긴 문서 목록(`links`: 같은 프로젝트의 문서와 하위 페이지)에서 이름으로 찾아 고른다. 고른 문서는 앱 안의 주소(`/projects/{key}/documents/{id}`)로 걸리고 본문에서는 옅은 바탕의 이름표로 보인다. 읽는 화면에서 앱 안의 주소로 가는 링크는 새 탭 대신 그 화면으로 간다(`RichBody`의 `followInside`). 서식 도구는 본문 칸의 좌우 안에 머문다.

HTML 파일(`text/html`)은 파일 카드 아래에 미리보기 틀을 둔다. 올린 사람의 스크립트가 들어 있을 수 있으므로 `sandbox="allow-scripts allow-forms allow-popups"`(같은 출처 권한 없음)로만 그려, 틀 안의 문서가 앱의 화면·쿠키·저장소에 닿지 못하게 한다. 로컬 저장소는 HTML을 `Content-Security-Policy: sandbox`와 함께 내보낸다. 본문에 올릴 수 있는 형식은 2026-11-10에 발표 자료·압축·텍스트·CSV·HTML까지 넓혔다(서버 `UploadPurpose.EVIDENCE`, 한도 10MB 그대로).

## HTML 임베드 · 도표 크기 · 원문 편집 칸 (cowork, 2026-11-10)

`/` 목록에서 주소로 넣던 웹 임베드를 빼고 HTML 임베드를 둡니다: 고르면 HTML 파일만 고르는 올리는 칸(`upload-zone.ts`의 `kind: 'html'`)이 뜨고, 올린 파일은 격리된 미리보기 틀로 들어갑니다. 이미 본문에 있는 웹 임베드 블록(`webEmbed`)은 그대로 보이며, 고칠 때는 점선 칸의 주소 한 줄로 고칩니다. 도표는 칸 폭을 채우되(원래 크기의 3배까지) 높이 36rem 안에서 그립니다. 도표·수식의 원문 편집 칸은 어두운 색으로 고정돼 있던 것을 테마 색을 따르게 했습니다.

## HTML 임베드를 읽는 화면에서 보기 · 크게 보기 · 링크 카드 (cowork, 2026-11-10)

저장한 HTML 임베드는 읽는 화면에서 열리지 않았습니다. 파일 주소가 `/api/**`의 응답이라 `X-Frame-Options: DENY`가 붙었기 때문입니다(수정 화면에서는 저장 전의 임시 주소라 보였습니다). 지금은 서버가 HTML 파일을 전용 주소 `/api/embeds/{서명}/{파일}`로 내줍니다(BIT의 페이지 보기와 같은 방식).

- 파일을 여는 주소(각 모듈의 `…/files/{id}`)는 그대로입니다. 권한을 확인한 뒤, HTML을 제자리에서 열 때만 전용 주소로 돌려보냅니다(`FileService.openUrl`, `HtmlEmbeds`). 내려받기는 전과 같습니다.
- 전용 주소의 응답은 격리 정책(`Content-Security-Policy: sandbox …; frame-ancestors 'self'`)을 달고 나갑니다(`HtmlEmbedSecurityConfig`). 그 문서는 출처가 없는 상태로 실행되어 이 앱의 쿠키·저장소·화면에 닿지 못하고, 우리 화면 안의 틀에서만 열립니다. 주소를 새 탭으로 바로 열어도 같습니다.
- 서명한 주소는 1시간 뒤 만료됩니다. 본문을 다시 읽으면 새 주소를 받습니다.
- 크게 보기: HTML 임베드의 도구에 크게 보기를 두었습니다(`openHtml`, `shared/ui/zoom-viewer`의 `HtmlViewer`). 창을 거의 채우는 `<dialog>` 안에 같은 격리 틀로 그리고, Esc와 닫기로 닫습니다. 새 탭에서 열기는 서버가 내주는 주소일 때만 둡니다(저장 전의 `blob:` 주소는 새 탭에서 이 앱의 출처로 열리므로 내놓지 않습니다).

링크 카드: `webEmbed` 노드는 이제 주소의 페이지를 틀에 넣지 않고, 그 페이지의 제목·설명·대표 사진을 카드로 보여 줍니다(`LinkCard.tsx`). `/` 목록의 "링크 카드"로 넣고, 이미 본문에 있던 웹 임베드도 카드로 보입니다. 노드의 모양(`source`에 주소)은 그대로라 저장된 본문과 마크다운 변환은 바뀌지 않습니다.

- 페이지는 서버가 읽습니다(`GET /api/v1/link-previews?url=`, `LinkPreviews` · `HttpPageReader`). 사용자가 고른 주소로 서버가 안쪽 망을 부르지 않도록 HTTPS 443, 공개 주소만 부르고, 리다이렉트도 한 번씩 같은 검사를 거칩니다(최대 3번). 5초 안에 답한 HTML의 앞 512KB만 읽고, 답은 6시간 기억합니다.
- 읽지 못한 주소는 주소만 있는 카드가 됩니다. 대표 사진은 읽는 사람의 브라우저가 그 사이트에서 직접 받습니다(리퍼러 없이).
- 읽는 화면에서는 카드 전체가 새 탭으로 여는 링크이고, 수정 화면에서는 누르면 블록이 선택되며 열기·주소 고치기는 위에 뜨는 도구로 합니다.

## MCP 본문과 Markdown 초안 (2026-11-10)

MCP의 첨부 이미지를 독립 문단으로 읽으면 서버가 media 블록으로 바꿉니다. 공지·오피스의 Markdown 초안도 같은 변환을 쓰며, 기존 attachment 참조를 파일 주소로 바꿔 사진으로 표시합니다. 업로드 칸의 파일 선택 함수는 편집기 뷰가 초기화·마운트된 뒤 연결하고, 해제 때 정리합니다. 초기화 전 storage에 접근해 공지 편집 화면이 중단되던 문제를 막습니다. MCP에서는 열 배치 등 Markdown으로 옮길 수 없는 블록을 보존 표시로 주고받습니다. Markdown만 저장하는 초안에는 보존 표시를 만들지 않습니다.

arc42의 9절은 시스템에 영향을 준 중요한 아키텍처 결정과 그 배경, 기각한 대안을 기록합니다. Webcraft에서는 규칙 절 본문에 결정 날짜나 과거 이력을 섞지 않고, 지침을 바꾼 결정과 긴 경위는 각 스킬의 `notes.md`(현재는 디자인 시스템의 지침 개선 기록)에 모읍니다. 개별 프로젝트에서 내린 되돌리기 어려운 기술 선택과 지침 예외의 이유는 해당 프로젝트의 기록과 `AGENTS.md` 프로젝트 규칙 표에 남깁니다.

최근 Webcraft와 레퍼런스 키트에서 내린 주요 결정은 다음과 같습니다.

| 날짜 | 결정 | 이유 |
| --- | --- | --- |
| 2026-11-05 | 반응형 분기점·셸 배치 전환에서도 페이지의 `Card` 부모 요소를 유지 | `Card`와 `VStack` 사이에서 부모 요소 종류가 바뀌면 페이지가 다시 마운트되어 작성 중인 초안이 사라지기 때문입니다. |
| 2026-11-07 | Storybook을 걷어내고 가이드 문서 안에 실제 키트 견본을 iframe으로 배치 | 정적 캡처는 직접 조작할 수 없고 키트가 바뀔 때마다 다시 떠야 하며, 별도 Storybook은 가이드 테마 선택과 갈라지기 때문입니다. |
| 2026-11-08 | 앱 코드 로드 전 첫 화면 규칙으로 업무 앱의 첫 방문 덮개(`BootCover`)와 공개 문서의 SSG를 구분 | 스크립트와 테마 CSS가 오기 전에 빈 화면이나 테마 없는 화면이 깜빡이는 현상을 막기 위해서입니다. |
| 2026-11-08 | 가이드 사이트를 Astro에서 키트와 같은 React·Vite·TanStack Router SPA로 전환 | 클라이언트 라우팅 시 테마 스타일 유실과 셸 재마운트를 막기 위한 우회를 없애고, 키트와 같은 전환 규칙을 그대로 쓰기 위해서입니다. |
| 2026-11-09 (0.8.0) | 화면 이동에서 본문을 가리는 막 대신 진행 표시와 교차 페이드 사용 | 스켈레톤·영역별 덮개·불투명 막은 본문 높이와 맞지 않거나 재방문에서도 화면을 가리므로, 캐시는 즉시 그리고 150ms가 넘는 대기만 카드 위쪽 진행 표시로 알립니다. |
| 2026-11-09 (0.8.0) | 리치 본문(본문 칸·상세 본문)을 데스크톱·휴대폰 모두 16px, 줄 높이 1.7로 설정 | 조밀한 목록·도구용 본문 토큰(13px·15px)과 긴 글을 읽고 쓰는 영역의 가독성 요구를 분리하고 작성 칸과 상세 본문의 크기를 맞추기 위해서입니다. |
| 2026-11-09 (0.8.0) | 공통 지침 제안을 Webcraft 공개 저장소 이슈로 일원화 | 프로젝트에 지침 사본을 두지 않고 `AGENTS.md`의 프로젝트 규칙 표와 원본 저장소 이슈로 예외와 회수를 관리하기 위해서입니다. |
| 2026-11-09 (0.9.0) | 가이드 메뉴를 arc42(1~9절) 기반으로 다시 묶고 지침마다 `arc42` 번호를 부여 | 지침을 읽는 사람과 프로젝트 아키텍처 정의서를 쓰는 에이전트가 같은 절 구조에서 규칙과 화면 해설을 찾고 연결하게 하기 위해서입니다. |

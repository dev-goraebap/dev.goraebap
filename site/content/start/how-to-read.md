화면을 새로 만들거나 기존 화면을 검토할 때 이 규칙집을 판단 기준으로 쓴다. 프론트엔드 레이아웃 이론을 깊이 모르는 개발자와 페이지를 만들기 전에 기준을 읽는 AI 에이전트가 같은 규칙을 보고 언제 무엇을 왜 선택하는지 결정한다.

규칙의 원본은 에이전트가 읽는 디자인 시스템 스킬의 Markdown 문서다. 이 가이드 사이트는 같은 규칙을 사람이 읽도록 풀어 쓴 해설이다(2026-11-07 결정). 규칙이 바뀌면 스킬을 먼저 고치고 가이드를 다시 쓴다. 두 문서의 내용이 다르면 스킬이 맞다.

규칙은 특정 UI 라이브러리나 부품 이름이 아니라 역할(셸, 머리 줄, 도구 자리, 본문 열)로 적는다. 기술 스택을 바꿔도 화면 설계 규칙은 그대로 두고, 끝에 분리해 둔 [구현 메모](/app-shell/astryx-notes/) 한 페이지만 다시 쓴다.

## 규칙의 세 가지 표시

모든 규칙 앞에는 성격을 나타내는 표시를 붙인다. 규칙을 따르거나 바꿀 때 이 표시를 보고 판단한다.

| 표시 | 뜻 | 바꿀 때 |
| --- | --- | --- |
| `[관례]` | 여러 제품과 디자인 지침이 같은 방향으로 수렴한 규칙이다. 근거 링크가 있다. | 근거가 바뀌었을 때 |
| `[고래밥]` | 뚜렷한 관례가 없거나 관례와 다르게 정한 우리 결정이다. 선택 이유와 감수하는 대가를 함께 적는다. | 결정 당시의 이유가 더 이상 맞지 않을 때 |
| `[선호]` | 사용자 취향으로 고른 시각적 모양이다. 기능이나 사용성 규칙이 아니다. | 취향이 바뀌면 자유롭게 |

규칙의 배경이 된 2026-11-07 조사에서는 실제 제품(Linear, Plane)과 디자인 지침(Primer, Atlassian, Apple HIG, Android Material, Carbon, NN/g)을 같은 기준으로 비교했다. 항목별 대조 결과는 [비교 표](/references/comparison/)에, 원문 출처는 [레퍼런스 읽기 목록](/references/reading-list/)에 정리했다. Linear 화면의 실제 px 수치처럼 공개 자료에서 확인하지 못한 값은 비교 표에 미확인으로 남겨 두었다. 관례와 다른 결정을 내린 배경은 [결정 기록](/start/decisions/)에서도 모아서 볼 수 있다.

## 화면을 만들 때 읽는 순서

새 화면을 설계하거나 에이전트가 페이지를 만들 때는 아래 순서로 문서를 읽고 판단한다.

1. [화면 유형 고르기](/start/choose-surface/)에서 만들 화면이 앱 셸인지, 앞으로 다룰 랜딩·문서 사이트인지 먼저 정한다.
2. 해당 화면 유형의 규칙집을 연다. 로그인 뒤 사이드바와 콘텐츠 영역으로 이루어진 업무 도구는 [앱 셸 개요](/app-shell/overview/)부터 읽는다.
3. 새 작업이나 대상을 열 때 대화상자, 미리보기 패널, 라우트 마스킹, 자기 페이지 중 무엇을 쓸지 [어떤 모습으로 열까](/app-shell/choosing-presentation/)의 판단표로 결정한다.
4. 화면을 이루는 각 영역의 규칙을 확인한다.
   - 틀과 탐색은 [셸과 사이드바](/app-shell/shell-and-sidebar/), [머리 줄과 툴바](/app-shell/header-and-toolbar/), [콘텐츠 폭](/app-shell/content-width/)에서 정한다.
   - 목록 구성과 도구 배치는 [컬렉션](/app-shell/collections/), [필터와 표시](/app-shell/filters-and-display/)를 따른다.
   - 화면 전환과 기기 대응은 [라우트 마스킹](/app-shell/route-masking/), [미리보기 패널](/app-shell/peek/), [적응형](/app-shell/adaptive/)에서 확인한다.
   - 상태 안내와 시각 표현은 [상태와 피드백](/app-shell/states-and-feedback/), [시각 위계](/common/visual-hierarchy/), [아이콘](/common/icons/)을 따른다.
5. [선호 화면](/app-shell/preferred-screens/)에 정리된 기준 모양에서 출발해 화면을 구성한다. 현재 스택의 부품 연결 방법은 [구현 메모](/app-shell/astryx-notes/)만 참고한다.

목록·표·보드 같은 [컬렉션](/app-shell/collections/) 화면에서 항목을 찾고 거르고 배열할 때 쓰는 세 도구(검색·필터·표시)의 설계 규칙이다. 화면을 만들거나 검토할 때 세 도구를 어떻게 나누고, 적용된 조건을 어디에 드러내며, 주소(URL)와 방문 기록을 어떻게 다룰지 이 기준으로 판단한다.

규칙 앞의 표시는 결정의 성격을 나타낸다.

- **[관례]**: 여러 제품과 디자인 지침이 같은 방향으로 수렴한 규칙이다.
- **[고래밥]**: 관례가 없거나 관례와 다르게 정한 규칙과 그 이유다.
- **[선호]**: 기능 계약이 아니라 시각적 취향으로 정한 모양이다.

---

## 세 도구의 역할과 배치

1. **[관례] 도구는 역할에 따라 검색·필터·표시 셋으로 나누고 한 메뉴에 섞지 않는다.**
   - **검색**: 입력한 글자로 항목을 좁힌다.
   - **필터**: 속성 값으로 목록에 남길 항목을 거른다(무엇을 보일지).
   - **표시**: 걸러진 항목을 어떻게 보일지 정한다(레이아웃·정렬·그룹·보일 속성).
   - [Linear의 표시 옵션 문서](https://linear.app/docs/display-options)는 표시 옵션이 모든 항목을 어떻게 보일지 정하고 필터가 목록을 좁힌다고 명시하며, Plane도 표시(`display-filters`)와 필터(`filters`)를 분리한다. 무엇을 남길지와 어떻게 배열할지를 한 메뉴에 섞으면 조건을 지우거나 초기화할 때 범위가 모호해진다.

2. **[고래밥] 도구는 `검색 → 필터 → 표시` 순서로 같은 좁은 간격 안에 묶는다.**
   - [머리 줄과 툴바](/app-shell/header-and-toolbar/) 규칙에 따라 뷰·탭이 있으면 툴바 오른쪽에 두고, 뷰가 없으면 머리 줄 오른쪽에 둔다. 만들기 버튼은 도구 묶음보다 넓은 간격을 띄워 머리 줄 맨 끝에 둔다.

3. **[선호] 세 도구는 둥근 버튼으로 두고, 켜진 상태는 채운 아이콘과 모서리 점으로 표시한다.**
   - 기본 상태는 선 아이콘을 쓰고, 검색어가 있거나 필터·표시가 기본값과 다를 때는 채운 아이콘과 모서리 점으로 활성 상태를 드러낸다. Linear 실제 화면의 도구 버튼이나 칩의 구체적인 픽셀(px) 수치는 공개 자료에 없어 확인하지 못했다.

| 도구 | 질문 | 다루는 대상 | 적용 시 화면 변화 |
| --- | --- | --- | --- |
| 검색 | 어떤 글자가 들어 있는가 | 제목·본문·식별자 등 텍스트 | 검색 칸 유지, 검색 도구 활성 표시 |
| 필터 | 어떤 속성 값에 해당하는가 | 상태·담당자·라벨·날짜 등 속성 | 툴바 아래 적용 칩 줄 생성, 필터 도구 활성 표시 |
| 표시 | 어떻게 배열하고 무엇을 드러낼까 | 레이아웃·정렬·그룹·행에 보일 속성 | 칩 줄 없음, 표시 도구에 모서리 점과 메뉴 안 초기화 노출 |

## 검색 동작

1. **[고래밥] 검색 도구는 누르면 그 자리에서 입력 칸으로 펼쳐진다.**
   - 별도 대화상자나 다른 줄을 열지 않고, 툴바(또는 머리 줄)의 검색 버튼 자리가 그대로 입력 칸으로 넓어진다.

2. **[고래밥] 입력 칸을 접어도 입력한 검색어는 유지한다.**
   - 검색어를 남겨 둔 채 칸만 접어 툴바 공간을 확보할 수 있게 한다. 검색어가 남아 있으면 검색 도구 버튼에 활성 표시(채운 아이콘과 모서리 점)를 유지한다.

3. **[고래밥] 검색 칸은 닫기 버튼이나 `Esc` 키로만 접고, 접으면 초점을 검색 도구 버튼으로 돌려보낸다.**
   - 바깥 영역을 클릭했다고 입력 칸이 저절로 접히면 목록을 확인하며 검색어를 고치기 불편하다. 키보드 사용자가 `Esc`로 칸을 접었을 때 초점을 잃지 않도록 원래 도구 버튼으로 초점을 되돌린다.

## 필터 구성과 조건 결합

1. **[관례] 필터 속성은 도메인에 중요한 것을 구체적인 이름으로 붙이고, 일반적인 것에서 전문적인 것 순서로 둔다.**
   - [NN/g의 패싯·필터 지침](https://www.nngroup.com/articles/filter-categories-values/)([Filters vs facets](https://www.nngroup.com/articles/filters-vs-facets/))에 따라 사용자가 자주 찾는 핵심 속성을 앞에 두고, 모호한 묶음 이름 대신 구체적인 속성 이름을 쓴다.

2. **[관례] [고래밥] 같은 속성 안의 여러 값은 OR로 묶고, 서로 다른 속성끼리는 AND로 묶는다. 속성 사이의 OR는 고급 모드에서만 다룬다.**
   - 예를 들어 상태를 `진행 중`과 `검토 중` 두 개 고르면 둘 중 하나에 해당하는 항목을 보이고(OR), 여기에 담당자 `지우`를 추가하면 그중 담당자가 지우인 항목만 남긴다(AND).
   - [Linear 필터](https://linear.app/docs/filters)는 `F` 단축키, `is`·`is not`·`any`·`all` 연산자, 고급 AND/OR 중첩을 제공하고, GitHub는 쿼리 문법에서 공백을 AND, 쉼표를 OR로 처리한다. 기본 필터 메뉴에서 연산자와 중첩 조건을 바로 노출하면 일반 목록 탐색이 복잡해지므로, 기본 조합은 값 다중 선택(같은 속성 OR, 다른 속성 AND)으로 고정하고 속성 간 OR가 꼭 필요한 화면에서만 고급 모드로 분리한다.

3. **[관례] [고래밥] 선택지가 많으면 목록 안에 검색을 두고, 처음에는 상위 8개와 이미 고른 항목만 보인다.**
   - 담당자·라벨처럼 선택지가 길어지는 속성은 필터 메뉴 안에 검색 칸을 둔다. 검색 전에는 처음 8개와 현재 선택된 값만 먼저 보여 주고, 검색어를 입력하면 최대 50개까지 결과를 보여 준다.

## 적용 상태 표시: 칩 줄과 표시 점

1. **[관례] [고래밥] 필터를 적용하면 툴바 아래에 적용 칩 줄을 만들고, 칩마다 바꾸기·지우기와 줄 끝에 모두 지우기를 둔다.**
   - Linear의 문장형 칩(`"Assignee is …"`)과 Plane의 적용 필터 행처럼, 현재 목록이 어떤 조건으로 걸러졌는지 본문 바로 위에서 읽히게 한다.
   - 각 칩을 누르면 해당 속성의 값을 바로 바꿀 수 있고, 칩의 지우기 버튼으로 그 조건만 빼거나 줄 끝의 **모두 지우기**로 전체 필터를 한 번에 해제한다. 조건에 맞는 항목이 하나도 없을 때는 [상태와 피드백](/app-shell/states-and-feedback/)의 '결과 없음' 빈 상태에서도 조건 지우기 행동을 함께 제공한다.

2. **[관례] [고래밥] 표시 옵션만 바꾼 경우에는 적용 칩 줄을 만들지 않는다.**
   - 정렬 기준, 그룹 묶기, 레이아웃, 행에 보일 속성을 기본값과 다르게 바꿨을 때는 칩 줄을 추가하지 않고 표시 도구 버튼에 "기본과 다름"을 뜻하는 모서리 점만 찍는다. 원래대로 돌리는 **초기화** 동작은 표시 메뉴 안에 둔다.
   - 필터는 목록에서 일부 항목을 숨기므로 적용 사실을 눈에 띄게 알려야 누락 오해를 막을 수 있지만, 표시는 같은 항목의 배열과 노출 속성만 바꾸므로 별도 줄로 본문 세로 공간을 쓰지 않는다.

## 주소에 남기기와 방문 기록

1. **[관례] [고래밥] 검색어·필터·표시 상태는 모두 주소(URL 쿼리)에 남긴다.**
   - [Linear](https://linear.app/docs/filters)와 GitHub가 필터·쿼리를 URL에 반영하듯, 검색어와 필터 조건뿐 아니라 표시 옵션까지 주소에 둔다. 새로고침하거나 뒤로가기로 돌아오거나 동료에게 링크를 공유했을 때 똑같은 목록과 배열 상태가 열려야 한다.
   - 목록에서 [미리보기 패널](/app-shell/peek/)(`?peek=대상ID`)을 열 때도 기존 검색·필터·표시 쿼리는 그대로 유지한다.

2. **[고래밥] 검색어를 입력하는 중이거나 필터·표시 값을 바꾸는 동안에는 방문 기록을 새로 쌓지 않고 바꾼다(`replace`).**
   - 글자를 칠 때마다, 혹은 체크박스를 누를 때마다 기록을 쌓으면(`push`) 뒤로가기를 눌렀을 때 이전 페이지로 나가지 못하고 직전 글자나 조건을 하나씩 되감게 된다. 목록 안에서의 조건 변경은 현재 주소를 덮어쓰고(`replace`), 다른 페이지나 첫 미리보기 진입처럼 화면 전환이 일어날 때만 기록을 쌓는다.

## 좁은 화면(휴대폰)에서의 동작

1. **[관례] [고래밥] 휴대폰 폭(1024px 미만)에서 필터는 두 단계 바텀시트(속성 → 값)로 연다.**
   - 데스크톱에서 팝오버로 열리던 필터와 표시 메뉴는 좁은 화면에서 바텀시트로 전환한다([NN/g: Bottom sheets](https://www.nngroup.com/articles/bottom-sheet/), [적응형](/app-shell/adaptive/)).
   - 필터 시트는 첫 단계에서 걸러낼 속성을 고르고, 두 번째 단계에서 그 속성의 값을 고르는 두 단계 구조로 연다. 시트 위에 또 다른 시트를 겹쳐 쌓지 않고 한 시트 안에서 단계를 전환한다.

2. **[고래밥] 휴대폰에서 적용 칩 줄은 가로로 넘기는 한 줄로 둔다.**
   - 적용된 필터 칩이 여러 개일 때 여러 줄로 줄바꿈하면 작은 화면에서 목록 본문이 아래로 밀려난다. 한 줄 높이를 유지하고 가로 스크롤로 넘겨 보게 한다.

3. **[고래밥] 필터·표시 바텀시트의 열림 상태는 주소에 넣지 않고 닫기 요청(`CloseWatcher`)과 닫기 버튼으로 닫는다.**
   - 시트를 열었다고 쿼리를 바꾸면 짧은 조작마다 기록이 쌓이고 새로고침할 때 시트가 다시 열린다. 안드로이드 뒤로가기와 `Esc`는 브라우저의 [CloseWatcher](https://developer.mozilla.org/en-US/docs/Web/API/CloseWatcher)로 받아 시트만 닫는다.
   - `CloseWatcher`를 지원하지 않는 브라우저(현재 iOS 사파리 등)에서는 뒤로가기가 이전 페이지로 이동할 수 있으므로, 끌어서 닫기에만 의존하지 않고 시트마다 눈에 보이는 닫기 버튼을 함께 둔다.

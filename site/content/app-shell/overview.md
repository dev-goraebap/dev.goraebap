로그인 뒤 사이드바(탐색)와 콘텐츠 영역으로 이루어진 업무 도구(Linear·Plane 같은 SaaS 앱)를 만들거나 검토할 때 따르는 규칙집이다. 개발자가 화면을 설계·검토할 때 판단 기준으로 삼고, AI 에이전트가 페이지를 만들기 전에 읽고 그대로 결정하도록 썼다. 랜딩 페이지나 문서 사이트는 [화면 유형 고르기](/start/choose-surface/)와 [랜딩](/landing/) 규칙집이 맡는다.

규칙은 특정 UI 라이브러리나 부품 이름이 아니라 화면에서의 **역할**(셸, 머리 줄, 도구 자리, 본문 열)로 정의한다. 기술 스택을 바꾸더라도 본문 규칙은 그대로 유지하고 [구현 메모](/app-shell/astryx-notes/)만 바꾼다.

## 앱 셸의 기본 구조와 지향점

앱 셸은 왼쪽 사이드바(탐색)와 오른쪽 콘텐츠 영역 두 부분으로 나뉜다. 셸은 페이지마다 새로 만들지 않고 한 곳에서 고정하며, 페이지 안에서도 머리 줄과 툴바는 고정한 채 본문만 스크롤한다.

Linear 리디자인 글에서 설명하듯 사이드바와 상단 머리 줄이 "뒤집힌 L자" 프레임이 되어 본문을 감싸고, 사이드바가 한 단계 뒤로 물러나 본문이 시각의 중심이 되게 한다([Linear: How we redesigned the Linear UI](https://linear.app/now/how-we-redesigned-the-linear-ui), [Linear: Behind the latest design refresh](https://linear.app/now/behind-the-latest-design-refresh)). 지향하는 화면 인상은 Linear처럼 "높은 밀도를 압도적이지 않게" 보여주는 것이다. 다만 Linear 실제 화면의 사이드바 폭·행 높이·모달 크기 같은 구체적인 px 수치는 공개 자료에 없어 미확인 상태다.

## 규칙의 성격 표시

각 규칙 앞에는 근거와 변경 기준을 나타내는 표시를 붙인다. 자세한 기준은 [읽는 법](/start/how-to-read/)과 [결정 기록](/start/decisions/)에서 다룬다.

| 표시 | 의미 | 바꾸는 시점 |
| --- | --- | --- |
| `[관례]` | 여러 제품(Linear, Plane)과 디자인 지침(Primer, Atlassian, Apple HIG, Android, Carbon, NN/g)이 같은 쪽으로 수렴한 규칙. 근거 링크가 있다 | 근거가 바뀌었을 때 |
| `[고래밥]` | 뚜렷한 관례가 없거나 관례와 다르게 정한 자체 결정. 결정 이유를 함께 적는다 | 이유가 더 이상 맞지 않을 때 |
| `[선호]` | 기능 규칙이 아니라 사용자 취향으로 정한 시각적 모양 | 취향이 바뀌면 자유롭게 |

## 핵심 원칙

이 규칙집의 세부 판단을 관통하는 세 가지 원칙이다.

1. **모든 의미 있는 상태는 주소를 가진다** `[고래밥]`
   페이지와 뷰 탭뿐 아니라 검색어·필터·표시 조건, 목록 위에 띄운 작성·수정 대화상자(라우트 마스킹), 목록 옆에 여는 미리보기 패널(`?peek=`)까지 모두 URL 경로 또는 쿼리에 남긴다. 새로고침, 링크 공유, 휴대폰의 뒤로가기 제스처가 언제나 같은 상태를 가리키게 하기 위해서다.
2. **무엇을 대화상자로 열고 무엇을 페이지로 열지는 판단표로 정한다** `[고래밥]`
   화면을 만들 때 가장 자주 흔들리는 결정이므로 임의로 고르지 않고 질문 순서에 따라 결정한다. 값 하나만 바꾸면 팝오버·바텀시트, 되돌릴 수 없는 결정은 확인 창, 공유할 일 없는 짧은 입력은 대화상자, 목록을 보며 연달아 훑으면 미리보기 패널, 짧게 끝내되 주소와 공유가 의미 있으면 라우트 마스킹, 오래 머물거나 외부 공유가 목적이면 자기 페이지로 연다.
3. **적응형 분기점은 하나로 통일한다** `[관례]` / **기준 폭은 1024px(64rem)이다** `[고래밥]`
   반응형이 같은 화면을 좁히는 것이라면, 적응형은 같은 주소와 데이터를 기기에 맞는 다른 부품으로 보여주는 것이다. 사이드바↔하단 탭, 팝오버↔바텀시트, 대화상자↔전체 화면 페이지, 표↔행 목록 전환이 모두 한 분기점(1024px)에서 함께 일어난다. Linear와 Plane은 웹의 휴대폰 화면을 따로 설계하지 않았기 때문에(Linear 리디자인 글은 데스크톱만 다루고 하단 탭은 2025년 10월 네이티브 앱에만 도입했으며, Plane은 768px 미만에서 사이드바를 접고 미리보기 대신 페이지로 이동함), 웹 적응형 규칙은 대부분 자체 결정(`[고래밥]`)이다.

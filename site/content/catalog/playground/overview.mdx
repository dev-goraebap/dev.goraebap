Playground는 기능 하나를 작은 앱 하나로 묶은 실행 견본 모음입니다. 목록·상세·작성처럼 화면 종류로만 나누면 견본 안에서 눌러 이동할 때 서로 겹치므로, 앱마다 느낌이 확실히 다른 화면을 다루고 같은 모양의 화면은 한 앱에서만 다룹니다(예: 표는 사용자 관리, 카드는 문서함).

새 기능을 만들 때는 아래 목록에서 만들 기능과 가장 비슷한 앱을 찾아 화면 구조와 부품 조합을 본뜹니다. Playground에 없는 기능도 성격이 가까운 앱을 찾아 본떠 만들 수 있고, 기존 앱과 느낌이 다른 화면이 필요할 때는 새 Playground를 보태 이 워크플로에 기여할 수 있습니다.

## 셸 배치 전환

Inset과 Split 배치마다 견본을 따로 두지 않습니다. 가이드 머리 줄 오른쪽(테마 단추 옆)의 배치 전환으로 바꾸면 가이드 자신과 문서 안의 모든 앱 견본이 같은 배치로 바뀝니다(휴대폰에는 사이드바가 없어 전환이 없습니다). 견본 앱은 `site/samples/catalog/shell-layout.ts`의 `useShellLayout()`을 `PlaygroundFrame`의 `layout`에 넘깁니다. `PlaygroundFrame`은 사이트 공통 브랜드(`WorkflowBrand`)와 견본용 기본 사이드바 폭(224px, 키트 `AppFrame`의 기본값은 340px 유지)을 적용하며, 해당 견본이 소개하는 기능 밖의 작업 공간 메뉴는 비활성 목데이터로 둡니다. 데스크톱 견본 iframe은 분기점(1024px)보다 넓은 1280px로 그립니다.

## 새 Playground 보태기

이미 있는 앱과 같은 모양의 화면은 새 앱으로 만들지 않고, 느낌이 다른 화면만 보탭니다. 새 Playground를 보탤 때는 다음 네 가지를 함께 만듭니다.

1. 앱 폴더 `site/samples/playground/<앱>/`: 메모리 라우터와 모의 데이터를 두고, 키트 부품을 `@/shared/ui/…`로 가져와 구성합니다.
2. 견본 파일 `site/samples/playground/<이름>.samples.tsx`: 묶음 id를 `playground-<이름>`으로 정하고, 파일 첫 주석에 이 앱이 무엇을 만들 때 본뜨는지 적습니다.
3. 테스트 파일 `<이름>.test.tsx`: 핵심 조작과 휴대폰 동작을 검증합니다.
4. 가이드 페이지 `site/content/catalog/playground/<이름>.mdx`: 앱이 무엇을 만들 때 본뜨는지와 다루는 화면을 소개하고 견본 묶음과 구현 코드를 연결합니다.

모든 견본은 `npm run site:test`를 실행할 때 데스크톱과 휴대폰에서 정상으로 그려지는지 자동으로 검사됩니다.

Webcraft 프로젝트는 어디를 열어도 같은 자리에 같은 종류의 코드가 있어요. 그래서 처음 보는 기능도 어디부터 읽을지 바로 알 수 있고, 에이전트도 새 코드를 어디에 둘지 헤매지 않아요. 이 장은 저장소 루트의 모양을 설명해요.

## 저장소 하나에 제품 하나

프론트엔드와 백엔드를 한 저장소의 두 폴더로 둬요. 왜 하나로 두는지는 [그래도 저장소는 하나예요](/web/project/monorepo/)에 있어요. 아래는 cowork 저장소의 루트예요.

<FileTree>
- cowork/
  - web/ 프론트엔드(React)
    - src/
    - package.json
    - vite.config.ts
  - server/ 백엔드(Spring Boot)
    - src/
    - build.gradle
    - openapi.json 서버가 만든 API 계약
  - scripts/
    - wait-for-server.mjs 서버가 뜬 뒤에 화면을 띄우게 기다리기
  - AGENTS.md 에이전트가 읽는 프로젝트 안내
  - CLAUDE.md `@AGENTS.md` 한 줄
  - Dockerfile 서버와 화면을 이미지 하나로 빌드
  - dev.sh 개발할 때 서버와 화면을 띄우기
  - README.md
</FileTree>

## AGENTS.md와 CLAUDE.md

`AGENTS.md`는 에이전트가 이 프로젝트에서 일할 때 먼저 읽는 안내예요. Codex는 이 파일을 바로 읽고, Claude Code는 `CLAUDE.md`의 `@AGENTS.md` 한 줄을 거쳐 같은 파일을 읽어요. 그래서 안내의 원본은 `AGENTS.md` 하나예요.

cowork의 `AGENTS.md`에는 이런 것이 들어 있어요.

| 절 | 내용 |
| :--- | :--- |
| 구성 | `server/`와 `web/`이 무엇으로 되어 있는지, 모듈과 키트를 어디에 두는지 |
| 개발 지침 | 이 프로젝트가 Webcraft 지침을 따른다는 것과, 작업할 때 함께 읽을 지침 |
| 프로젝트 규칙 | Webcraft 지침과 다르게 정한 것과 그 이유 |
| 실행과 검증 | `sh dev.sh`, 서버와 화면을 바꾼 뒤 돌릴 검사 명령 |

Webcraft 지침을 그대로 베껴 두지 않고, 이 프로젝트만의 예외만 적어요.

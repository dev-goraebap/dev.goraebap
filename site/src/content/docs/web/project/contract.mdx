화면과 서버는 HTTP로만 이야기하므로, 무엇을 주고받는지를 둘 사이의 계약으로 정해요. 계약의 원본은 서버예요. 서버가 OpenAPI 문서를 만들고, 화면은 그 문서에서 TypeScript 타입을 생성해 써요. API를 바꾸면 계약 파일, 생성한 타입, 그 API를 부르는 화면 코드를 같은 변경에서 맞춰요.

## 계약을 맞추는 순서

<Steps>

1. 서버의 컨트롤러와 요청·응답 타입(`…Requests`, `…Views`)을 고쳐요. 서버는 springdoc으로 `/api/openapi`에서 OpenAPI 문서를 내보내요.

2. `server/`에서 계약 파일을 다시 써요. 이 작업은 테스트로 서버를 띄워 `/api/openapi`를 읽고 `server/openapi.json`에 저장해요.

   ```bash
   ./gradlew exportOpenApi
   ```

3. `web/`에서 타입을 생성해요. openapi-typescript가 `../server/openapi.json`을 읽어 `web/src/shared/api/schema.d.ts`를 만들어요. 이 파일은 손으로 고치지 않아요.

   ```bash
   npm run api:generate
   ```

4. `web/`에서 `npm run check`를 실행해요. 화면 코드가 바뀐 계약과 맞지 않으면 타입 검사(`tsc --noEmit`)에서 실패해요.

</Steps>

## 화면 코드가 생성한 타입을 쓰는 방식

생성한 타입은 `@/shared/api`가 다시 내보내요. 화면 코드는 HTTP 도우미(`getJson`, `sendJson` 등)와 타입을 이곳에서만 가져와요.

```ts title="web/src/shared/api/index.ts"
export { ApiError,  getJson, isNotFound, sendCommand, sendCreate, sendJson } from './http';
export type { components,  } from './schema';
```

조회를 소유한 슬라이스는 `components['schemas']`에서 응답 타입을 꺼내 화면에 맞게 다듬어요. 아래는 프로젝트 조회의 예예요. 서버가 늘 채워 주는 필드를 필수로 바꾸고, 서버가 판정한 `can`을 함께 실어요.

```ts title="web/src/entities/project/api/projects.ts" {9,19-20}
import { queryOptions, type QueryClient } from '@tanstack/react-query';
import { getJson, sendCommand, sendCreate, type components } from '@/shared/api';

/*
 * Projects' reads and writes against /api/v1/workspace/projects, as client/'s. Every read sits under ['projects'], so a change
 * made here reads them all again. A project's key in a path is its current key or an old one, in any case.
 */

type Schemas = components['schemas'];
type WithRequired<T, K extends keyof T> = T & { [P in K]-?: NonNullable<T[P]> };

// …

/**
 * A project as the screens list and open it, with its member count, whether it is the reader's favourite, and the
 * reader's role and what it lets them do. Only projects the reader sees are listed (their members' and every one for a
 * Workspace administrator).
 */
export type Project = WithRequired<Schemas['ProjectView'], 'id' | 'key' | 'name' | 'position' | 'version' | 'memberCount' | 'favorite' | 'createdAt' | 'updatedAt'>
  & { myRole: ProjectRole | 'NONE'; can: ProjectCan };
```

## 오류도 계약이에요

실패한 요청은 `application/problem+json`으로 돌아와요. 화면은 응답의 `code`로 오류를 구별하고, 업무 오류면 서버가 쓴 `detail`을 그대로 보여 줘요. 상태 코드와 오류 응답의 모양은 [API 계약과 오류](/web/backend/api/)에 있어요.

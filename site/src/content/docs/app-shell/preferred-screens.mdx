새 업무 화면을 만들거나 기존 화면의 인상을 검토할 때 출발점으로 삼는 기준 화면을 정의한다. 다른 페이지의 `[관례]`나 `[고래밥]` 항목이 사유와 근거가 있는 기능·배치 규칙이라면, 이 페이지의 항목은 "이런 모양으로 그린다"는 시각적 취향(`[선호]`)이다. 에이전트와 개발자는 특별한 이유가 없을 때 이 기준 화면에서 출발하고, 제품 성격이나 취향이 바뀌면 기능 계약을 해치지 않는 선에서 자유롭게 바꾼다.

구체적인 레이아웃 수치와 상호작용 계약은 각 규칙 페이지에서 다루고, 실제 컴포넌트 연결은 [구현 메모](/app-shell/astryx-notes/)에 따로 적는다. 이 페이지의 기준 화면들은 저장소의 `frontend` 폴더에서 `npm run patterns`를 실행해 Storybook 키트의 서가 예제로 확인할 수 있다.

## 규칙과 선호의 구분

화면을 구성하는 요소마다 적용하는 성격 표시가 다르다. 자세한 구분 기준은 [읽는 법](/start/how-to-read/)과 [앱 셸 개요](/app-shell/overview/)를 따른다.

| 표시 | 의미 | 변경 기준 |
| --- | --- | --- |
| `[관례]` | 여러 제품과 디자인 지침이 수렴한 규칙 | 근거가 바뀌었을 때 |
| `[고래밥]` | 관례가 없거나 관례와 다르게 정한 자체 결정 | 결정 이유가 더 이상 맞지 않을 때 |
| `[선호]` | 기능 규칙이 아니라 취향으로 정한 시각적 모양 | 취향이 바뀌면 자유롭게 |

## 전체 틀과 색·면의 인상

앱 셸은 본문이 시각의 중심이 되도록 바탕과 주변 요소를 한 단계 누그러뜨린다. 차분한 회색 바탕과 본문 중심 대비는 Linear 리디자인 문서에서 방향을 참고했으나, Linear 실제 화면의 사이드바 폭·행 높이·모달 크기 같은 구체적인 px 수치는 공개 자료에 없어 미확인 상태다.

- **Inset 셸을 기본으로 삼는다** `[선호]`
  사이드바와 본문을 선으로만 나누는 Split 배치도 제공하지만, 기본 출발점은 옅은 바탕 위에 **16px 둥근 모서리의 페이지 카드**를 띄우는 Inset 셸이다. 사이드바 머리와 페이지 머리 줄의 높이를 같게 맞춘다(머리 줄 52px, 툴바 44px). 자세한 구조는 [셸과 사이드바](/app-shell/shell-and-sidebar/)를 따른다.
- **먹색 강조와 따뜻한 회색 4단계 면을 쓴다** `[선호]`
  강조색은 별도의 브랜드 색이 아니라 본문 글자와 같은 **먹색**이다. 바탕은 **따뜻한 회색** 계열로 맞추고, 깊이는 **4단계 면**(바닥·페이지·카드·떠 있는 면)과 **2단계 선**(내부선·바깥 경계)으로 나눈다. 자세한 기준은 [시각 위계](/common/visual-hierarchy/)에서 다룬다.
- **선과 채움으로 상태를 드러내는 한 세트의 아이콘을 쓴다** `[선호]`
  기본 상태는 선 아이콘으로 그리고, 선택된 상태나 현재 위치는 채운 아이콘으로 바꾼다. 자세한 기준은 [아이콘](/common/icons/)에서 다룬다.

## 머리 줄과 도구 자리

페이지 상단의 뷰 선택과 목록 조작 도구는 형태와 간격으로 역할을 구분한다. 배치 규칙은 [머리 줄과 툴바](/app-shell/header-and-toolbar/)와 [검색·필터·표시](/app-shell/filters-and-display/)를 따른다.

- **뷰는 알약 버튼, 도구는 둥근 아이콘 버튼 셋으로 묶는다** `[선호]`
  툴바 왼쪽의 뷰·탭은 알약 모양 버튼으로 둔다. 도구 자리에는 **검색·필터·표시** 세 가지 둥근 버튼을 같은 좁은 간격으로 묶고, 그보다 넓은 간격 뒤에 **만들기 버튼**을 둔다(`[고래밥]` 순서 규칙).
- **켜진 도구는 채운 아이콘과 모서리 점으로 표시한다** `[선호]`
  검색어나 필터, 기본과 다른 표시 조건이 적용된 도구 버튼은 선 아이콘을 **채운 아이콘**으로 바꾸고 버튼 모서리에 점을 찍는다.
- **검색 버튼은 그 자리에서 입력 칸으로 펼쳐진다** `[선호]`
  검색은 처음에 둥근 버튼으로 두었다가 누르면 그 자리에서 입력 칸으로 넓어진다. 입력 칸을 다시 닫아도 입력해 둔 검색어는 지워지지 않고 남는다.

## 목록·상세·작성 화면의 생김새

화면이 담는 작업의 성격(훑기, 읽기, 쓰기)에 따라 바탕 질감과 속성 배치를 다르게 가져간다. 폭 기준과 열 구성은 [콘텐츠 폭](/app-shell/content-width/)과 [목록·표·보드](/app-shell/collections/)를 따른다.

| 화면 | 바탕과 틀 | 제목·본문·속성 배치 |
| --- | --- | --- |
| 일반 목록 | 옅은 점 무늬 바탕 `[선호]` | 본문 전체 폭을 쓰며 항목을 카드로 감싸지 않는다 `[관례]`. 데이터가 없을 때는 현재 테마 색으로 칠한 **펜 선 풍경 그림**과 다음 행동 하나를 둔다 `[선호]` |
| 상세 화면 | 무늬 없는 평평한 바탕 `[선호]` | 최대 약 720px 읽기 열과 오른쪽 속성 열(약 256px)을 나란히 둔다 `[관례]`. 대화상자·패널·좁은 창에서 영역 실제 폭이 좁아지면 같은 속성들이 제목 아래의 **알약 줄**로 옮겨 간다 `[고래밥]` `[선호]` |
| 작성 양식 ("종이") | 무늬 없는 평평한 바탕 `[선호]` | 입력 칸 테두리가 없는 큰 제목, 서식 막대 없는 본문 영역, 그 아래의 **속성 알약 줄**로 구성한다. 값이 비어 있는 속성 알약은 아이콘과 이름을 함께 보이고, 필수 항목에는 `*`를 붙인다 `[선호]` |

빈 상태의 세 가지 구분(처음·결과 없음·오류)과 제출 시 필수 항목 검증 규칙은 [상태와 피드백](/app-shell/states-and-feedback/)을 따르고, 데스크톱 목록 위에서 작성 양식을 대화상자로 열되 주소를 유지하는 방식은 [라우트 마스킹](/app-shell/route-masking/)을 따른다.

## 휴대폰 화면

1024px(64rem) 미만 폭에서는 데스크톱과 같은 주소·데이터를 휴대폰에 맞는 부품으로 바꾸어 그린다. 세부 동작과 뒤로가기 처리는 [적응형](/app-shell/adaptive/)에서 다룬다.

- **목록과 주 탐색 화면**: 화면 바닥에 **하단 탭 4칸과 더보기**를 고정하고(`[고래밥]`), 하단 탭 위에 떠 있는 **만들기 버튼(FAB)**을 둔다(`[관례]`, `[선호]`).
- **상세와 작성 화면**: 내용에 집중하고 화면 높이와 키보드 공간을 확보하기 위해 하단 탭과 만들기 FAB를 치우고, 상단의 뒤로가기(`← 이름`)와 바닥 동작 줄만 갖춘 **탭 없는 전체 화면**으로 연다(`[고래밥]`, `[선호]`).

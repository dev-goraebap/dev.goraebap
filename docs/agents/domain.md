# 도메인 문서

엔지니어링 스킬이 코드베이스를 살필 때 이 저장소의 도메인 문서를 읽는 방법입니다.

## 살피기 전에 읽을 것

- **`GLOSSARY.md`**: 저장소 루트의 용어집입니다.
- **`docs/adr/`**: 작업할 영역에 닿는 ADR을 읽습니다.

파일이 없으면 **조용히 넘어갑니다**. 없다고 알리거나 미리 만들자고 제안하지 않습니다. `/domain-modeling` 스킬(`/grill-with-docs`, `/improve-codebase-architecture`에서 이어짐)이 용어나 결정이 실제로 정해질 때 만듭니다.

## 파일 구조

단일 문맥입니다.

```
/
├── GLOSSARY.md
├── docs/adr/
│   ├── 0001-event-sourced-orders.md
│   └── 0002-postgres-for-write-model.md
├── .agents/skills/
├── server/
└── web/
```

## 용어집의 말을 쓴다

결과물(이슈 제목, 리팩터링 제안, 가설, 테스트 이름)에서 도메인 개념을 부를 때는 `GLOSSARY.md`에 정의된 말을 씁니다. 용어집이 피하라고 한 동의어로 바꾸지 않습니다.

필요한 개념이 용어집에 없으면 신호로 봅니다. 프로젝트가 쓰지 않는 말을 지어내고 있거나(다시 생각합니다), 실제로 빠진 용어입니다(`/domain-modeling`에 넘길 것으로 적어 둡니다).

## ADR과 어긋나면 드러낸다

결과물이 기존 ADR과 어긋나면 조용히 덮어쓰지 말고 드러내 알립니다.

> _ADR-0007(이벤트 소싱 주문)과 어긋나지만, … 때문에 다시 열 만합니다._

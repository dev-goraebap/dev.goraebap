# 프론트엔드 카탈로그

Storybook에서 Astryx 기반 부품과 화면 패턴을 읽고 조작한다. 별도 예제 앱이나 개발 서버를 두지 않는다.

## 실행과 검증

저장소 루트에서 `npm ci` 후 `npm run patterns`로 Storybook(4431)을 연다. `npm run patterns:check`는 타입, `npm run patterns:test`는 상호작용, `npm run patterns:build`는 정적 내보내기를 검사한다.

## 구성

| 위치 | 관리하는 내용 |
| --- | --- |
| `.storybook` | 테마 제공자, 화면 크기, 문서·접근성·검증 설정 |
| `src/foundations` | 테마 연결, Solar 아이콘, 공통 스타일과 크기 |
| `src/components/primitives` | Astryx 기본 부품을 직접 사용하는 견본 |
| `src/components/composites` | 검색, 메뉴, 공통 다이얼로그, 에디터와 빈 상태 |
| `src/patterns` | 생성 양식, 라우트 마스킹과 상호작용 조합 |
| `src/layouts` | Split·Inset, 공통 페이지와 상세 배치 |
| `src/examples/library` | 부품을 조합한 서가의 목록·상세·생성 화면과 모의 응답 |

사용 기준은 `skills/design-system/references`의 Markdown이 원본이다. MDX는 해당 글을 가져오고 코드와 Story를 연결한다. 프로젝트로 제공하는 레퍼런스 구현과 기본 시나리오는 `skills/design-system/assets/workspace`에 한 번만 두고, 카탈로그의 진입 파일에서 가져온다. Astryx 기본 부품 자체를 다시 구현하지 않는다.

서가 예제의 화면 파일 구조는 공식 FSD 지침에 맡긴다. 카탈로그는 자체 FSD 설명이나 경계 검사기를 제공하지 않는다.

## 확인할 동작

탐색 순서는 디자인 기초·기본 부품·조합 부품·레이아웃·사용 패턴·화면 예제다. 테마와 아이콘은 디자인 기초 안의 별도 항목이다.

라이트·다크와 화면 크기는 상단 도구 모음에서 바꾼다. 모드별 메뉴와 예제 내부의 별도 테마 전환을 두지 않는다. 컴포넌트는 상태별로, 패턴은 동작별로, 예제는 화면 전체의 조합으로 확인한다. 각 Story의 모의 응답·QueryClient·메모리 라우터는 독립적이며 실제 계정이나 서버를 변경하지 않는다.

데스크톱 예제에서는 목록 위에 상세·생성 다이얼로그를 열고 페이지로 확장한다. 모바일과 직접 진입 시나리오는 페이지로 연다. 제목·본문 초안은 확장 뒤에도 남는다. 검색·필터·보기·정렬은 예제 라우터의 URL 상태가 소유한다. Storybook의 브라우저 주소와 예제의 메모리 주소는 별개이므로 실제 서비스의 새로고침·직접 링크는 채택한 프로젝트에서 추가 검증한다.

검색 닫기는 조건을 유지하고 검색어 지우기는 별도 동작이다. 보기·정렬 변경은 표시 메뉴에서 초기화하며 필터 적용 줄은 실제 필터에만 사용한다. 모바일 메뉴는 바텀시트로 열리고, 목록의 생성 FAB 아래로 마지막 항목이 가려지지 않게 스크롤 여백을 둔다.

등록·즐겨찾기는 Story의 메모리에만 보관한다. 바이너리 업로드·계정·서버 동기화는 제공하지 않는다. 자동 검증은 이름에 ‘검증’을 붙여 대표 화면과 구분한다.

기본 부품은 중앙 배치하고 크기·변형·상태를 비교한다. 문서의 작은 견본은 180px부터 시작하며, 메뉴·다이얼로그·빈 상태는 조작에 필요한 높이를 둔다. 레이아웃과 화면 예제는 전체 화면을 유지한다. 다이얼로그 조합은 열기 버튼만 배치하고 배경 앱 화면을 덧붙이지 않는다.

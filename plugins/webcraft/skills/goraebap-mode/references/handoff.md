# 이어받기 문서

설치된 Webcraft 플러그인 판이 프로젝트 AGENTS.md의 최소 판보다 낮거나, 세션 중에 플러그인이 갱신돼 지침이 맞지 않거나, 필요한 지침을 읽을 수 없을 때는 추측으로 진행하지 않습니다. 지금까지의 작업 상태를 이어받기 문서로 남기고 플러그인 설치·갱신 방법과 새 세션에서 읽을 문서 경로를 사용자에게 알립니다.

세션 시작 훅이 새 판을 알려 첫 요청 전에 갱신을 제안할 때는, 진행 중인 작업이 없으면 사용자 동의를 받아 갱신 명령을 실행하고 `/reload-plugins`를 안내합니다. 작업을 시작한 뒤에 갱신이 필요해지면 이어받기 문서를 먼저 남깁니다.

## 위치와 담는 내용

저장소를 더럽히지 않고 커밋에 섞이지 않도록 저장소 밖 `~/.goraebap/handoff/<YYYY-MM-DD>-<프로젝트 폴더 이름>-<짧은 영문 이름>.md`에 만듭니다. 비밀값과 접속 정보는 넣지 않습니다.

| 항목 | 적는 내용 |
| --- | --- |
| 사용자가 원한 결과 | 요청의 목적과 완료 기준 |
| 결정과 기각한 안 | 사용자가 내린 결정, 검토했다가 기각한 안과 이유 |
| 바꾼 파일 | 지금까지 고치거나 만든 파일 경로와 커밋 여부 |
| 다음 단계 | 바로 이어서 해야 할 작업 순서 |
| 검증 상태 | 수행한 검증과 아직 못 한 검증 |
| 묻지 못한 질문 | 사용자 확인이 남은 질문 |

## 사용자 안내와 갱신

문서를 남긴 뒤 사용자에게 할 일을 짧게 안내합니다.

1. 플러그인 갱신 명령(Claude Code는 `claude plugin marketplace update dev-goraebap`과 `claude plugin update webcraft@dev-goraebap`, Codex는 `codex plugin marketplace upgrade dev-goraebap`)을 안내하거나, 사용자가 `"Webcraft 업데이트해 줘"`라고 요청하면 에이전트가 직접 실행합니다.
2. 새 판을 적용하는 `/reload-plugins` 입력 또는 새 세션 시작을 안내합니다.
3. 새 세션에 붙여 넣을 한 문장(`"~/.goraebap/handoff/<파일 이름>.md를 읽고 이어서 진행해 줘"`)을 함께 전달합니다.

## 새 세션에서 이어받기

이어받기 문서를 전달받은 새 세션은 문서를 읽고 지금 저장소 상태(`git status`)와 대조한 뒤 다음 단계부터 이어서 진행합니다. 작업을 모두 이어받으면 이어받기 문서를 지워도 된다고 사용자에게 알립니다.

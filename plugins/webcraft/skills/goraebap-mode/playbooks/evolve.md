# 지침 개선

1. 실제 실패나 사용자 피드백을 근거로 빠진 규칙·잘못된 도구·놓친 검증 중 원인을 찾습니다. 한 사례를 모든 프로젝트의 절대 규칙으로 만들지 않습니다.
2. 다음 변경이 이 프로젝트만의 결정인지, 여러 프로젝트에 맞는 공통 개선인지 구분합니다. 당장 구분할 수 없으면 이 프로젝트의 결정으로 먼저 둡니다.
3. 이 프로젝트만의 결정은 프로젝트 AGENTS.md의 프로젝트 규칙 표에 이유와 함께 적습니다([프로젝트 규칙](../../manage-workflow/references/project-rules.md)). 경고를 늘리기 전에 자동 검사나 구조로 실수를 막을 수 있는지 검토합니다.
4. 같은 상황에서 결과가 달라지는지 확인합니다. 경미한 문구 수정에 불필요한 전체 앱 검사를 요구하지 않습니다.
5. 공통 개선은 [지침 제안](../../manage-workflow/references/proposals.md)에 따라 일반화한 이슈 본문 초안을 사용자에게 보이고 승인을 받아 Webcraft 원본 저장소(`dev-goraebap/dev.goraebap`)의 이슈로 올립니다. 프로젝트 규칙 표에는 이슈 번호나 제안 표시 없이 지속 규칙 한 줄만 남깁니다. 원본은 원본 저장소 세션에서 제안 이슈를 검토해 [글쓰기 기준](../references/writing.md)에 따라 고칩니다.
6. 플러그인이 갱신되면 닫힌 이슈를 보고 프로젝트 규칙 표의 같은 줄을 지우거나 예외로 남깁니다.

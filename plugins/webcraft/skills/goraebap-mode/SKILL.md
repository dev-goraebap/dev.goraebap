# 웹 플랫폼 작업 방식

프로젝트가 채택한 개발 방식입니다. 현재 프로젝트의 AGENTS.md를 먼저 읽습니다. AGENTS.md의 "프로젝트 규칙"은 이 플러그인의 지침보다 우선합니다. 지침을 읽다가 프로젝트 규칙과 다른 곳을 만나면 프로젝트 규칙을 따릅니다. 작업 중 요청이 지침과 부딪히면 그때만 한 번 이 프로젝트만 예외로 둘지([프로젝트 규칙](../manage-workflow/references/project-rules.md)), 지침을 고칠지([지침 제안](../manage-workflow/references/proposals.md)), 지침대로 할지 사용자에게 묻고 처리합니다. 플러그인 원본과 다른 프로젝트는 자동으로 바꾸지 않습니다.

## 시작

시작할 때 프로젝트 AGENTS.md의 최소 판과 설치된 플러그인 판을 비교합니다. 설치된 판이 낮거나, 세션 중에 플러그인이 갱신돼 지침이 맞지 않거나, 필요한 지침을 읽을 수 없으면 추측으로 진행하지 않고 [이어받기 문서](references/handoff.md)를 따릅니다.

사용자가 원하는 결과를 짧게 설명하고 기존 변경·staging 상태를 확인합니다. 제품 동작이 달라지면 관련 요구사항과 설계를 읽습니다. 기록 위치와 이슈 도구는 프로젝트가 정합니다. 연결되지 않은 도구를 필수로 가정하거나 조회만 하는 질문에 업무를 만들지 않습니다.

작업에 맞는 플레이북 하나를 읽고, 계약·스키마 변경 같은 의존 단계만 함께 수행합니다. 작은 수정은 필요한 단계만 적용합니다.

| 작업 | 플레이북 |
| --- | --- |
| 코드·설계 설명, 근거 조사 | [조사](playbooks/investigate.md) |
| 새 기능·제품 동작 변경 | [기능](playbooks/feature.md) |
| 버그 재현·수정 | [버그](playbooks/bug-fix.md) |
| 동작을 유지하는 구조 변경 | [리팩터링](playbooks/refactor.md) |
| 반복 실수·작업 방식 개선 | [지침 개선](playbooks/evolve.md) |

## 필요한 지침만 읽기

아래 링크에서 필요한 지침만 읽습니다. 관리 도구로 이름을 바꿔 설치하면 스킬 메타데이터와 지침 링크도 함께 바뀝니다.

| 바꾸는 것 | 읽을 스킬 |
| --- | --- |
| React 화면·상태·라우트 | [프론트엔드](../frontend/SKILL.md) |
| UI 부품·테마·아이콘 | [디자인 시스템](../design-system/SKILL.md) |
| Java 모듈·도메인·서비스 | [백엔드](../backend/SKILL.md) |
| HTTP·오류·인증·생성 타입 | [API](../api/SKILL.md) |
| 스키마·마이그레이션 | [DB](../database/SKILL.md) |
| 시스템 경계·새 기술·운영 | [아키텍처](../architecture/SKILL.md) |

프론트엔드는 상태와 코드 구조, 디자인 시스템은 화면 표현을 다룹니다. 백엔드는 도메인·서비스·트랜잭션, DB는 스키마·마이그레이션, API는 외부 HTTP 계약을 다룹니다. 여러 영역을 바꾸면 관련 지침을 함께 읽습니다. 규칙 본문은 담당 지침 한 곳에서 고치고 다른 지침에서는 연결합니다.

스킬·참고 자료·문서를 작성하거나 고칠 때는 [글쓰기 기준](references/writing.md)을 읽습니다. 스킬 본문과 예시에도 같은 기준을 적용합니다. 글은 직접 쓰지 않고 [글쓰기 맡기기](references/writer.md)에 따라 맡깁니다. 로고·이미지 같은 에셋은 [에셋 맡기기](references/assets.md)에 따라 맡깁니다.

## 진행과 완료

- 관례와 코드로 확인할 수 있는 것은 확인하고 진행합니다. 제품 의미·팀 선택이 갈리는 부분만 질문합니다.
- 데이터 소유권·입출력·실패 상태를 정한 뒤 구현합니다. 추측한 재사용을 위해 계층을 늘리지 않습니다.
- 역할마다 기본값을 두되(글쓰기·에셋 역할), 도구와 모델은 사용자 설정과 실행 환경을 따르고 없으면 세션 모델을 씁니다. 다중 에이전트, 자동 커밋·병합을 전제하지 않습니다.
- [검증](references/verification.md)에 따라 바뀐 부분을 확인합니다. 수행한 검증과 남은 제한을 구분해 답합니다.
- 작업 중 MCP·플러그인 도구의 기능 부족이나 반복 호출을 실제 스키마로 확인하면 우회만 설명하고 끝내지 않고 [도구의 부족을 발견했을 때](references/tool-improvements.md)를 따릅니다.
- 커밋·푸시·게시·배포는 사용자가 허용한 범위에서만 합니다.

스킬 자체가 틀렸으면 [지침 개선](playbooks/evolve.md)으로 원인을 고칩니다.

# 미리보기 패널

목록을 그대로 둔 채 항목을 차례로 훑을 때 목록 옆에 여는 비모달 패널입니다. Linear는 Space 키로, Plane은 행 클릭으로 엽니다. 우리는 Plane과 달리 미리보기 대상을 주소에 남겨 뒤로가기·새로고침·공유가 같은 화면을 엽니다. 구현은 키트의 [peek](https://github.com/dev-goraebap/dev.goraebap/tree/main/site/src/shared/ui/patterns/routing)와 [PeekLayout](https://github.com/dev-goraebap/dev.goraebap/tree/main/site/src/shared/ui/layouts/peek)·[InboxLayout](https://github.com/dev-goraebap/dev.goraebap/tree/main/site/src/shared/ui/layouts/peek)·[InboxPane](https://github.com/dev-goraebap/dev.goraebap/tree/main/site/src/shared/ui/layouts/peek)이 맡습니다.

## 언제 쓰나

| 상황 | 표현 |
| --- | --- |
| 목록을 보며 여러 항목을 차례로 확인합니다 | 미리보기 패널 |
| 한 항목에 들어가 오래 읽고 씁니다 | 자기 페이지 |
| 새로 만들거나 고칩니다 | [라우트 마스킹](route-masking.md) |
| 기록 한 줄의 사실만 봅니다(주소가 필요 없음) | [옆 패널](layout-patterns.md#옆-패널) |

## 계약

1. 목록 주소에 `?peek=대상ID`를 더합니다. 검색·필터·표시 조건은 그대로 둡니다.
2. 처음 열 때는 방문 기록을 하나 쌓습니다(push). 뒤로가기가 패널을 닫습니다.
3. 열린 채 다른 항목으로 옮길 때(다른 행, 위·아래 키)는 기록을 쌓지 않고 바꿉니다(replace). 뒤로가기 한 번이면 목록으로 돌아옵니다.
4. 새로고침·공유 링크로 `?peek=`가 오면 목록과 패널을 함께 엽니다. 대상이 없으면 패널 자리에만 "찾을 수 없음"을 보입니다.
5. 패널의 "페이지로 열기"는 대상의 자기 주소로 갑니다. 미리보기와 페이지는 같은 조회와 같은 본문 부품을 씁니다.
6. 휴대폰 폭에서 `?peek=`가 오면 패널을 그리지 않고 대상 페이지로 바꿔 갑니다(replace).
7. 패널은 목록을 가리지 않습니다. 목록은 계속 조작할 수 있고 미리보기 중인 행을 표시합니다. Esc와 닫기 버튼으로 닫고, 닫으면 초점은 그 행으로 돌아갑니다.
8. 패널 폭은 본문의 약 40~50%입니다. 영역이 좁아 목록과 패널을 함께 둘 수 없으면 미리보기 대신 페이지로 엽니다.

## 행을 누르면 무엇이 열리나

목록이 무엇을 하는 곳인지로 정합니다. 한 목록 안에서는 한 가지로 통일합니다.

| 목록 | 예 | 행 클릭 | 행 링크의 주소 | 미리보기를 여는 다른 방법 |
| --- | --- | --- | --- | --- |
| 처리 목록: 여러 항목을 연달아 확인하고 판단합니다 | 받은 항목, 알림, 승인 대기, 검토 요청 | 미리보기 | 목록 주소 + `?peek=ID` | 위·아래 키로 이동 |
| 작업 목록: 하나를 골라 들어가 일합니다 | 업무, 문서, 자료 | 페이지 | 대상의 자기 주소 | Space 키, 행 끝의 미리보기 버튼 |

작업 목록은 열 때만 생기는 미리보기 패널(`PeekPanel`, 본문의 약 45%)을 쓰고, 처리 목록은 데스크톱에서 `InboxLayout`으로 목록과 상세 칸(`InboxPane`)을 늘 함께 둡니다. 목록과 상세 칸은 각각 자기 머리 줄과 세로 스크롤을 가지며, 목록 폭은 가운데 구분선 손잡이(`ResizeHandle`, 키보드 조작 지원)로 조절합니다. 고른 항목이 없으면 상세 칸에 전용 일러스트(`InboxIllustration`)와 함께 고르라는 빈 상태(예: "알림을 선택해 주세요")를 보입니다. 행 어디를 눌러도(글자가 아닌 곳도) 상세 칸에 그 항목이 열리며, 안 읽은 항목은 바탕색을 쓰지 않고 굵은 제목과 행 끝의 "안 읽음" 표시로 구분하고 열면 읽음이 되어 메뉴의 안 읽은 수도 줄어듭니다. 상세 칸 머리 왼쪽에는 ← 닫기와 항목 이름, 오른쪽에는 페이지로 열기를 둡니다. ←나 Esc로 닫으면 빈 상태로 돌아가고 초점은 그 행으로 갑니다. 주소 계약(`?peek=`, 처음은 push·옮길 때 replace, 새로고침·공유, 없는 대상은 상세 칸에만 "찾을 수 없음", 위·아래 키로 옮김)은 기존 계약 그대로이며, 휴대폰은 상세 칸 없이 목록만 보이고 행은 그 항목의 페이지로 갑니다.

어느 쪽이든 행은 실제 링크라서 새 탭·주소 복사가 그 주소를 따릅니다. 휴대폰은 미리보기가 없어 둘 다 페이지로 갑니다. 성격이 애매하면 작업 목록으로 봅니다.

## 확인할 동작

작업 목록에서 행 끝 버튼이나 Space로 미리보기를 열고 위·아래 키로 옮긴 뒤 뒤로가기 한 번에 목록으로 돌아오는지, 주소의 `?peek=`가 바뀌는지, 새로고침해도 같은 패널이 열리는지 확인합니다. 휴대폰 폭에서 같은 주소가 페이지로 바뀌는지, 닫은 뒤 초점이 행으로 돌아오는지 확인합니다. 처리 목록에서는 행 아무 데나 눌러 상세 칸을 열고, ←나 Esc로 닫으면 빈 상태로 돌아갔다가 다시 다른 행을 누르면 열리며, 휴대폰에서는 행을 누르면 페이지로 가는지 확인합니다.

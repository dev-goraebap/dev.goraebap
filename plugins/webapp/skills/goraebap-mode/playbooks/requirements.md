# 요구사항 토론

1. 누가 어떤 상황에서 무엇을 하려는지 질문과 답변으로 좁혀 문제와 범위를 정리합니다.
2. 근거를 조사합니다. 코드, 테스트, 기존 설계·결정 순으로 필요한 부분을 읽고 현재 구현, 문서상의 의도, 아직 확인되지 않은 추정을 구분합니다. 버전이 바뀔 수 있는 외부 기술 사실은 해당 버전의 공식 자료를 확인합니다. 조사만 요청받았으면 여기서 멈추고 구현이나 규칙 변경으로 넘어가지 않습니다.
3. 관례와 코드로 확인할 수 있는 부분은 확인하고 넘어가며, 제품 의미나 구조 선택이 갈리는 지점만 권장안과 감수할 대가를 붙여 하나씩 묻습니다. 여러 영역에 걸치는 구조나 상태 소유권, 외부 연동은 [프로젝트 지침](../../webapp-project/SKILL.md) 기준으로 검토합니다.
4. 합의한 요구사항과 수용 조건을 프로젝트가 정한 문서와 이슈 도구에 남기고, 되돌리기 어려운 선택과 기각한 대안은 결정 기록에 적습니다. 사람이 읽는 문서는 [글쓰기 기준](../references/writing.md)과 [글쓰기 맡기기](../references/writer.md)에 따라 다듬습니다.

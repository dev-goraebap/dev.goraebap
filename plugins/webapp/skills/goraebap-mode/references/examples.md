# 예시 읽기

영역 지침은 판단 기준만 담습니다. 그 기준을 실제 코드로 옮긴 모양은 각 스킬의 `examples/` 폴더에 주제별 예시 파일로 있습니다. 예시는 공개 오픈소스 프로젝트의 고정 커밋에서 발췌한 코드이며, 파일 하나에 스택별 절이 하나씩 있습니다.

## 고르는 법

1. 프로젝트 AGENTS.md의 `- Webapp 스택: <스택 id>, <스택 id>` 줄을 확인합니다.
2. 영역 지침의 규칙을 구현할 때 같은 스킬의 `examples/`에서 그 규칙을 링크한 예시 파일을 찾고, 프로젝트 스택과 이름이 같은 절만 읽습니다.
3. 프로젝트 스택과 같은 절이 없으면 다른 스택의 절을 옮겨 쓰지 않고 지침만으로 구현합니다. 예시가 없었다는 사실을 작업 보고에 적습니다.
4. 줄이 없으면 프로젝트의 실제 의존성에서 스택을 확인하고, 줄을 더할지 사용자에게 묻습니다([연결](../../onboarding/SKILL.md#연결)).

## 읽는 기준

- 규칙은 지침에서 읽고, 예시에서는 그 규칙이 코드의 어디에 드러나는지만 봅니다. 예시에만 있는 구현을 새 규칙으로 삼지 않습니다.
- 예시는 복사할 템플릿이 아닙니다. 예시 프로젝트에만 있는 기능과 이름은 따라 만들지 않습니다.
- 지금 프로젝트의 AGENTS.md 프로젝트 규칙과 기존 코드가 예시보다 우선합니다.
- 작업을 보고할 때 읽은 지침과 예시 파일을 적습니다.

## 예시를 더하거나 고치는 법

- 파일은 `skills/<스킬>/examples/<주제>.md`에 둡니다. 프론트매터 `arc42`는 그 스킬과 같은 값, 제목은 한국어 주제 이름, 첫 문단은 예시가 보여 주는 규칙과 그 규칙 링크입니다.
- 절 제목은 스택 id만 씁니다. 쓸 수 있는 id는 `plugins/webapp/scripts/check.mjs`의 `STACKS` 목록이며, 새 스택을 더할 때는 그 목록에 함께 더합니다.
- 절마다 `출처:` 줄에 원본 저장소의 40자리 고정 커밋 주소를 걸고, 언어를 적은 코드 블록으로 원문을 발췌합니다. 줄인 자리는 주석 한 줄로 표시합니다.
- 예시는 공개 오픈소스 프로젝트에서만 가져옵니다. 원본이 크게 바뀌면 같은 주제의 발췌와 고정 커밋을 함께 올립니다.
- 고친 뒤 `plugins/webapp/`에서 `npm run check`로 형식을, `npm run check:links`로 고정 커밋 링크를 확인합니다.

# 프론트엔드 엔지니어링

웹 앱은 컴포넌트 기반 화면, 검증한 URL을 다루는 라우터, 서버 데이터 캐시를 맡는 조회 도구로 짭니다. 파일 구조는 공식 `feature-sliced-design` 스킬을 따릅니다. 어떤 라이브러리와 판을 쓰는지는 프로젝트에서 정하며, 프로젝트가 채택한 스택을 다른 것으로 바꾸는 일을 작업에 끼워 넣지 않습니다.

## 예시

이 지침은 판단 기준만 담고 구현은 담지 않습니다. 구현 모양은 이 스킬의 `examples/` 폴더에서 프로젝트 `AGENTS.md`의 `Webapp 스택:` 줄과 이름이 같은 절을 읽습니다. 읽는 법은 [예시 읽기](../goraebap-mode/references/examples.md)에 있습니다. 예시와 프로젝트 `AGENTS.md`가 다르면 `AGENTS.md`를 따릅니다.

## 읽을 자료

- [코드 작성](references/structure.md): 컴포넌트·훅·Effect를 다룰 때 읽습니다.
- [상태와 데이터 흐름](references/data-flow.md): 조회·변경·폼·라우트를 다룰 때 읽습니다.
- [화면 전환](references/navigation.md): 로딩·목록 복귀·상세 이동을 다룰 때 읽습니다.

화면 패턴을 구현·수정할 때는 디자인 시스템 지침의 [패턴 카탈로그](../frontend-design-system/references/pattern-catalog.md)에서 사용 기준과 실제 컴포넌트를 함께 찾습니다. 견본에는 제품과 같은 라우터·상태 경계를 연결하고 데이터와 시작 상태를 제어합니다.

새 화면이나 시각적 변경은 [디자인 시스템](../frontend-design-system/SKILL.md)을, 로딩·전환·상태 화면·누르는 동작은 [인터랙션](../frontend-interaction/SKILL.md)을 함께 읽습니다. 이 스킬은 코드 배치·상태·URL·비동기 흐름을 소유하고, 컴포넌트 선택·테마·레이아웃·반응형 표현은 디자인 시스템, 화면이 반응하고 움직이는 방식은 인터랙션 지침을 따릅니다. 같은 규칙을 두 곳에 복제하지 않습니다.

경로·개발 포트·로그인 방법·검사 명령은 프로젝트의 실제 설정에서 확인합니다. 완료 시 프로젝트 검사와 바뀐 사용자 동작을 확인합니다.

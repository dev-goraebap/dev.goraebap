# 프로젝트 규칙

프로젝트가 플러그인 지침과 다르게 하는 결정을 적는 자리입니다. 에이전트는 지침을 읽기 전에 이 규칙을 먼저 보고, 지침과 부딪히는 곳은 프로젝트 규칙을 따릅니다.

## 표로 적는다

AGENTS.md의 "프로젝트 규칙" 표에 결정 하나를 한 줄로 적습니다.

| 열 | 쓰는 것 |
| --- | --- |
| 지침 | 덮어쓰는 지침 이름과 주제. 예: `frontend-engineering` 폼 초안 |
| 지침의 기준 | 지침이 정한 것을 한 문장으로 |
| 이 프로젝트 | 대신 하는 것을 한 문장으로 |
| 이유 | 왜 다른지. 제품 제약, 기존 시스템, 팀 합의 |

예시는 다음과 같습니다.

| 지침 | 지침의 기준 | 이 프로젝트 | 이유 |
| --- | --- | --- | --- |
| `frontend-design-system` 분기점 | 휴대폰과 데스크톱을 64rem 하나로 가릅니다 | 태블릿 가로(1024~1279px)에서는 사이드바를 접어 엽니다 | 현장 태블릿이 주 사용 기기입니다 |
| `backend-engineering` 조회 | 스키마에서 생성한 쿼리 코드로 조회합니다 | 통계 화면은 기존 SQL 매퍼를 유지합니다 | 이관 전 레거시 모듈 |
| `goraebap-mode` 글쓰기 모델 | 사람이 읽는 글은 Gemini 4 Neon에 맡깁니다 | Claude 하위 에이전트로 씁니다(외부 모델 금지) | 회사 자산이 외부로 나가지 않아야 합니다 |

## Webapp 스택 줄

AGENTS.md "개발 지침" 블록의 `- Webapp 스택: <스택 id>` 줄은 각 스킬의 `examples/`에서 읽을 스택 절을 정합니다. 지침은 스택 없이 규칙만 담으므로, 에이전트는 영역 지침을 읽을 때마다 같은 스킬의 `examples/`에서 이 줄에 적은 스택 절을 함께 읽습니다. 고르는 법과 읽는 기준은 [예시 읽기](../../goraebap-mode/references/examples.md)에 있습니다.

- 줄은 블록의 지침 문단 바로 뒤, "프로젝트 규칙" 표 앞에 한 줄로 둡니다. 스택이 여럿이면 쉼표로 구분해 적습니다.
- 예시와 이 프로젝트가 다르게 하는 것은 스택 줄이 아니라 프로젝트 규칙 표에 적습니다. 프로젝트 규칙이 예시보다 우선합니다.
- 지원하는 스택 절이 없으면 줄을 두지 않습니다. 에이전트는 지침만으로 작업하고 그 사실을 보고합니다.

## 길면 파일로 뺀다

한 줄에 담기지 않는 규칙(절차, 여러 예외, 코드 예시)은 `.agents/rules/<지침>.md`에 쓰고 표의 "이 프로젝트" 칸에서 링크합니다. 그 파일도 지침과 다른 부분만 적습니다. 지침 전체를 옮겨 적지 않습니다.

## 프로젝트 스킬

AGENTS.md는 모든 세션에 읽히므로 늘 필요한 것만 둡니다. 프로젝트 설명 한 문단, 폴더 지도, 로컬 실행 한 줄, 커밋·배포 범위 같은 상시 규칙, 프로젝트 스킬 목록, Webapp 블록과 프로젝트 규칙 표입니다. 그 밖에 특정 작업에서만 필요한 절차(배포, 패키징, 도메인 규칙, 외부 시스템 연동, 검사 명령 묶음)는 프로젝트 스킬로 뺍니다.

- 원본은 `.agents/skills/<스킬>/SKILL.md`입니다. 머리말에 `name`과, 언제 읽는지 적은 `description`을 둡니다. 이름은 프로젝트 접두사를 붙여 Webapp 지침 이름과 겹치지 않게 합니다(예: `<프로젝트>-delivery`).
- AGENTS.md에는 「작업 | 스킬」 표로 목록만 둡니다. 본문은 그 작업을 할 때만 읽힙니다.
- `.agents/skills`를 바로 읽지 않는 에이전트(Claude Code)를 위해 `npx skills add ./.agents/skills --skill "*" -a claude-code --copy -y`로 `.claude/skills/`에 복사합니다. 세션 시작 훅에서 이 복사를 돌리는 스크립트(`scripts/sync-skills.mjs`)를 두고, 원본에서 지운 스킬은 `skills-lock.json`의 이름으로 찾아 사본에서도 지웁니다. `.claude/skills/`와 `skills-lock.json`은 gitignore하고 손으로 고치지 않습니다.
- Webapp 지침의 사본은 프로젝트 스킬로 두지 않습니다. 지침과 다르게 하는 것은 위의 프로젝트 규칙 표에 적습니다.

## 지킬 것

- 지침과 같은 내용은 적지 않습니다. 같으면 지침이 이미 말하고 있습니다.
- 지침에 없는 이 프로젝트만의 사실은 표에 적지 않습니다. 늘 필요한 것(폴더 지도, 로컬 실행)은 AGENTS.md 설명에, 특정 작업에서만 필요한 것(제품 용어, 도메인 규칙, 절차)은 [프로젝트 스킬](#프로젝트-스킬)에 씁니다.
- 플러그인을 갱신한 뒤 지침이 프로젝트 규칙과 같아졌으면 그 줄을 지웁니다. 지침이 바뀌어 규칙의 "지침의 기준" 칸이 틀려졌으면 고칩니다.
- 공통 지침 수정을 제안한 항목도 표에는 이슈 번호나 제안 표시 없이 지속 규칙 한 줄만 남깁니다. 플러그인을 갱신한 뒤 닫힌 이슈를 보고 반영됐으면 같은 줄을 지우고, 버려졌으면 예외로 남깁니다.
- 다른 프로젝트에도 맞는 규칙은 [지침 제안](proposals.md) 대상입니다.

# 조회와 변경

## 조회 옵션, 캐시 키, 준비 함수

조회를 소유한 슬라이스의 `api/`에 요청 함수, 캐시 키, 조회 옵션을 함께 둡니다. 라우트의 데이터 준비(loader)와 화면 컴포넌트는 같은 조회 옵션을 쓰며, 응답을 바꾸는 모든 인자를 캐시 키에 빠짐없이 넣습니다.

캐시에서 꺼낸 값이 항상 최신 응답이라고 가정하지 않고, 최신 응답을 기다려야 하면 그 조회의 신선도 기준을 명시합니다. 조회 도구가 사용 중단한 API는 쓰지 않고 그 버전이 권하는 호출로 씁니다. 라우트의 데이터 준비는 실패하면 준비가 멈추는 필수 조회와 실패해도 넘어가는 선택 조회를 나눈 준비 함수 하나로 정리합니다.

스택별 구현: [react.md](react.md#query-options) · [angular.md](angular.md#query-options)의 「query-options」 절

## 변경과 캐시 무효화

기본 변경 흐름은 mutation이 성공한 뒤 관련된 캐시 키를 무효화하는 방식입니다. 저장은 성공했는데 뒤따른 재조회만 실패한 상황을 저장 실패로 알리지 않습니다.

낙관적 갱신과 명령 자동 재시도는 기본으로 켜지 않고 중복 실행 위험과 복구 비용을 따져 필요한 곳에만 고릅니다.

## 상태 구분, 계정 전환, 큰 목록

초기 로딩, 정상 빈 결과, 조회 오류는 분명히 구분해 처리합니다(상태별 화면 표현은 디자인 시스템의 [화면 상태](../../../design-system/ui-states/index.md)에서 다룹니다). 계정이나 권한이 바뀌는 순간에는 이전 범위의 데이터가 노출되지 않도록 진행 중인 조회를 취소하고 캐시를 비웁니다.

큰 목록은 브라우저에서 전체를 내려받지 않고 서버에서 필터, 정렬, 페이지를 처리합니다. 무한 목록은 보관 중인 페이지 조각 전체가 한꺼번에 재조회되는 비용을 확인하고 목록 복귀, 새 진입, 갱신 정책을 따로 정합니다. 프로젝트에 없는 목록 도우미를 임의로 호출하지 않습니다.

| 상황 | 처리 기준 |
| - | - |
| 조회 결과 구분 | 초기 로딩, 정상 빈 결과, 조회 오류를 서로 섞지 않음 |
| 계정 · 권한 전환 | 진행 중 조회 취소와 이전 범위 캐시 제거 |
| 큰 목록 | 서버에서 필터, 정렬, 페이징 처리 |
| 무한 목록 | 조각 전체 재조회 비용을 확인하고 복귀·새 진입·갱신 정책 분리 |

# 리소스 화면 패턴

리소스 하나(공지, 회의록, 업무, 문서처럼 목록과 자기 주소를 가진 대상)의 목록·상세·생성·수정을 어디에 띄우고 어떻게 오가는지 정합니다. 리소스마다 아래 세 패턴 가운데 하나를 고릅니다. 이 문서는 배치·주소·오가는 방식·언제 쓰나만 정하고, 모양은 컴포넌트 이름으로 가리킵니다. 헤더·목록·상세의 모양은 페이지 배치, 목록 위 대화상자의 주소 계약은 [라우팅 마스크](../../interaction/route-masking/index.md), 상태·복귀·직접 링크의 코드 계약은 frontend의 [리소스 주소](../../engineering/resource-routes/index.md)을 따릅니다.

## 세 패턴

| 패턴 | 배치 | 주소 | 언제 쓰나 |
| - | - | - | - |
| List-Detail (목록-상세 분할) | 목록과 오른쪽 칸을 한 화면에 둡니다. 상세·생성·수정을 모두 오른쪽 칸에 엽니다 | 열린 칸을 주소가 정합니다: `/리소스/{id}`, `/리소스/new`, `/리소스/{id}/edit`. 칸을 바꿔도 목록은 다시 그리지 않습니다 | 줄 하나가 제목과 한두 줄로 읽히고, 하나씩 열어 읽고 넘기는 리소스 |
| Drill-down (페이지 이동형) | 목록은 전체 너비(표를 쓸 수 있습니다). 상세·생성·수정은 각자 자기 페이지입니다 | 주소 규칙은 같습니다. 어디서 열든 그 페이지로 갑니다 | 목록이 열을 비교하는 표라 좁히면 안 되는 리소스, 오래 읽는 상세, 길거나 단계가 있는 양식 |
| Routed Modal (목록 위 대화상자) | 목록(캘린더·보드·넓은 표)이 화면을 다 쓰고, 상세·생성·수정은 그 위의 대화상자(45rem)에 엽니다 | 주소창에는 대상 주소를, 실제 주소는 목록 + 패널 쿼리로 둡니다([라우팅 마스크](../../interaction/route-masking/index.md)). 새로고침·직접 링크는 대상 페이지를 엽니다 | 목록 자체가 화면을 다 써야 하고, 상세를 잠깐 보고 돌아오는 일이 잦을 때 |

패턴은 앱 전체에 하나만 두지 않고 리소스의 성격에 맞춰 고릅니다. 패턴은 리소스가 아니라 여는 화면이 정합니다. 같은 일정 양식이 자기 목록에서 열면 페이지(Drill-down)이고, 캘린더에서 열면 대화상자(Routed Modal)일 수 있습니다. "어디서 열든 페이지"여야 하는 리소스만 주소 규칙으로 고정합니다.

줄을 누르면 패턴이 정한 곳이 열립니다. 목록 옆에 따로 훑어보는 미리보기 패널은 두지 않습니다. 줄을 눌러 여는 것과 역할이 겹치기 때문입니다.

## List-Detail

데스크톱에서 목록과 오른쪽 칸을 분할 틀로 나란히 둡니다. 오른쪽 칸의 상세·생성·수정은 칸 머리 틀을 씁니다.

- 고르기 전의 오른쪽 칸은 빈칸으로 두지 않고 고르기를 권하는 상태(리소스별 그림과 제목)를 보입니다. 점 무늬는 이 빈 칸에만 씁니다.
- 목록을 접고 상세만 크게 보는 집중 보기를 둡니다. 주소에 집중 보기 쿼리(예: `?focus=1`)를 더하고 Esc로 풉니다.
- 오른쪽 칸에 쓰던 내용이 있으면 다른 줄을 누르거나 칸을 닫을 때 버릴지 묻습니다.
- 데스크톱 목록은 표가 아니라 줄 목록이고, 정렬은 정렬 메뉴로 바꿉니다.
- 휴대폰은 목록만 보이고 상세·생성·수정은 각자 페이지로 엽니다.
- 표·보드·캘린더에는 쓰지 않습니다. 표를 오른쪽 칸 옆으로 좁히면 열이 빠져 비교할 정보가 사라집니다.

화면마다 분할 틀을 새로 조립하지 않습니다. 분할 틀은 진입부·목록 화면·줄 컴포넌트로 나눠 두고, 화면은 줄·도구·칸 내용만 넘깁니다. 빈 칸의 문구와 목록 폭을 저장할 키는 화면마다 반드시 넘깁니다.

## Drill-down

목록은 작업 영역 전체 폭을 쓰고, 상세·생성·수정은 페이지 틀 안의 자기 화면입니다. 데스크톱의 상세·작성·수정 페이지는 List-Detail의 오른쪽 칸과 같은 칸 머리 틀을 씁니다. 관리 화면의 상세도 같습니다.

- 상세의 뒤로는 경로의 위 단계(목록)로 갑니다. 브라우저 기록을 되짚지 않습니다.
- 수정은 끝내거나 취소하면 원래 상세로, 생성은 저장하면 만든 대상의 상세로 갑니다.
- 휴대폰은 상세·양식에서 하단 막대를 숨깁니다(앱 셸).

## Routed Modal

캘린더·보드·넓은 표가 화면을 다 쓰고, 상세·생성·수정은 그 위의 대화상자로 엽니다. 대화상자 안의 상세는 대화상자 머리를, 내용은 페이지와 같은 상세 컴포넌트를 씁니다.

- 항목을 누르면 요약 팝오버를 거치지 않고 바로 상세 대화상자를 엽니다.
- 대화상자에서 다른 대화상자로 넘어갈 때(상세 → 수정, 상세 → 다른 상세)는 닫혔다 열리지 않고 지금 대화상자의 자리를 이어받습니다([페이지 전환과 대기](../../interaction/page-transition/index.md#화면-전환)).
- 대화상자의 "페이지로 열기"는 대상의 자기 주소로 갑니다.
- 휴대폰은 대화상자 없이 그 페이지로 갑니다.

## 크게 보기의 두 아이콘

주소가 다른 페이지로 바뀌는 동작(대화상자나 칸을 페이지로 열기)은 ↗ 아이콘을 씁니다. 같은 주소에서 목록을 접어 크게 보는 동작(List-Detail의 집중 보기)만 ⤢·⤡ 아이콘을 씁니다. 두 동작에 같은 아이콘을 쓰면 누른 뒤 주소가 바뀌는지 미리 알 수 없습니다.

## 패턴이 아닌 여는 방식

주소가 있는 리소스는 세 패턴 가운데 하나로 엽니다. 다음은 리소스 패턴이 아니며 따로 정합니다.

| 여는 것 | 표현 |
| - | - |
| 주소가 필요 없는 기록 한 줄의 사실, 표·그림 위에서 잠깐 보는 대상 | 옆 패널 |
| 자기 페이지가 없는 짧은 양식(이름 바꾸기, 폴더 만들기) | [짧은 양식 대화상자](../dialog/index.md) |
| 프로필 같은 짧은 보기, 전역 검색 | [라우팅 마스크](../../interaction/route-masking/index.md)의 목록 위 대화상자 |

## 확인할 동작

- List-Detail: 줄을 눌러 칸을 바꿔도 목록의 스크롤과 선택이 남는지, 주소가 `/리소스/{id}`로 바뀌는지, 새로고침해도 같은 칸이 열리는지 확인합니다. 집중 보기를 켜고 Esc로 푸는지, 작성 중에 다른 줄을 누르면 버릴지 묻는지, 휴대폰에서 줄이 페이지로 가는지 확인합니다.
- Drill-down: 상세의 뒤로가 목록으로 가는지, 수정 취소가 원래 상세로, 생성 저장이 만든 상세로 가는지, 휴대폰에서 상세·양식의 하단 막대가 숨는지 확인합니다.
- Routed Modal: 항목을 누르면 바로 상세 대화상자가 열리는지, 상세 → 수정에서 대화상자가 다시 뜨지 않고 자리를 이어받는지, 새로고침이 대상 페이지를 여는지, 휴대폰에서 페이지로 가는지 확인합니다.

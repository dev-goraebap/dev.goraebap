# 프론트엔드

## design-system

웹 앱의 테마·글자·간격·면 위계·아이콘, 기본·조합 컴포넌트, 앱 셸·페이지 배치·리소스 화면 패턴과 화면 문구를 일관되게 구현합니다. 컴포넌트·스타일·테마·레이아웃·화면 패턴을 만들거나 바꿀 때 사용합니다.

고정된 디자인 토큰 값을 강제하지 않고, 어떤 UI 라이브러리를 쓰든 지키는 화면 구조·면 위계·반응형 전환·상호작용 기준을 담습니다. 프로젝트가 정한 디자인·기존 컴포넌트·사용자가 준 참고 화면을 우선합니다. 별도 지정이 없으면 예시에서 채택한 컴포넌트 라이브러리·스타일 도구·아이콘 세트와 아래 기준을 출발점으로 씁니다. 기본값을 다른 UI 라이브러리로 바꾸는 권한으로 해석하지 않습니다.

### 예시

구현 모양은 각 자료 폴더의 스택 글(`react.md`·`angular.md`)에서 프로젝트 스택의 것만 읽습니다(예시 읽기).

### 맡는 범위

공통 지침은 화면의 구성·상태·반응형·상호작용을 다룹니다. 컴포넌트 하나의 API(조합 방법, 폼 칸 묶기, 요소 바꾸기, 아이콘 넣는 법, 간격 유틸리티 등)는 프로젝트가 채택한 컴포넌트 라이브러리의 공식 문서와 도구가 맡고, 이 지침은 면 단계·휴대폰 규칙·로딩 방식·대화상자 ↔ 페이지·문구 같은 규칙을 맡습니다. 둘이 다르면 이 지침의 규칙이 우선이고, 컴포넌트 API는 라이브러리 문서를 따릅니다. 특정 제품의 업무 단계·문서 종류·권한·저장 계약은 프로젝트 지침에 둡니다. 프로젝트 사례를 공통 원본으로 가져올 때는 재사용할 화면 구조와 동작만 추출합니다.

- [앱 셸과 모바일 탐색](design-system/app-shell/index.md): 앱 셸·공간·사이드바·휴대폰 탐색을 다룰 때 읽습니다.
- [페이지 배치](design-system/page-layout/index.md): 페이지 머리·칸 머리·툴바·목록·표·상세·설정·작성·옆 패널의 모양을 다룰 때 읽습니다.

규칙 본문은 각 자료가 소유합니다. URL·서버 데이터·초안의 소유는 [프론트엔드 엔지니어링](README.md), 움직임·대기와 상태 화면·라우트 마스킹·누르는 동작은 [인터랙션](README.md), 모양과 컴포넌트 조합은 이 지침이 담당합니다. 화면을 만들거나 고칠 때 문구도 설계 대상으로 검토합니다.

디자인 시스템 코드는 스킬에 포함하지 않고 레지스트리에서 받습니다. 스타일 레시피 전체와 프로젝트 프레임워크의 어댑터를 통째로 받아 정해진 폴더에 두고, 받은 폴더는 고치지 않으며 원본 커밋으로 갱신을 비교합니다(디자인 시스템 받기와 갱신). 설치·동기화만으로 제품 소스에 받지 않고, 공통 원본의 변경을 프로젝트에 자동으로 적용하지 않습니다.

완료 시 바뀐 화면의 데스크톱·휴대폰, 제공하는 테마 모드, 포커스·키보드·확대 상태를 확인합니다. 특정 버전의 버그와 우회는 프로젝트 규칙에 둡니다.

## engineering

웹 앱의 화면 계층·코드 규칙, 서버 데이터 캐시와 상태 소유, 라우트와 화면 전환을 구현합니다. 페이지·컴포넌트 코드·프론트 상태·라우트를 만들거나 고칠 때 사용합니다.

웹 앱은 컴포넌트 기반 화면, 검증한 URL을 다루는 라우터, 서버 데이터 캐시를 맡는 조회 도구로 짭니다. 파일 구조는 FSD(Feature-Sliced Design)를 따르며, 이 지침이 쓰는 층과 묶는 법은 [화면 계층](engineering/layers/index.md)에 있습니다. 공식 `feature-sliced-design` 스킬이 설치되어 있으면 함께 읽습니다. 어떤 라이브러리와 판을 쓰는지는 프로젝트에서 정하며, 프로젝트가 채택한 스택을 다른 것으로 바꾸는 일을 작업에 끼워 넣지 않습니다.

### 예시

구현 모양은 각 자료 폴더의 스택 글(`react.md`·`angular.md`)에서 프로젝트 스택의 것만 읽습니다(예시 읽기).

### 읽을 자료

- [화면 계층](engineering/layers/index.md): 층과 pages 폴더, 키트·앱 셸의 경계, 렌더링 방식을 다룰 때 읽습니다.
- [코드 규칙](engineering/code-style/index.md): 파일 이름, 파생값과 부수 효과, 메모이제이션을 다룰 때 읽습니다.
- [상태 소유](engineering/state/index.md): 서버 데이터·URL·입력 초안의 소유와 저장 중 편집을 다룰 때 읽습니다.
- [조회와 변경](engineering/data-flow/index.md): 조회 옵션·준비 함수·변경 후 무효화·큰 목록을 다룰 때 읽습니다.
- [화면 전환](engineering/navigation/index.md): 로딩·미리 준비·지연 로딩·목록 복귀를 다룰 때 읽습니다.
- [리소스 주소](engineering/resource-routes/index.md): 목록·상세·생성·수정의 주소, 대화상자 안 이동, 공간 주소를 다룰 때 읽습니다.

화면 패턴을 구현·수정할 때는 디자인 시스템 지침의 [패턴 카탈로그](design-system/pattern-catalog/index.md)에서 사용 기준과 실제 컴포넌트를 함께 찾습니다. 견본에는 제품과 같은 라우터·상태 경계를 연결하고 데이터와 시작 상태를 제어합니다.

새 화면이나 시각적 변경은 디자인 시스템을, 로딩·전환·상태 화면·누르는 동작은 [인터랙션](README.md)을 함께 읽습니다. 이 스킬은 코드 배치·상태·URL·비동기 흐름을 소유하고, 컴포넌트 선택·테마·레이아웃·반응형 표현은 디자인 시스템, 화면이 반응하고 움직이는 방식은 인터랙션 지침을 따릅니다. 같은 규칙을 두 곳에 복제하지 않습니다.

경로·개발 포트·로그인 방법·검사 명령은 프로젝트의 실제 설정에서 확인합니다. 완료 시 프로젝트 검사와 바뀐 사용자 동작을 확인합니다.

## interaction

웹 앱의 움직임과 동작 줄이기, 대기·빈 상태·실패와 화면 전환, 목록 위 대화상자(라우트 마스킹), 표면 고르기·누르는 대상·키보드 동작, 화면 크기와 스크롤바를 구현합니다. 로딩·전환·상태 화면·상호작용을 만들거나 고칠 때 사용합니다.

화면이 사용자 입력과 데이터 대기에 어떻게 반응하고 움직이는지를 다룹니다. 모양과 컴포넌트 조합은 디자인 시스템, 라우트 데이터 준비·URL·상태 소유는 [프론트엔드 엔지니어링](README.md)이 맡습니다. 같은 규칙을 두 곳에 복제하지 않고 연결합니다.

### 예시

구현 모양은 각 자료 폴더의 스택 글(`react.md`·`angular.md`)에서 프로젝트 스택의 것만 읽습니다.

### 읽을 자료

- [페이지 전환과 대기](interaction/page-transition/index.md): 화면 전환, 진행 표시, 움직임의 시간과 동작 줄이기를 다룰 때 읽습니다.
- [로딩과 크기 전환](interaction/loading-feedback/index.md): 입력 디바운스, 대화상자의 데이터 준비, 높이 전환, 사진 자리를 다룰 때 읽습니다.
- [초기 진입과 새로고침](interaction/initial-load/index.md): 폰트 로딩, 스플래시 화면, 빌드 때 넣는 첫 화면을 다룰 때 읽습니다.
- [라우팅 마스크](interaction/route-masking/index.md): 목록 위 대화상자와 대상 주소, 새로고침·휴대폰 전환을 다룰 때 읽습니다.
- [화면 상태](interaction/ui-states/index.md): 빈 상태·결과 없음·없는 대상·실패 화면과 오류 알림의 자리를 다룰 때 읽습니다.
- [적응형 UI](interaction/adaptive-ui/index.md): 휴대폰 표면 고르기, 누르는 대상, 선택 칸, 키보드, 순서 바꾸기를 다룰 때 읽습니다.
- [화면 크기와 rem](interaction/ui-size/index.md): 큰 화면 자동 확대, 사용자 화면 크기 설정, rem과 px을 다룰 때 읽습니다.
- [스크롤바](interaction/scrollbar/index.md): 스크롤바 거터, 얇은 스크롤바, 부드러운 스크롤을 다룰 때 읽습니다.

완료 시 바뀐 화면의 데스크톱·휴대폰에서 대기·실패·빈 상태, 뒤로가기·새로고침, 포커스·키보드, 동작 줄이기 설정을 확인합니다.

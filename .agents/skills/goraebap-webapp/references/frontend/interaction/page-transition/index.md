# 페이지 전환과 대기

## 이전 화면을 두고 기다리기

링크를 누르자마자 빈 화면이나 스켈레톤으로 넘기면 빠른 응답에서도 화면이 깜빡입니다. 캐시가 있으면 즉시 전환하고, 지연이 길어질 때만 화면 맨 위에 얇은 진행 막대를 띄운 뒤 완성된 화면을 View Transition으로 교체합니다. 그러면 전환이 끊기지 않습니다.

동작 원칙과 CSS는 프레임워크에 관계없이 같으며, 라우터의 데이터 선조회와 캐시 계층을 연결해 구현합니다. 캐시 우선 표시, 미리 준비, 지연 로딩 코드의 준비는 Engineering의 [화면 전환](../../engineering/navigation/index.md)이 소유하고, 이 글은 기다리는 동안과 바뀌는 순간의 표현을 다룹니다.

스택별 구현: [react.md](react.md#router-setup) · [angular.md](angular.md#router-setup)의 「router-setup」 절

## 진행 표시

앱 첫 진입만 스플래시 화면으로 덮고, 그 뒤의 화면 이동에는 본문을 가리는 불투명한 막을 두지 않습니다. 화면 전체 스켈레톤은 모양이 바뀌는 본문과 높이가 맞지 않고, 영역별 오버레이는 같은 판정이 화면마다 늘어나며, 콘텐츠 막은 상세 안 사이드바까지 덮습니다.

캐시가 없어 기다릴 때는 이전 화면을 그대로 두고, 150ms가 지나면 화면 맨 위에 높이 2px의 진행 막대만 띄웁니다. 막대는 배치 위에 겹쳐 그려 내용을 밀지 않습니다. 150ms 안에 끝나면 띄우지 않고, 한 번 띄웠으면 최소 300ms 둔 뒤 새 화면과 함께 바로 내립니다. 그리기 확인 뒤 천천히 걷는 대기를 진행 표시에 쓰면 이동이 끝난 뒤에도 남으므로 쓰지 않습니다. 누른 메뉴의 선택 표시는 응답 전에 먼저 옮깁니다.

진행 막대는 화면 읽기 프로그램에 상태 문구로 알리고, 준비 중인 영역은 `aria-busy`로 드러냅니다. 목록 조건을 바꾸는 동안은 이전 결과를 자리 값으로 유지하고 진행 중임을 알립니다.

## 화면 전환

준비된 화면끼리는 콘텐츠 영역만 200ms 교차 페이드합니다. 화면 전환은 View Transitions로 하고, 문서 전체의 기본 스냅숏을 빼고 전환 이름을 콘텐츠 영역 하나에만 붙입니다. 앞뒤 화면에서 같은 부분(사이드바 등)은 같은 픽셀끼리 겹쳐 그대로 있는 듯 보이므로 화면별 예외를 두지 않습니다. 전환은 라우터가 다음 화면의 데이터 준비를 마친 뒤 시작해, 준비하는 동안 진행 표시가 멈추지 않게 합니다.

```css
/* View Transitions API 공통 전환 시간 */
::view-transition-old(root),
::view-transition-new(root) {
  animation-duration: 160ms;
  animation-timing-function: ease-out;
}

@media (prefers-reduced-motion: reduce) {
  ::view-transition-old(root),
  ::view-transition-new(root) {
    animation-duration: 0ms;
  }
}
```

지원하지 않는 브라우저, 동작 줄이기 설정, 로그인 오가기, 진행 중인 전환, 열린 대화상자에서는 전환 없이 바로 바꿉니다.

- 둥근 면(본문 카드, 휴대폰 하단 막대)이 전환할 때 스냅숏이 각진 사각형으로 번쩍이지 않게, 그 면의 전환 묶음(`::view-transition-image-pair`)을 면의 모서리 반지름으로 자릅니다.
- 대화상자의 바꿔 끼우기(불러오는 중 → 내용, 대화상자 → 대화상자)는 View Transitions로 두 내용을 겹쳐 바꿉니다. 이 전환 동안 페이지 콘텐츠에는 전환 이름을 두지 않습니다. 같이 잡히면 대화상자가 다시 뜨는 것처럼 보입니다.
- 대화상자의 "페이지로 열기"는 대화상자가 그 자리에서 페이지의 콘텐츠 영역으로 커지는 공유 요소(shared element) 전환입니다. 같은 전환 이름이 동시에 두 요소에 붙지 않게, 이름은 전환 종류(`types`)가 맞을 때만 붙입니다.

스택별 구현: [react.md](react.md#crossfade)의 「crossfade」 절

## 움직임의 시간

움직임은 위치가 바뀌었거나 새 내용이 도착했음을 알릴 때, 또는 절차 완료를 한 번 축하할 때만 씁니다. 장식으로 반복하는 움직임을 두지 않습니다.

| 쓰임 | 시간 |
| - | - |
| 꺾쇠 회전·작은 상태 전환 | 빠름 토큰(100ms) |
| 메뉴·시트 등장 | 중간 토큰(250ms) 또는 컴포넌트 기본값 |
| 상태 화면 문구가 자리 잡기 | 420ms, `cubic-bezier(0.2, 0, 0, 1)` |
| 상태 그림이 도착해 나타나기 | 600ms, 한 번만 |
| 화면 전환(캐시가 있을 때) | 200ms 교차 페이드 |
| 스플래시 화면 걷기 | 최소 0.3초 보인 뒤 700ms 페이드([초기 진입과 새로고침](../initial-load/index.md)) |

이미 본 그림·내용은 다시 흐리게 시작하지 않습니다. 흐림(blur) 전환은 매 프레임 다시 그려 무거우므로 쓰지 않습니다.

## 완료 축하

신청 제출이나 최종 승인, 초기 설정 완료처럼 사용자의 절차가 성공으로 끝난 순간에는 기준 요소에서 한 번 터져 사라지는 색종이 효과를 더할 수 있습니다. 이 효과는 화면의 완료 상태 확정·안내 문구를 대신하지 않는 별개 장식이며, 실패·반려·취소에는 쓰지 않습니다.

## 동작 줄이기

`prefers-reduced-motion: reduce`이면 이동·등장·회전·화면 전환을 끄고 결과 상태를 바로 보입니다. 완료 축하 효과도 실행하지 않습니다. CSS 전환을 더하면 같은 파일에 줄이기 규칙도 둡니다. 스크립트에서 부드러운 스크롤·애니메이션을 시작할 때도 같은 설정을 확인합니다.

## 확인할 동작

첫 방문, 캐시가 있는 재방문, 느린 코드·데이터, 중첩 경로, 빠른 연속 이동과 동작 줄이기를 나눠 확인합니다. 화면 전환·로딩·캐시·지연 로딩 컴포넌트를 바꾸면, 실행 중인 앱에 개발용 로그인으로 들어가 주요 이동을 차례로 누르는 브라우저 자동화 점검을 돌립니다.

- 단계에는 같은 틀 안 이동, 3초 넘게 지난 페이지로 다시 방문, 목록 → 상세 → 뒤로 → 같은 상세를 넣고, 새 종류의 화면을 만들면 단계를 더합니다.
- 단계마다 누른 뒤의 레이아웃 이동 합(`layout-shift`, 입력 직후 제외)과 새 화면으로 교체가 끝날 때까지의 대기를 잽니다.
- 진행 표시는 데이터 속성으로 감지하고, 대기는 주소 변경 시각이 아니라 준비 중 표시(`aria-busy`)가 풀릴 때까지로 잽니다.
- 이동이 0.01을 넘거나, 캐시가 있어야 하는 다시 방문에서 진행 표시가 뜨면 실패입니다.

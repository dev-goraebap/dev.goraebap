# 화면 구성

아래 이름은 패턴과 레퍼런스 키트의 부품 이름이다. Astryx 패키지가 같은 이름으로 제공한다고 가정하지 않는다. 제품에는 기존 공통 부품이 있는지 먼저 확인한다.

## 셸

AppShell과 SideNav를 기본으로 한다. inset은 바탕에서 떨어진 페이지 면, split은 탐색과 본문을 가는 선으로 나눈 형태다. 메뉴·테마·본문 밀도는 페이지마다 새로 만들지 않는다. 사이드바는 기본 약 21.25rem, 조절 범위 13.75~23.75rem에서 출발하고 큰 화면 확대 정책과 함께 정한다.

사이드바와 모바일 탐색은 같은 분기점에서 전환한다. 상위 페이지는 앱 바 → 페이지 이름 → 필요한 툴바 → 본문 → 하단 탐색 순이다. 상세·양식은 앱 바와 하단 탭을 치우고 자기 뒤로가기·제목·도구를 가진 전체 화면이다. 상단·하단 탐색을 동시에 중복 표시하지 않는다. 하단 탭은 현재 영역의 주 메뉴와 더보기로 구성하고 업무별 메뉴 이름은 프로젝트가 정한다.

## Page: 머리 줄과 툴바

머리 줄은 왼쪽 경로·페이지 이름·페이지 메뉴, 오른쪽 주 동작이다. 휴대폰은 위 단계로 가는 화살표와 현재 이름으로 줄인다. 경로와 이름은 한 줄이며 넘치면 말줄임한다. 시각적 경로와 본문의 접근 가능한 h1을 함께 고려한다.

뷰·탭이 있으면 아래에 툴바를 둔다. 왼쪽은 보기, 오른쪽은 검색·필터·표시다. 뷰 영역만 가로로 넘치고 도구 영역과 페이지 전체는 넘치지 않는다. 선택 상태는 같은 아이콘의 Bold Duotone과 한 단계 진한 알약으로 표시한다.

구현 전에 기존 Page와 같은 역할의 화면을 읽고, 각 조작을 보기·조건·표시·주 동작으로 나눈다. 검색·필터·정렬 값을 뷰 슬롯에 넣어 툴바를 만들지 않는다. 별도 뷰·탭이 없으면 도구는 머리 줄 오른쪽, 만들기는 그 마지막에 둔다. 생성 선택지가 여럿이면 머리 줄의 같은 만들기 메뉴와 휴대폰 FAB에서 선택하게 한다.

프로젝트가 저장·편집·복제할 수 있는 것은 뷰, 고정된 나눔은 탭으로 구분한다. 보기 방식과 실제 데이터 조건의 소유권은 프론트 상태 규칙을 따른다.

## 목록·관리 화면

목록·표·보드는 작업 영역 전체 폭을 사용한다. 데스크톱 표는 휴대폰에서 핵심 정보의 행 목록으로 바꾼다. 끝의 값은 자주 존재하는 값을 바깥쪽에 정렬해 눈으로 비교하기 쉽게 한다. 목록 밀도·열 정렬·숫자 표기는 공통 정책으로 둔다.

만들기는 데스크톱 머리 줄 마지막 버튼, 휴대폰 상위 목록에서는 하단 탐색 위 FAB다. 선택지가 여럿이면 같은 FAB에서 짧은 선택 시트를 연다. 마지막 행이 FAB에 가리지 않도록 여유를 둔다. 빈 화면의 만들기 동작은 유지한다. 양식에는 FAB를 두지 않는다.

행의 메뉴는 그 항목의 수정·삭제에, 페이지 메뉴는 페이지 자체의 동작에 사용한다. 전체 수가 판단에 필요하면 목록 아래에 읽은 수·전체 수·더 읽기를 둔다. 상세 이동의 URL·검색 복원은 frontend가 담당한다.

## SettingsPage: 값과 정책을 정하는 화면

동일한 페이지 머리 줄 아래 최대 45rem의 가운데 열을 둔다. 제목, 작은 구역 이름·구역 동작, 올린 면 안의 값 목록 순으로 배치한다. 설명은 제목·항목 이름만으로 부족한 정보를 보탤 때만 둔다. 항목은 이름과 끝의 값/컨트롤로 구성하고 필요한 설명을 연결한다. 카드의 마지막 구분선이 바깥 테두리와 겹치지 않게 한다. 작은 변경은 짧은 양식, 제목·본문이 있는 작성은 문서형 양식으로 연다.

## DetailLayout: 본문과 속성

넓으면 읽기 열 오른쪽에 속성을 묶고, 좁으면 같은 속성을 제목과 본문 사이의 줄바꿈 가능한 알약으로 이동한다. 창 폭 대신 실제 컨테이너 폭으로 판단해 패널에서도 자연스럽게 전환한다. 속성 요소를 두 벌 렌더링해 값·초점·상태를 따로 관리하지 않는다. 본문 도구는 페이지 머리 줄의 공통 슬롯으로 연결한다.

리스트·표·보드·달력·매뉴얼은 같은 페이지 틀에 서로 다른 본문을 넣는다. 실제 부품을 사용한 견본으로 밀도와 상태를 비교하며 제품 화면을 별도로 복제하지 않는다.

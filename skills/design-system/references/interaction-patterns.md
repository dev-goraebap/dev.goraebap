# 입력과 상호작용

## 검색·필터·표시

검색 도구는 필요할 때 그 자리에서 칸으로 열고 Esc나 빈 상태의 이탈로 닫는다. 필터는 값을 실제로 고른 경우에만 활성 상태로 본다. 같은 속성 안에서 선택한 여러 값은 OR, 다른 속성의 조건끼리는 AND를 기본으로 하고 제품이 다른 연산자를 요구하면 명시한다.

데스크톱 필터는 속성 → 값의 두 단계 팝오버다. 적용 조건은 아래 줄의 속성·값·지우기 칩, 추가, 모두 지우기로 보인다. 휴대폰은 두 단계 바텀시트와 가로로 넘기는 적용 칩을 사용한다. 필터 버튼의 점은 조건이 있다는 표시이고 개수는 접근 가능한 이름에 포함한다. 정렬·그룹 등 표시 설정이 기본과 다르면 표시와 초기화를 제공한다.

정렬·그룹만 변경했을 때는 표시 메뉴의 인디케이터와 초기화를 사용한다. 실제 필터 조건 없이 필터 상태줄을 만들지 않는다.

URL과 쿼리 키·브라우저 복귀 정책의 본문은 [프론트 데이터 흐름](../../frontend/references/data-flow.md)이 소유한다. 시각적 칩 상태를 별도의 원본으로 만들어 URL과 따로 맞추지 않는다.

## 선택 칸

작은 고정 선택지는 Selector, 큰 목록에서 찾는 입력은 Typeahead/콤보박스를 사용한다. 큰 목록은 처음 8개와 이미 고른 항목, 검색 결과 최대 50개, 나머지 개수 안내를 기본으로 시작한다. 무제한으로 전부 렌더링하지 않는다. 이 수치는 서버 한도와 구분하며 프로젝트가 조절할 수 있다.

검색을 열면 입력에 초점을 두고 선택·Esc 후에는 열었던 칸으로 돌려준다. 선택된 항목은 검색으로 잠깐 보이지 않아도 지키고 로딩·결과 없음·추가 결과 안내를 구분한다. 큰 목록을 검색 기능이 붙은 단순 Selector로 대체하지 않는다.

날짜는 프로젝트 공통 달력, 시간은 직접 입력과 목록을 함께 제공하는 공통 입력으로 일관되게 받는다. 입력 방식은 창 폭을 기준으로 정해 터치 노트북에서도 데스크톱 레이아웃이 깨지지 않게 한다. 종료 시각은 시작 이후의 값과 길이를 함께 보여 준다. 네이티브 입력 사용 여부는 제품의 일관성과 접근성 검증 결과로 정한다.

## 짧은 창과 주소가 있는 양식

확인·소수 입력은 데스크톱의 짧은 대화상자, 휴대폰의 바텀시트다. 제목·본문·속성처럼 큰 작성은 자기 URL을 가진 양식으로 두고, 데스크톱에서는 이전 화면 위에 패널로 열 수 있다. 직접 링크·새로고침·휴대폰에서는 같은 내용을 페이지로 연다. 라우팅과 복귀 구현은 frontend가 담당한다.

문서형 작성은 큰 제목 → 본문 → 속성 알약 → 동작 줄 순이다. 정말 복잡할 때만 단계로 나누고 단계 검증과 마지막 저장을 구분한다. 휴대폰 양식은 하단 탭 없이 저장·취소를 바닥 줄에 모으고 키보드·안전 영역과 본문 가림을 확인한다.

대화상자·시트는 머리·스크롤 본문·바닥의 공통 해부도를 쓴다. 시트의 손잡이 영역과 제목을 겹치지 않게 하고 본문이 길어져도 바닥 동작을 유지한다. 내용이 짧으면 화면 대부분을 차지하지 않는다. 닫기·Esc·배경 누르기·뒤로가기와 초안 보존은 프로젝트의 한 정책으로 묶는다. 닫힌 뒤 초점을 복원한다.

순서 변경은 같은 목록 범위의 손잡이 드래그와 키보드 조작을 함께 제공한다. 이동 위치·취소·자동 스크롤과 실패 시 복구를 확인한다. 트리는 어떤 부모 범위에서 이동 가능한지 제품 규칙을 먼저 정한다.

높이 제한과 본문 스크롤을 함께 확인한다. 위치를 지정한 Dialog에 공통 margin을 더하면 top과 여백이 겹쳐 화면 아래로 밀릴 수 있다. 일반 대화상자의 위치는 부품 기본값을 쓰고, 위쪽에 고정할 패널은 position과 남은 화면 높이를 함께 정한다. 긴 내용은 Layout의 머리·스크롤 본문·바닥으로 나누고 화면이 낮아져도 닫기와 마지막 내용에 닿는지 확인한다.

# 프로젝트 개발 방식 관리

공통 개발 지침은 프로젝트 저장소에 배포한다. 로컬 플러그인의 스킬은 모두 명시적으로 호출할 때만 사용한다. 관리 스킬과 개발 스킬을 함께 제공하지만, 호출하지 않은 개인 개발 규칙을 프로젝트 규칙 대신 적용하지 않는다.

## 실행 위치

이 SKILL.md의 위치에서 `../../scripts/workflow.mjs`를 찾는다. 원본 저장소와 패키지 모두 같은 상대 구조다. Node 22 이상이 필요하고 텍스트 병합에는 Git이 필요하다. 프로젝트 경로는 항상 `--project`로 명시한다.

플러그인의 공통 개발 지침은 직접 호출용이다. 프로젝트에 배포할 때는 install·update의 `--source`에 사용자가 관리하는 goraebap-workflow 체크아웃 경로를 준다. 체크아웃이 없으면 위치를 묻고 임의로 네트워크에서 내려받지 않는다. compare는 기준 스냅샷만으로도 가능하다.

명령과 프로젝트 연결 예시는 [운영 절차](references/operations.md)를 읽는다.

## 지킬 것

- 플러그인 설치는 사용자 범위를 기본으로 한다. Claude의 마켓플레이스 등록과 설치에는 `--scope user`를 명시하고, Codex는 사용자 설정에 마켓플레이스를 등록해 설치한다. 사용자가 다른 범위를 명시했을 때만 그 범위를 쓴다. 프로젝트에 스킬을 배포하는 `install --project`와 플러그인 설치를 구분한다. 팀원에게 플러그인 설치를 필수로 요구하지 않는다.
- 프로젝트의 AGENTS.md·staging·기존 스킬을 확인한다. 기존 스킬을 지우거나 설치로 덮어쓰지 않는다. 기존 프로젝트를 관리 대상으로 등록하는 기능은 아직 없으므로 수동 이관을 설치로 가장하지 않는다.
- update는 먼저 미리보기한다. 사용자가 업데이트를 요청했다면 검토 후 --apply까지 진행하되 의미 충돌·제품 결정은 해결한다. 텍스트 충돌이 있으면 파일·lock은 바뀌지 않는다.
- 프로젝트 수정의 목적지를 project·upstream·trial로 분류한다. 분류 뒤 파일이 다시 바뀌면 분류를 갱신한다.
- propose는 현재 upstream으로 분류된 파일의 로컬 초안만 만든다. 전체 파일이 포함될 수 있으므로 회사 정보·제품 전용 내용·이름 매핑을 검토한다. 원본 자동 수정·외부 전송·PR 생성은 하지 않는다.
- Claude 사본의 직접 수정은 덮어쓰지 않고 `.agents/skills`로 먼저 회수한다. Git과 배포에서 제외한 개발 참고 자료를 스킬이나 제안에 복사하지 않는다.
- 동기화는 이 도구가 관리하는 스킬만 대상으로 한다. 다른 스킬·전역 설정·앱 코드·기존 AGENTS.md를 자동 수정하지 않는다.
- 플러그인이 갱신돼도 프로젝트 지침은 갱신하지 않는다. 프로젝트 업데이트는 기본 수동이며 자동 실행·스케줄 기능은 아직 제공하지 않는다. 자동 업데이트를 원한다는 말만으로 팀 프로젝트나 전역 설정에 훅을 설치하지 않는다.

완료 시 적용 경로·원본 digest·변경·충돌·실행한 검증을 보고한다. 실제 Claude/Codex에서 활성화했는지와 패키지 파일 검증을 구분한다.

# 프로젝트 개발 방식 관리

로컬 플러그인은 사용자 범위에 설치하고 명시적으로 호출한다. 프로젝트의 개발 규칙은 `.agents/skills`가 유일한 원본이며 팀원에게 플러그인 설치를 요구하지 않는다.

## 실행 위치

이 SKILL.md에서 `../../scripts/workflow.mjs`를 찾는다. Node 22 이상과 Git이 필요하다. `--project`에는 에이전트가 확인한 프로젝트 Git 저장소 루트를 준다. 기본 원본은 설치된 플러그인에 포함된 프로젝트용 지침이다. 사용자에게 로컬 원본 경로나 정형 프롬프트를 요구하지 않는다. 개발·시험 원본을 따로 지정한 경우에만 --source를 사용한다. 별도 체크아웃이나 네트워크 다운로드는 필요하지 않다.

## 호출만 한 경우의 온보딩

사용자가 이 스킬만 명시적으로 호출해도 현재 프로젝트를 점검하고 온보딩을 진행한다. 사용법만 답하거나 추가 요청문을 쓰라고 되묻지 않는다. 구체적인 관리 작업을 함께 요청했다면 그 작업을 우선한다.

1. 현재 폴더·Git 루트·status와 staging, AGENTS.md·기존 스킬·시작 훅을 읽는다. 다른 저장소에 설치하지 않는다. Git이 없으면 선택된 프로젝트 폴더가 명확한 경우 그 폴더에 초기화하고, 대상이 모호할 때만 확인한다. 기존 제품·팀 규칙은 유지한다.
2. 대화에서 정한 사용 에이전트와 기존 프로젝트 설정을 확인한다. 확인한 선택을 --agents로 전달해 `onboard --project PROJECT`를 실행한다. CLI는 기존 훅 설정에서도 선택을 감지한다. 단서가 없을 때만 한 번 짧게 사용 에이전트를 질문한다. 현재 실행 환경을 알면 현재 에이전트만 또는 Claude·Codex 함께 쓰기를 선택지로 제시할 수 있다. 원본 경로·접두사·복사 폴더처럼 정해진 기본값은 묻지 않는다.
3. 아래 상태에 맞춰 진행한다.

| 상태 | 수행 |
| --- | --- |
| installed | 신규 지침·동기화 설정이 준비됐다. 새 AGENTS.md를 확인하거나, 반환된 일반 작업 지침을 기존 AGENTS.md의 입구와 충돌 없이 통합한다. sync → sync --check로 마친다. |
| needs-agents | 아직 파일은 바뀌지 않았다. 위 선택만 확인한 뒤 --agents로 다시 실행한다. |
| managed | 기존 기준과 수정 상태를 요약하고 비교·업데이트·동기화 같은 관리 작업을 안내한다. 호출만으로 재설치·갱신하지 않는다. |
| existing-skills | 로컬 기준 없이 기존 지침이 있다. 먼저 내용을 읽는다. 동기화만 필요하면 setup-sync, 기준 복구가 필요하면 실제 채택했던 원본으로 adopt한다. 출처를 추정하거나 기존 입구를 중복 생성하지 않는다. |

4. 명시적인 기존 규칙과 신규 지침이 충돌하면 필요한 선택만 확인한다. 설정 완료 후 일반 개발은 프로젝트 입구를 따르므로 관리 스킬을 매번 호출할 필요가 없다고 안내한다. 자동 커밋·푸시·제품 구현은 온보딩에 포함하지 않는다.

명령과 구성은 [운영 절차](references/operations.md)를 읽는다.

## 지킬 것

- 플러그인 설치의 기본 범위는 사용자다. Claude 등록·설치에 --scope user를 명시하고 Codex는 사용자 설정에 등록한다. 다른 범위는 사용자가 명시했을 때만 선택한다.
- 프로젝트 AGENTS.md·기존 스킬·staging을 확인한다. install은 기존 스킬을 덮어쓰지 않는다. 이미 있는 프로젝트에 동기화 기능만 넣을 때는 setup-sync를 쓴다.
- 관리 기준·분류·제안은 Git이 알려주는 로컬 관리 경로의 goraebap-workflow 아래에 둔다. 리터럴 .git 폴더를 가정하지 않는다. 프로젝트에 관리용 lock이나 플러그인 안내를 생성하지 않는다.
- 프로젝트에는 스킬 원본·독립 동기화 스크립트·시작 훅·사본 폴더의 gitignore와 일반 작업 지침만 공유한다. onboard는 AGENTS.md가 없을 때 만들고 기존 파일은 에이전트가 읽어 프로젝트 입구와 원본/사본 정책만 통합한다. 개인 설치 경로를 프로젝트 파일에 넣지 않는다.
- setup-sync는 기존 훅·권한·설정을 보존한다. 다른 사람이 만든 동기화 도구와 추적 중인 사본을 자동 덮어쓰기·추적 해제하지 않는다. 먼저 원본과 대조하고 통합한다.
- sync는 출처와 관계없이 프로젝트 전체 스킬을 대상으로 한다. 사본의 직접 수정과 다른 소유자의 파일을 보호하고 원본으로 회수하도록 안내한다. skills-lock.json과 외부 도구의 설치 기록을 수정하지 않는다.
- 시작 훅은 네트워크나 개인 플러그인 없이 사본만 준비한다. 공통 원본 업데이트·개선 회수는 별도 관리 작업이다. 훅의 신뢰 승인은 각 사용자가 진행하며, 지원하지 않는 환경에서는 독립 명령을 제공한다.
- clone이나 새 worktree에 관리 기준이 없으면 그 범위를 알린다. 채택했던 원본을 확인해 adopt --source로 등록하고 현재 수정본을 원본이라고 추정하지 않는다. 기존 .workflow 파일은 자동 삭제하지 않는다.
- update는 먼저 미리보기한다. 사용자가 업데이트를 요청했다면 검토 후 --apply까지 진행하되 충돌·제품 선택을 해결한다. 플러그인 갱신이나 시작 훅이 프로젝트 기준을 자동으로 올리지 않는다.
- classify는 project·upstream·trial과 이유를 현재 파일 해시에 연결한다. propose는 현재 upstream 변경의 로컬 초안만 만든다. 회사 정보·전체 본문·이름 대응을 검토하고 공통 원본은 별도 요청으로 반영한다.

완료 시 공유 파일·로컬 메타데이터 위치·선택한 에이전트·충돌·검증을 보고한다. 파일 생성, 훅 명령 실행, 실제 세션의 승인·실행을 구분한다. 커밋·푸시·전역 설치는 요청 범위에서만 수행한다.

화면을 만들거나 검토하기 전에 그 화면이 어느 유형에 속하는지 먼저 정합니다. 화면의 목적과 구조에 따라 적용하는 규칙집이 다릅니다. 개발자와 에이전트는 화면 유형을 먼저 고른 뒤 해당 규칙집의 기준을 따릅니다.

한 제품 안에서도 화면마다 따르는 규칙집이 다를 수 있습니다. 예를 들어 로그인 전 마케팅 페이지와 로그인 뒤 업무 화면은 같은 제품에 속하더라도 서로 다른 규칙집을 따릅니다.

## 화면 유형 비교

만들려는 화면의 역할과 구조에 맞춰 규칙집을 고릅니다.

| 화면 유형 | 구조와 특징 | 대상 예시 | 규칙집 상태 |
| --- | --- | --- | --- |
| 앱 셸 (사이드바 레이아웃, 애플리케이션 셸) | 로그인 뒤 사이드바(탐색)와 콘텐츠 영역으로 이루어진 업무 도구 | Linear, Plane, 연차관리 같은 SaaS 앱 | 작성됨 ([앱 셸 개요](/app-shell/overview/)) |
| 랜딩 (마케팅 사이트) | 히어로, 섹션 흐름, 행동 유도가 중심인 화면 | 로그인 전 제품 소개·마케팅 페이지 | 미정 ([랜딩](/landing/)) |
| 문서 사이트 | 문서를 읽고 탐색하는 화면 | 가이드, 참고 문서 | 미정 |

## 유형별 판단 기준

### 앱 셸을 고르는 경우

로그인 뒤에 들어가며, 왼쪽 사이드바에 탐색 메뉴를 두고 오른쪽 본문 영역에서 목록·표·보드·상세·설정 같은 업무 화면을 다루면 [앱 셸 규칙집](/app-shell/overview/)을 따릅니다.

- [관례] 셸은 사이드바(탐색)와 콘텐츠 영역 두 부분으로 나누고, 머리 줄과 툴바는 고정한 채 본문만 스크롤합니다. 페이지마다 셸을 새로 만들지 않습니다. ([셸과 사이드바](/app-shell/shell-and-sidebar/))
- [고래밥] 목록 옆 미리보기 패널이나 라우트 마스킹처럼 관례가 하나로 수렴하지 않은 동작은 우리 결정과 이유를 적은 계약을 따릅니다. ([결정 기록](/start/decisions/), [표현 고르기](/app-shell/choosing-presentation/))
- [선호] 바탕 위에 떠 있는 둥근 페이지 카드(Inset)나 선으로만 나눈 면(Split) 같은 시각적 모양은 기능 규칙과 구분해 둡니다. ([선호하는 화면 모양](/app-shell/preferred-screens/))

각 표시(`[관례]`, `[고래밥]`, `[선호]`)를 읽고 바꾸는 기준은 [규칙집 읽는 법](/start/how-to-read/)에서 설명합니다.

### 랜딩이나 문서 사이트를 고르는 경우

히어로와 섹션 흐름을 따라 행동을 유도하는 마케팅 페이지는 앱 셸과 목적이 다르므로 앱 셸의 고정 사이드바·툴바 규칙을 그대로 적용하지 않습니다. 문서 사이트도 별도 규칙집으로 다룹니다.

랜딩과 문서 사이트의 구체적인 설계 규칙은 아직 정하지 않았습니다(미확정). 앞으로 새 화면 유형의 규칙을 정하면 사이드바에 해당 규칙집 묶음을 하나씩 더합니다.

앱 셸 규칙이 어디서 나왔는지 확인할 때 이 문서를 읽습니다. 실제 업무 도구인 Linear·Plane과 공개 디자인 지침(Primer, Atlassian, Apple HIG, Android 개발자 문서, Carbon, NN/g, Smashing, Refactoring UI 등)을 같은 주제로 나란히 놓고, 공통으로 수렴하는 지점과 고래밥의 판단을 비교했습니다.

각 항목에는 규칙의 성격을 함께 표시합니다. 구분 기준은 [읽는 법](/start/how-to-read/)을 따릅니다.

- `[관례]`: 여러 제품과 지침이 같은 방향으로 수렴한 규칙입니다.
- `[고래밥]`: 뚜렷한 관례가 없거나, 공개 지침과 다르게 정한 우리 결정입니다.
- `[선호]`: 기능 계약이 아니라 시각적 취향으로 고른 모양입니다.

표의 마지막 열('고래밥 키트')은 2026-11-07 조사 시점의 키트 구현 상태입니다. 조사 직후 내린 결정으로 규칙이 바뀐 항목은 표 안에 함께 적고, 문서 끝의 [지침과 다르게 정한 곳과 이후 결정](#지침과-다르게-정한-곳과-이후-결정)과 [결정 기록](/start/decisions/)에 따로 정리했습니다. 표에 언급한 출처 링크는 [레퍼런스 읽기 목록](/references/reading-list/)에 있습니다.

원문을 확인하지 못했거나 공개 자료가 없는 항목은 '미확인'으로 적었습니다.

- Linear 웹 앱의 실제 픽셀 수치(사이드바 폭, 행 높이, 모달 크기)는 공개 자료에 없어 확인하지 못했습니다.
- Linear의 미리보기(peek)·모바일 문서는 일부 페이지가 열리지 않아(404) 검색 요약만 확인했습니다.
- Material 3 원문은 스크립트 렌더링 문제로 본문을 확인하지 못해 Android 개발자 문서로 대체했습니다.
- Refactoring UI는 본문 대신 요약 자료만 확인했습니다.

| 항목 | Linear | Plane | 지침 | 수렴 및 성격 | 고래밥 키트 |

| 상세 화면 배치 | 본문 + 오른쪽 속성 패널 | 미리보기 본문 + 속성 | Android 보조 패널 70:30 비율 | `[관례]` 읽기 본문 열 옆에 오른쪽 속성 열을 두고, 영역이 좁아지면 속성을 제목 아래로 옮깁니다 | 읽기 열 45rem(720px) + 속성 열 16rem(256px) 적용됨 |

| 휴대폰 상세·작성 | 네이티브 앱만 제공 | 미리보기 대신 페이지로 이동 | Primer: 입력이 있는 대화상자는 휴대폰에서 전체 화면으로 연다 | `[관례]` 휴대폰에서는 미리보기나 마스킹 없이 바로 페이지(전체 화면)로 엽니다 | 페이지 이동 적용됨 |
| 모달 중첩 | — | — | Apple·Atlassian·NN/g 중첩 금지, Primer 최대 3단계 | `[관례]` 모달 위에 다른 작업 모달을 중첩하지 않습니다(닫기 확인 창만 예외) | 확인 창만 위에 허용 (적용됨) |
| 닫을 때 입력 손실 방지 | 자동 임시 저장 | — | Apple: 입력이 사라질 때 사용자에게 확인 | `[관례]` 임시 저장하거나 버릴지 묻습니다 | 닫기 전 확인 창 적용됨 |

## 5. 적응형(휴대폰)

관련 규칙은 [적응형](/app-shell/adaptive/)에서 다룹니다. Linear와 Plane은 웹에서 휴대폰 전용 탐색을 거의 설계하지 않았으므로 이 영역은 모바일 플랫폼 지침과 `[고래밥]` 결정의 비중이 큽니다.

| 항목 | Linear | Plane | 지침 | 수렴 및 성격 | 고래밥 키트 |
| --- | --- | --- | --- | --- | --- |
| 휴대폰 주 탐색 | 네이티브 앱은 2025-10 하단 툴바 도입, 웹 모바일 설계 없음 | 사이드바 접힘(하단 탭 확인 안 됨) | Android: 좁으면 하단 바, 넓으면 레일. NN/g: 탭 바 4~5개를 항상 노출 | `[관례]` 데스크톱 사이드바를 휴대폰에서는 4~5칸 하단 탭으로 바꿉니다 | 하단 탭 4칸 + 더보기 적용됨 |
| 더보기 탭 | 개인화로 숨김 | — | Apple: More 탭 같은 오버플로를 피하라. Android·NN/g: 5개 상한만 제시 | `[고래밥]` 업무 도구는 목적지가 5개를 넘는 경우가 많아, 숨긴 햄버거 메뉴보다 눈에 보이는 '더보기' 탭과 바텀시트를 씁니다(Apple HIG와 다른 결정) | 더보기 바텀시트 적용됨 |

## 지침과 다르게 정한 곳과 이후 결정

조사 과정에서 공개 지침과 충돌하거나 관례가 갈렸던 6가지 쟁점과, 2026-11-07에 확정한 결론입니다. 각 결정의 배경과 대안 비교는 [결정 기록](/start/decisions/)에서 확인할 수 있습니다.

1. **휴대폰 상세·작성·대화 화면에서 하단 탭 숨김 (`[고래밥]` 결정 유지)**
   - Apple HIG는 모달이 덮을 때를 빼면 하단 탭 바를 숨기지 말라고 권합니다. 그러나 휴대폰 웹 브라우저는 주소창과 가상 키보드로 세로 공간이 크게 줄고, 작성·상세 화면 바닥에는 제출이나 주요 동작 줄이 놓여야 합니다. 따라서 내용에 집중하거나 키보드를 쓰는 화면에서는 하단 탭을 치우고 상단에 '← 이름 + 도구', 하단에 동작 줄을 둔 전체 화면으로 엽니다([적응형](/app-shell/adaptive/)).
2. **휴대폰 하단 탭에 '더보기' 배치 (`[고래밥]` 결정 유지)**
   - Apple HIG는 More 탭 같은 오버플로를 피하라고 하고, Android와 NN/g는 탭 개수를 4~5개로 제한하라고만 안내합니다. 업무 도구는 최상위 목적지가 5개를 넘는 일이 잦은데, 숨긴 햄버거 메뉴는 발견성이 크게 떨어집니다(NN/g 조사에서 사용률 27% vs 48%). 앞 네 곳은 탭에 두고 나머지는 눈에 보이는 '더보기' 바텀시트로 여는 쪽을 택했습니다([적응형](/app-shell/adaptive/)).
3. **작성 양식의 라우트 마스킹 (`[고래밥]` 결정 유지)**
   - Linear·Plane은 작성 양식을 모달로 열고, Primer는 링크로 공유할 대상은 페이지로 열라고 권합니다. 데스크톱 목록에서 열 때는 목록 맥락을 유지하는 대화상자로 띄우되 주소창에는 실제 페이지 주소를 넣고, 새로고침·직접 진입·휴대폰에서는 페이지로 여는 [라우트 마스킹](/app-shell/route-masking/)으로 두 요구를 함께 충족합니다.
4. **필수 값이 비어 있을 때 제출 버튼 비활성화 해제 (`[관례]` 수용으로 변경, 2026-11-07)**
   - 조사 시점의 키트는 필수 입력이 비면 제출 버튼을 비활성화했습니다. 하지만 비활성 버튼은 키보드 초점이 닿지 않고 왜 누를 수 없는지 알려 주지 못합니다. Primer의 저장 지침을 따라 제출 버튼은 활성 상태로 두고, 누르면 빠진 칸 곁에 오류를 표시한 뒤 첫 번째 빠진 칸으로 초점을 옮기기로 바꾸었습니다([상태와 피드백](/app-shell/states-and-feedback/)). 현재 키트의 작성 양식과 예제는 이 기준으로 수정할 대상입니다.
5. **짧은 완료 알림에 토스트 제한적 사용 (`[고래밥]` 결정 확정, 2026-11-07)**
   - Primer는 토스트 사용 자체를 권하지 않고, Atlassian은 자동으로 사라지는 알림에 중요한 내용을 넣지 말라고 합니다. 우리는 화면에서 결과가 바로 확인되면 알림을 생략하되, 주소 복사·보관·백그라운드 작업 시작처럼 화면에 즉각 변화가 보이지 않는 짧은 완료나 '되돌리기' 동작 하나를 제공하는 완료에만 토스트를 쓰기로 정했습니다([상태와 피드백](/app-shell/states-and-feedback/)). 오류와 경고는 토스트에 두지 않습니다.
6. **미리보기(peek) 패널 도입과 주소 반영 (`[고래밥]` 결정 확정, 2026-11-07)**
   - 조사 시점의 키트에는 Linear·Plane의 핵심 패턴인 목록 옆 미리보기 패널이 없었습니다. 목록을 유지한 채 항목을 차례로 훑는 비모달 [미리보기](/app-shell/peek/) 패널을 추가하되, 상태를 클라이언트 스토어에만 두어 새로고침·공유가 되지 않는 Plane과 달리 목록 주소 쿼리(`?peek=대상ID`)에 상태를 남기기로 결정했습니다. 처리 목록(받은 항목, 승인 대기 등)은 행을 누르면 미리보기가 열리고, 작업 목록(업무, 문서 등)은 행을 누르면 페이지로 가며 Space 키나 미리보기 버튼으로 패널을 엽니다.

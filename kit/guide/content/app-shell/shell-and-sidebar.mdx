로그인 뒤 사이드바와 콘텐츠 영역으로 이루어진 업무용 웹 앱의 외곽 틀(셸)과 좌측 탐색 영역을 설계하거나 검토할 때 이 규칙을 적용합니다. 특정 UI 라이브러리의 부품 이름이 아니라 화면에서의 역할(셸, 사이드바, 머리 줄, 툴바, 본문)을 기준으로 판단합니다.

각 규칙은 성격에 따라 세 가지로 표시합니다([읽는 법](/#규칙의-세-가지-표시) 참고).

- **[관례]**: 여러 제품과 디자인 시스템 지침이 같은 방향으로 수렴한 기준입니다.
- **[고래밥]**: 뚜렷한 관례가 없거나 관례와 다르게 정한 결정입니다. 판단 이유를 함께 적습니다.
- **[선호]**: 기능 규칙이 아니라 시각적 취향으로 고른 모양입니다.

## 셸을 고정하고 본문만 스크롤한다

**[관례]** 셸은 좌측의 사이드바(탐색)와 우측의 콘텐츠 영역 두 부분으로 나눕니다. 앱 전체에서 셸은 한 번만 두고 페이지마다 새로 그리지 않습니다. 콘텐츠 영역 안에서는 상단의 머리 줄과 툴바를 자리에 고정하고, 그 아래 본문 영역만 스크롤합니다. 머리 줄과 툴바의 상세 규칙은 [머리 줄과 툴바](/app-shell/header-and-toolbar/)에서 다룹니다.

이동할 때마다 외곽 틀이 다시 그려지거나 상단 도구가 스크롤에 밀려 사라지면 현재 위치와 페이지 동작을 잃기 쉽습니다. Linear는 사이드바와 상단 헤더가 만나는 "뒤집힌 L자" 프레임을 고정하고 본문을 중심에 두며([How we redesigned the Linear UI](https://linear.app/now/how-we-redesigned-the-linear-ui)), Plane도 바깥 프레임 안에 사이드바와 본문을 고정합니다. Atlassian 지침([Navigation system layout](https://atlassian.design/components/navigation-system/layout/examples)) 역시 최상위 루트 아래에 각 영역을 직계로 배치하고 본문만 스크롤하도록 규정합니다(Atlassian의 상단바 높이는 48px입니다).

## 본문을 시각의 중심에 두고 셸 배치를 고른다

**[관례]** 사이드바는 본문보다 시각적으로 한 단계 뒤로 물러난 면으로 처리합니다. 사용자의 작업이 일어나는 본문이 화면의 주인공이어야 하기 때문입니다([Linear: Behind the latest design refresh](https://linear.app/now/behind-the-latest-design-refresh)). 표면의 명도 단계와 경계선 기준은 [시각 위계](/common/visual-hierarchy/)를 따릅니다.

**[선호]** 셸의 외곽 배치는 다음 두 가지 모양을 제공합니다([선호 화면](/app-shell/preferred-screens/) 참고).

- **Inset**: 옅은 바탕 면 위에 본문 영역을 16px 둥근 모서리의 페이지 카드로 띄우는 배치입니다. 사이드바 머리와 페이지 머리 줄의 높이를 같은 선에 맞춥니다.
- **Split**: 바탕 면의 높이 차이를 두지 않고 사이드바와 본문을 경계선으로만 나누는 배치입니다.

## 데스크톱 사이드바는 기본으로 펼쳐 둔다

**[관례]** 데스크톱 화면에서는 사이드바를 기본으로 펼쳐 두어 주요 탐색 경로가 바로 보이게 합니다. 사용자가 공간을 넓히고 싶을 때 직접 접을 수 있게 하되, 접은 상태에서는 아이콘만 남기거나 포인터를 올렸을 때(hover) 사이드바를 잠깐 펼쳐서 이동할 수 있게 합니다.

처음부터 메뉴를 햄버거 버튼 뒤로 숨기면 탐색 경로를 찾는 비용이 커집니다. NN/g의 실험([Hamburger menus](https://www.nngroup.com/articles/hamburger-menus/))에서 데스크톱의 숨긴 내비게이션 사용률은 27%로, 눈에 보이는 내비게이션(48%)보다 절반 가까이 낮았습니다. Apple HIG([Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars))도 사이드바를 기본으로 숨기지 않고 사용자가 직접 숨기기를 선택하도록 안내합니다.

## 사이드바 폭은 340px에서 시작하고 끌어서 조절한다

**[관례]** 사이드바 기본 폭은 250~340px 사이에서 시작하고, 사용자가 경계를 끌어서 폭을 조절할 수 있게 합니다. 최소 폭은 220~256px 선을 지킵니다.

**[고래밥]** 기본 폭은 **340px**, 사용자 조절 범위는 **220~380px**로 합니다(2026-11-07 결정).

메뉴 이름과 2단계 하위 항목을 말줄임표 없이 한눈에 읽을 수 있도록 기본 폭을 넉넉하게 잡았습니다. 다른 제품이나 지침(250~320px)보다 기본 폭이 넓은 편이어서, 화면이 좁은 노트북에서 목록 옆에 [미리보기 패널](/app-shell/peek/)을 함께 열면 목록 영역이 좁아지는 대가가 따릅니다. 이 경우에는 사용자가 사이드바를 220px까지 줄이거나 접어서 본문 폭을 확보하도록 합니다.

화면 폭이 **1024px(64rem)** 미만이 되면 데스크톱 사이드바를 유지하지 않고 휴대폰·태블릿 세로용 하단 탭 탐색으로 전환합니다(**[고래밥]**). 전환 분기점을 1024px보다 작게 잡으면 태블릿 세로 화면에서 사이드바와 터치 크기가 섞이기 때문입니다. 좁은 화면에서의 탐색 전환 규칙은 [적응형](/app-shell/adaptive/)에서 다룹니다.

| 비교 대상 | 기본 폭과 조절 범위 | 접기 동작 | 좁은 화면 전환 기준 |
| --- | --- | --- | --- |
| Linear | 공개 자료에서 px 수치 미확인 | 접기 지원(세부 동작 미확인) | 웹 모바일 설계 없음 |
| Plane | 기본 250px, 폭 조절 및 상태 저장([사이드바 소스](https://github.com/makeplane/plane/blob/preview/apps/web/app/(all)/[workspaceSlug]/(projects)/_sidebar.tsx)) | 접힘 상태에서 hover로 잠깐 펼침 | 768px 미만에서 자동 접힘 |
| Atlassian | 기본 320px, 범위 240px~화면 폭의 50%([Navigation system layout](https://atlassian.design/components/navigation-system/layout/examples)) | 접기 토글·단축키·hover 오버레이 펼침 | 1024px 미만에서 오버레이로 전환 |
| GitHub Primer | 최소 256px([PageLayout](https://primer.style/components/page-layout)) | 지침 별도 표기 없음 | 768px 기준 반응형 전환 |
| 우리 규칙 | 기본 340px, 범위 220~380px | 기본 펼침, 접으면 아이콘 또는 hover 펼침 | 1024px(64rem) 미만에서 하단 탭으로 전환 |

## 위에서 아래로 역할을 나누고 계층은 2단계까지만 둔다

**[관례]** 사이드바 안의 항목은 위에서 아래로 다음 순서로 배치합니다.

1. **작업 공간**: 로고와 작업 공간 전환 메뉴를 맨 위에 둡니다.
2. **개인 영역**: 받은 항목, 내 일처럼 사용자 개인에게 할당된 흐름을 그 아래에 둡니다.
3. **작업 대상 묶음**: 프로젝트, 팀, 주요 기능 목록을 가운데 영역에 둡니다.
4. **설정과 도움말**: 자주 바꾸지 않는 보조 진입점을 아래쪽에 둡니다.

**[관례]** 사용자가 자주 쓰거나 중요한 동작을 사이드바 맨 아래에만 두지 않습니다([Apple HIG: Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars)).

**[관례]** 사이드바의 트리 계층은 최대 **2단계**까지만 둡니다(예: Linear의 팀 > 뷰, Plane의 프로젝트 > 하위 항목). Apple HIG, Carbon, Primer 모두 사이드바 계층을 2단계 이하로 제한합니다. 3단계 이상의 깊은 분류가 필요할 때는 사이드바 안에서 트리를 더 쪼개지 않고, 해당 항목을 열어 페이지 안의 탭이나 뷰로 나눕니다([머리 줄과 툴바](/app-shell/header-and-toolbar/) 참고).

한편 Linear는 사용자가 사이드바 항목 순서를 바꾸거나 덜 쓰는 항목을 More 뒤로 숨기는 개인화 기능을 제공하고([Personalized sidebar](https://linear.app/changelog/2024-12-18-personalized-sidebar)), Plane은 즐겨찾기 섹션을 둡니다. 이러한 개인화는 앱의 복잡도에 따라 추가하는 선택 기능으로 보며 기본 필수 규칙으로 강제하지 않습니다.

## 하위 공간은 주 메뉴를 대체하고 돌아가기 링크를 둔다

**[고래밥]** 내 계정이나 관리(설정)처럼 주 작업 공간과 성격이 다른 하위 공간으로 들어갈 때는 사이드바의 주 메뉴를 하위 공간의 전용 메뉴로 대체합니다. 이때 사이드바 맨 위에는 원래 공간으로 돌아가는 `← 공간 이름` 동작을 둡니다.

기존 사이드바 옆에 설정용 보조 사이드바를 한 겹 더 붙이면 탐색 열이 두 겹으로 쌓여 본문 폭을 잠식하고 시선이 분산됩니다. 주 메뉴 자체를 교체하고 상단에 명확한 복귀 경로를 두면 2단계 계층 한도와 본문 폭을 그대로 유지할 수 있습니다.

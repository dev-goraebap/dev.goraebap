목록을 유지한 채 여러 항목을 차례로 훑을 때는 데스크톱 본문 옆에 비모달 미리보기 패널(peek)을 엽니다. 이 문서는 미리보기 패널의 주소·방문 기록·폭 규칙과, 목록에서 행을 눌렀을 때 미리보기 패널과 대상 페이지 중 무엇을 열지 판단하는 기준을 다룹니다. 대화상자·라우트 마스킹·페이지 중 무엇을 쓸지 고르는 상위 기준은 [표현 고르기](/app-shell/choosing-presentation/)와 [라우트 마스킹](/app-shell/route-masking/)을 따릅니다.

규칙마다 성격을 함께 적습니다. `[관례]`는 여러 제품과 지침이 수렴한 기준이고, `[고래밥]`은 관례가 없거나 관례와 다르게 정한 결정입니다.

## 왜 주소에 남기는가

- `[관례]` 목록의 맥락을 잃지 않고 항목을 참조하거나 비교해야 할 때는 바닥 화면을 가리지 않는 비모달 패널을 씁니다([Smashing Magazine: Modal vs separate page decision tree](https://www.smashingmagazine.com/2026/03/modal-separate-page-ux-decision-tree/)).
- Linear는 목록에서 `Space` 키로 미리보기 패널을 열고 닫으며, `J`·`K` 키로 행을 이동할 때 패널 내용이 함께 바뀝니다(원문 문서 일부가 404 상태여서 검색 요약으로 확인했습니다. 실제 화면의 패널 폭 px 수치도 공개 자료에 없어 미확인입니다).
- Plane은 오른쪽 50%(`side-peek`, 기본), 모달 5/6, 전체 화면의 세 가지 모드를 두고([Plane 미리보기 소스](https://github.com/makeplane/plane/blob/preview/apps/web/components/issues/peek-overview/view.tsx)), 휴대폰에서는 미리보기 대신 상세 페이지로 이동합니다([Plane 휴대폰 이동 훅 소스](https://github.com/makeplane/plane/blob/preview/apps/web/hooks/use-issue-peek-overview-redirection.tsx)). 다만 웹 앱에서 패널의 열림 상태를 스토어에만 두고 주소에 반영하지 않아 뒤로가기·새로고침·링크 공유가 동작하지 않습니다.
- `[고래밥, 2026-11-07 결정]` Linear·Plane처럼 목록 옆에서 항목을 훑는 미리보기 패널을 두되, 뒤로가기·새로고침·공유에서 같은 화면이 열리도록 패널 대상을 주소 쿼리(`?peek=대상ID`)에 남깁니다.

## 미리보기 패널 동작 계약

`[고래밥, 2026-11-07 결정]` 미리보기 패널을 구현할 때는 아래 8가지 계약을 지킵니다.

1. 목록 주소에 `?peek=대상ID`를 더합니다. 목록에 적용된 다른 조건([검색·필터·표시](/app-shell/filters-and-display/))은 그대로 유지합니다.
2. 목록에서 미리보기를 처음 열 때는 브라우저 방문 기록을 하나 쌓습니다(`push`). 사용자가 뒤로가기를 누르면 패널이 닫히고 이전 목록 상태로 돌아옵니다.
3. 패널이 이미 열린 상태에서 다른 행을 선택하거나 위·아래 방향키로 이동할 때는 방문 기록을 쌓지 않고 현재 주소를 바꿉니다(`replace`). 여러 항목을 연달아 확인한 뒤에도 뒤로가기 한 번이면 목록으로 돌아옵니다.
4. 새로고침하거나 공유받은 링크로 `?peek=대상ID`가 들어오면 목록과 패널을 함께 엽니다. 해당 대상을 찾을 수 없으면 목록은 그대로 두고 패널 자리에만 "찾을 수 없음" 상태를 보여 줍니다.
5. 패널 안의 "페이지로 열기"를 누르면 대상의 자기 주소로 이동합니다. 미리보기 패널과 대상 페이지는 같은 데이터 조회와 같은 본문 구성을 씁니다.
6. 휴대폰 폭([적응형 분기점](/app-shell/adaptive/) 1024px 미만)에서 `?peek=대상ID` 주소로 들어오면 패널을 그리지 않고 대상의 자기 주소로 바꿔 이동합니다(`replace`).
7. 패널은 비모달로 열려 목록 조작을 막지 않습니다. 목록에는 현재 미리보기 중인 행을 강조해 표시합니다([Plane 목록 행 소스](https://github.com/makeplane/plane/blob/preview/apps/web/components/issues/issue-layouts/list/block.tsx)). `Esc` 키와 패널의 닫기 버튼으로 닫습니다.
8. 패널 폭은 본문 영역의 약 40~50%를 차지합니다. 본문 영역이 좁아 목록과 패널을 나란히 두기 어려우면 미리보기 대신 대상 페이지로 엽니다. 좁은 노트북 화면에서 패널을 함께 열 때 목록이 좁아지는 문제는 사용자가 [사이드바](/app-shell/shell-and-sidebar/) 폭을 줄이거나 접어서 조절합니다.

## 행을 누르면 무엇이 열리나

`[고래밥, 2026-11-07 결정]` 목록에서 행을 눌렀을 때 미리보기 패널을 열지, 대상의 자기 페이지로 갈지는 그 목록이 무엇을 하는 곳인지로 정합니다. 한 목록 안에서는 한 가지 동작으로 통일합니다.

| 목록의 성격 | 해당 화면 예 | 행 클릭 기본 동작 | 행 링크의 주소 | 미리보기를 여는 다른 방법 |
| --- | --- | --- | --- | --- |
| **처리 목록**: 여러 항목을 연달아 확인하고 판단합니다 | 받은 항목, 알림, 승인 대기, 검토 요청 | 미리보기 패널 | 목록 주소 + `?peek=ID` | 위·아래 방향키로 행 이동 |
| **작업 목록**: 항목 하나를 골라 들어가 일합니다 | 업무, 문서, 자료 | 대상 페이지 | 대상의 자기 주소 | `Space` 키, 행 끝의 미리보기 버튼(데스크톱에서 포인터를 올리면 보이고 키보드 초점으로 닿음) |

### 행 링크와 예외 기준

- `[관례]` 처리 목록이든 작업 목록이든 행은 실제 링크로 만듭니다. 행 전체를 링크 요소로 감싸지 않고 제목 링크의 클릭 영역을 행 전체로 늘리며, 행 안의 다른 링크나 버튼(담당자, 별표, 행 메뉴, 미리보기 버튼)은 그 위로 올려 따로 누를 수 있게 합니다([Inclusive Components: Cards](https://inclusive-components.design/cards/), [Adrian Roselli: Block links](https://adrianroselli.com/2020/02/block-links-cards-clickable-regions-etc.html), [컬렉션 행 규칙](/app-shell/collections/)). 새 탭으로 열기나 주소 복사는 그 행 링크에 걸린 주소를 그대로 따릅니다.
- `[고래밥]` 휴대폰 폭에서는 미리보기 패널을 두지 않으므로 처리 목록과 작업 목록 모두 행을 누르면 대상 페이지로 이동합니다.
- `[고래밥]` 목록의 성격이 처리 목록인지 작업 목록인지 애매할 때는 작업 목록으로 판단합니다. 행 클릭은 대상 페이지 이동을 기본으로 두고, 미리보기 패널은 `Space` 키와 행 끝 버튼으로만 열게 합니다.

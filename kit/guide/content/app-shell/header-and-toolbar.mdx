페이지 상단에 경로·제목·뷰·도구·주요 동작을 배치하는 규칙입니다. [셸과 사이드바](/app-shell/shell-and-sidebar/)에서 정한 콘텐츠 영역의 맨 위를 다루며, 머리 줄과 툴바는 화면 위에 고정하고 본문만 스크롤합니다. 화면을 설계하거나 검토할 때 상단 요소를 몇 줄로 나눌지, 어떤 도구를 어디에 둘지 이 기준으로 판단합니다.

규칙 앞의 `[관례]`, `[고래밥]`, `[선호]` 표시는 [규칙 읽는 법](/#규칙의-세-가지-표시)을 따릅니다.

## 위에서 아래로 쌓는 순서

콘텐츠 영역 상단은 필요한 요소가 있을 때만 위에서 아래 순서로 자리를 차지합니다.

1. **머리 줄**: 현재 위치(경로·제목)와 페이지 동작을 둡니다. 모든 페이지에 하나씩 있습니다.
2. **배너 자리**: 페이지 전체의 상태나 오류를 알립니다. 알릴 내용이 있을 때만 나타납니다.
3. **툴바**: 뷰·탭 전환과 목록 조회 도구를 둡니다. 뷰나 탭이 있는 화면에만 따로 둡니다.
4. **필터 적용 줄**: 현재 걸려 있는 필터 조건을 칩으로 보여 줍니다. 활성화된 필터가 있을 때만 나타납니다.

`[고래밥]` 페이지 전체에 영향을 주는 상태나 오류 안내는 머리 줄 바로 아래, 툴바 위의 배너 자리에 둡니다([상태와 피드백](/app-shell/states-and-feedback/)). 안내할 내용이 없으면 빈 여백을 남기지 않고 자리 자체를 그리지 않습니다.

## 머리 줄에 위치와 페이지 동작을 둔다

`[관례]` 페이지마다 머리 줄은 하나만 둡니다([Atlassian Page header](https://atlassian.design/components/page-header/usage)). 왼쪽에는 현재 위치(경로와 페이지 제목)를 두고, 오른쪽에는 이 페이지의 주요 동작을 둡니다.

`[관례]` 머리 줄 오른쪽의 동작 위치는 모든 페이지에서 일관되게 유지합니다([Linear](https://linear.app/now/behind-the-latest-design-refresh), [Atlassian](https://atlassian.design/components/page-header/usage)). 페이지를 옮겨 다녀도 만들기나 주요 명령이 같은 자리에 있어야 시선과 포인터를 다시 찾지 않습니다. 화면 폭이 좁아져 동작을 다 보여 줄 수 없으면 보조 동작을 오버플로 메뉴로 묶습니다([Primer PageHeader](https://primer.style/product/components/page-header/guidelines/)).

### 경로는 3단계 이상일 때만 쓴다

`[관례]` 상위 계층을 보여 주는 경로(Breadcrumbs)는 깊이가 3단계 이상일 때만 둡니다([NN/g Breadcrumbs](https://www.nngroup.com/articles/breadcrumbs/)). 사이드바에서 바로 들어오는 1~2단계 화면에는 경로를 중복해서 적지 않고 페이지 제목만 씁니다.

`[관례]` 경로를 쓸 때 현재 페이지는 맨 끝에 링크 없이 표시합니다(NN/g). 화면이 좁아지면 전체 경로를 줄바꿈하거나 말줄임하지 않고, 바로 위 단계로 돌아가는 부모 링크(`← 위 단계`) 하나로 줄입니다([Primer PageHeader](https://primer.style/product/components/page-header/guidelines/)).

## 뷰가 있는지 보고 도구 자리를 정한다

사이드바 탐색은 2단계까지만 두고, 그보다 깊은 분류나 저장된 보기는 페이지 안의 탭이나 뷰로 나눕니다([셸과 사이드바](/app-shell/shell-and-sidebar/)). 페이지에 뷰·탭이 있는지에 따라 조회 도구가 놓이는 줄이 달라집니다.

| 페이지 구성 | 머리 줄 오른쪽 | 툴바 (머리 줄 아래) |
| --- | --- | --- |
| 뷰·탭이 없는 페이지 | 검색 → 필터 → 표시, 넓은 간격 뒤 만들기 | 두지 않음 |
| 뷰·탭이 있는 페이지 | 페이지 주요 동작(만들기 등) | 왼쪽에 뷰·탭, 오른쪽에 검색 → 필터 → 표시 |

`[고래밥]` 뷰가 없는 화면에서는 빈 툴바 줄을 따로 만들지 않고 검색·필터·표시 도구를 머리 줄 오른쪽에 함께 둡니다. 뷰나 탭이 있을 때만 머리 줄 아래에 툴바를 만듭니다.

`[관례]` 뷰나 탭은 툴바 왼쪽에 둡니다. 각 뷰·탭마다 고유한 주소(URL)를 부여해 새로고침이나 링크 공유로 같은 화면에 바로 들어올 수 있게 합니다. 탭에는 아이콘만 단독으로 쓰지 않고 이름을 함께 적으며, 탭 줄을 두 겹으로 쌓지 않습니다(Primer UnderlineNav).

## 검색·필터·표시를 나누고 순서대로 묶는다

`[관례]` 목록을 다루는 도구는 역할에 따라 세 가지로 나누고 한 메뉴에 섞지 않습니다([Linear Display options](https://linear.app/docs/display-options), [필터와 표시](/app-shell/filters-and-display/)). Carbon 디자인 시스템은 툴바에 놓는 전역 동작을 최대 5개까지로 제한합니다([Carbon Data table](https://carbondesignsystem.com/components/data-table/usage/)).

| 도구 | 역할 | 적용했을 때 상단 변화 |
| --- | --- | --- |
| 검색 | 입력한 글자로 대상을 좁힙니다 | 버튼이 그 자리에서 입력 칸으로 펼쳐지고 닫아도 검색어가 남습니다 `[선호]` |
| 필터 | 속성 값으로 무엇을 보일지 거릅니다 | 툴바 아래에 적용 칩 줄이 생깁니다 `[관례]` |
| 표시 | 레이아웃·정렬·그룹·보일 속성 등 어떻게 보일지 정합니다 | 칩 줄을 만들지 않고 표시 버튼에만 기본과 다름을 표시합니다 `[관례]` |

`[고래밥]` 도구는 언제나 **검색 → 필터 → 표시** 순서로 놓고, 세 버튼을 같은 좁은 간격으로 묶습니다. **만들기** 버튼은 그보다 넓은 간격을 띄운 뒤 머리 줄의 맨 오른쪽 끝에 둡니다. 화면을 좁히고 고르는 조회 도구 셋과 새 항목을 추가하는 생성 동작을 간격과 자리로 구분하기 위해서입니다.

`[관례]` 필터를 하나 이상 적용하면 툴바 아래에 적용 칩 줄이 나타납니다([Linear Filters](https://linear.app/docs/filters)). 각 칩에서 조건을 바꾸거나 지울 수 있게 하고, 줄 끝에 모두 지우기 동작을 둡니다. 반면 표시 옵션(정렬, 그룹, 레이아웃 등)만 바꾼 경우에는 칩 줄을 추가하지 않습니다. 대신 표시 도구 버튼에 기본값과 다르다는 표시를 하고, 표시 메뉴 안에 초기화 버튼을 둡니다.

## 높이와 모양

아래 수치와 모양은 기능 규칙이 아니라 일관된 인상을 위한 `[선호]` 기준입니다([선호 화면](/app-shell/preferred-screens/)).

- 머리 줄 높이는 52px, 툴바 높이는 44px(휴대폰은 52px)로 맞춥니다. 참고한 지침 중 Atlassian의 상단바는 48px이고, Linear 웹 화면의 실제 머리 줄·툴바 px 수치는 공개 자료에 없어 확인하지 못했습니다.
- 검색·필터·표시 도구는 둥근 아이콘 버튼을 씁니다(데스크톱 28px, 휴대폰 44px). 검색어나 필터가 걸려 있거나 표시 옵션이 기본값과 다를 때는 채운 아이콘과 버튼 모서리 점으로 켜진 상태를 드러냅니다.
- 툴바 왼쪽의 뷰 전환은 알약 모양 버튼을 씁니다(데스크톱 28px, 휴대폰 44px).

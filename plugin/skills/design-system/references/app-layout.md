# 앱 셸과 모바일 탐색

앱 셸([AppFrame](https://github.com/dev-goraebap/goraebap-workflow/blob/main/kit/reference/layouts/app/AppFrame.tsx))은 Astryx AppShell과 SideNav 위에 메뉴·페이지·휴대폰 탐색을 조립합니다. 메뉴·테마·밀도는 페이지마다 새로 만들지 않습니다.

## 데스크톱: Inset과 Split

| 배치 | 표현 |
| --- | --- |
| Inset | 바탕(wash) 위에 떨어진 페이지 카드: 위·오른쪽 8px, 16px squircle, 진한 외곽선, 아주 옅은 그림자 |
| Split | 사이드바와 페이지를 진한 가는 선으로 나눈 면. 사이드바 머리 줄이 페이지 머리 줄과 같은 선에 놓입니다 |

두 배치에서 페이지의 머리·툴바·본문 슬롯은 같습니다. 배치는 사용자 설정이며 휴대폰에는 적용하지 않습니다. 분기점·배치를 바꿔도 페이지의 부모 요소 종류를 바꾸지 않아 작성 중인 초안이 다시 마운트되지 않게 합니다.

## 사이드바

열 때 340px, 220~380px로 끌어 조절합니다(큰 화면 배율만큼 함께 커집니다). 다른 제품·지침의 기본(250~320px)보다 넓은 것은 메뉴 이름과 하위 항목을 말줄임 없이 보이기 위한 선택입니다. 좁은 노트북에서 미리보기 패널과 함께 열 때 목록이 좁아지면 사용자가 사이드바를 줄이거나 접습니다. 머리 줄은 페이지 머리 줄과 같은 52px에 로고(홈 링크)·상자 버튼(전역 검색 등)·접기를 둡니다. 접으면 머리를 세로로 쌓고 접기 버튼은 바닥으로 옮기며, 사라진 묶음 이름 대신 선으로 묶음을 나눕니다. 접고 펼친 뒤 초점은 같은 버튼에 남습니다.

메뉴 묶음은 이름으로 나누고 첫 묶음은 이름을 숨길 수 있습니다. 펼친 하위 항목도 상위 항목끼리와 같은 2px(0.125rem) 간격으로 띄웁니다(Astryx SideNav 기본은 하위 묶음 안 간격이 0입니다). 펼친 묶음 끝에는 `--spacing-2`(8px)를 더해 다음 상위 항목과 [경계를 보이고](spacing.md)(항목 사이 2px와 합쳐 10px), 접은 묶음에서는 이 간격이 함께 사라집니다. 하위 메뉴 묶음(`openGroups`)은 메뉴가 짧은 업무 앱에서는 모두 펼치는 `'all'`(기본)을, 묶음이 많은 문서 사이트에서는 현재 위치가 든 묶음만 펼치는 `'current'`를 씁니다. `'current'`에서는 다른 묶음으로 옮겨 가면 그 묶음도 펼치고, 사용자가 직접 연 묶음은 그대로 둡니다. 현재 항목은 주소의 가장 긴 접두사로 정하며 검색 조건으로 나뉜 메뉴는 조건까지 비교합니다. 선택 항목은 Bold Duotone입니다. 메뉴 글자는 보조 글자색으로 두고 포인터가 올라온 항목과 현재 항목만 본문 글자색으로 올립니다. 메뉴가 길어져도 무겁지 않고 현재 위치가 먼저 읽힙니다. 하단 탭과 더보기 시트도 같은 규칙입니다. 내 계정·관리처럼 따로 묶인 공간은 주 메뉴를 대체하고 위에 "← 공간 이름"을 둡니다.

## 휴대폰

사이드바와 하단 탭은 같은 분기점(64rem)에서 바뀌며 동시에 보이지 않습니다.

| 화면 | 구성 |
| --- | --- |
| 일반 페이지 | 52px 머리 줄 하나에 현재 이름(위 단계로 가는 ←)과 끝의 앱 도구(검색·알림·내 메뉴), 필요하면 툴바, 본문, 하단 탭 |
| 상세·양식·대화 | 앱 도구와 하단 탭을 치운 전체 화면. ←·이름·자기 도구, 바닥 고정 동작 줄. 휴대폰 웹은 화면 높이와 키보드 공간이 부족하고 바닥에 제출 동작이 와야 해서 탭을 치웁니다(Apple HIG는 탭을 숨기지 말라고 합니다) |

하단 탭은 현재 메뉴 공간의 앞 네 곳과 더보기입니다. 업무 앱의 목적지는 다섯을 넘는 경우가 많아, 숨긴 메뉴보다 보이는 더보기를 택했습니다(Apple HIG는 More 탭을 피하라고 합니다). 더보기는 탭에 없는 목적지를 바텀시트로 보이며, 하위 공간이면 그 이름과 돌아가기를 둡니다. 하위 목적지는 상위 항목 아래 묶음으로 두고(행 높이 44px·2.75rem), 상위 항목이 하단 탭에 있어도 탭에 없는 하위가 남으면 상위 항목을 묶음 머리로 다시 보입니다. 사이드바와 같은 위계로 하위 항목의 글자는 상위 아이콘 뒤 글자 시작선에 맞춰 들이고, 하위 목적지가 있는 묶음은 앞뒤를 가는 선(1px)과 간격(`--spacing-2`)으로 나눕니다. 탭은 높이 3.5rem에 홈 표시줄을 더하고(아이콘 24px, 이름 11px) 현재 탭은 진한 글자와 Bold Duotone입니다. 만들기 FAB는 56px 정사각(아이콘 24px)으로 하단 탭(3.5rem)과 홈 표시줄 위에 뜨고, 목록 끝에 FAB 높이와 간격만큼 여유를 둡니다. 상세·양식에는 FAB를 두지 않습니다.

`viewport-fit=cover`를 쓰면 페이지 위·좌우와 하단 탭·바닥 줄의 안전 영역을 피합니다. 입력 칸에 초점이 갈 때 바닥 고정 줄이 키보드에 가리지 않는지 실제 기기에서 확인합니다.

## 확인할 동작

검토 메모를 입력하고 배치·테마·창 너비를 바꿉니다. 초안이 남고 페이지 전체에 가로 스크롤이 생기지 않아야 합니다. 사이드바를 끌고 접고 펼치며 키보드 초점을 확인합니다. 휴대폰에서 긴 목록의 마지막 행이 FAB·하단 탭에 가리지 않는지, 상세에서 하단 탭이 사라지는지 확인합니다.

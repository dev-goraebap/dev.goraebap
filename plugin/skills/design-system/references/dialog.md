# 공통 다이얼로그

모든 대화상자는 한 틀([AppDialog](https://github.com/dev-goraebap/goraebap-workflow/blob/main/frontend/reference/composites/dialog/AppDialog.tsx))을 쓴다. 머리·스크롤 본문·선택적 바닥이며 긴 본문에서도 본문만 스크롤하고 제목·닫기·마지막 동작은 보인다. 제품 화면은 Astryx Dialog를 직접 쓰지 않는다.

| 항목 | 기준 |
| --- | --- |
| 위치 | 위에서 12dvh, 아래도 같은 여유. 최대 높이는 `100dvh - 2 × 12dvh` |
| 안 여백 | 좌우·바깥 1rem, 머리 아래·본문 위 0.5rem |
| 바닥 구분선 | 기본은 없다. 긴 본문과 바닥이 붙어 보일 때만 선택한다 |
| 첫 초점 | 제목(`tabIndex=-1`). 입력이 주인 양식은 첫 입력, 확인 창은 취소 |
| 닫기 | 닫기 X·Esc·배경 누르기. 닫으면 초점이 연 요소로 돌아간다 |
| 휴대폰 | 짧은 확인은 같은 틀, 양식은 전체 화면이나 페이지. 전체 화면은 안전 영역을 피한다 |

위치를 지정한 Dialog에 공통 margin을 더하면 top과 겹쳐 아래로 밀린다. 위치와 남은 높이를 함께 정하고 짧은 화면에서도 닫기와 마지막 내용에 닿는지 확인한다.

## 쓰임에 따른 세 가지

| 쓰임 | 부품 | 동작 |
| --- | --- | --- |
| 되돌리기 어려운 결정 | AlertDialog | 닫기 X와 제목 초점 없이 취소에 첫 초점. 휴대폰은 버튼을 세로로 쌓고 주 동작을 위에 |
| 몇 칸의 짧은 양식 | FormDialog | 칸 곁의 입력 오류와 칸 아래 실패 이유, 바닥 취소·제출. 제출 버튼은 비활성화하지 않고 누르면 검사한다. 한 줄 칸의 Enter는 제출(한글 조합 중 제외). 저장 중에는 닫기를 막는다. 휴대폰은 전체 화면 |
| 제목·본문이 있는 작성 | ComposeSurface | [생성 양식](creation-form.md). 자기 주소가 있고 페이지로 확장한다 |

입력이 있는 대화상자를 닫기·Esc·배경·뒤로가기로 닫을 때 버릴지 묻는 정책을 제품에서 하나로 정한다. 키트의 작성 양식은 입력이 있으면 "계속 작성 / 버리기"를 묻는다.

## 확인할 동작

긴 본문만 스크롤되고 제목·닫기·바닥이 보이는지, 닫기와 Esc 뒤 열기 버튼으로 초점이 돌아오는지 확인한다. 바닥 구분선은 고른 경우에만 보인다. 견본은 열기 버튼과 대화상자만 둔다.

# 지침 개선 기록

## 2026-11-05 · 제작 맥락의 화면 노출

- 증상: 견본 화면의 바닥글에 사용자 업무와 무관한 제작·검증 안내가 남았고, 본문과 부제도 화면 구조 자체를 설명했다.
- 원인: 슬롯과 빈 공간을 설명 문구로 채우고, 검토자를 위한 기록과 실제 사용자에게 필요한 안내를 구분하지 않았다.
- 수정: 문구의 대상·판단/행동 영향·중복·표시 시점을 기준으로 선택한다. 슬롯을 채울 의무를 없애고 렌더링된 보조 문구를 검토 절차에 포함한다. 저장 범위·오류 복구·접근성 이름처럼 필요한 정보는 보존한다.
- 특정 문자열 차단으로 처리하지 않는다. 임시 화면에서 제작 안내·중복 부제를 제거하고, 견본 본문을 업무 내용으로 바꾸어 확인한다.

## 2026-11-05 · 새 프로젝트의 브라우저 검증

- 증상: 레퍼런스 안내대로 초기화했지만 목록 버튼에 브라우저 기본 테두리·배경이 남았다.
- 원인: reset.css와 reset → astryx-base → astryx-theme의 선행 레이어 선언이 안내에 빠졌다. 런타임 테마가 뒤늦게 reset 레이어를 만들면 초기 레이어 순서가 달라질 수 있다.
- 수정: 앱 초기화 CSS와 import 순서를 안내하고 실제 버튼의 기본 스타일 잔존 여부를 검증 절차에 넣었다.
- 증상: 본문 편집 중 반응형 전환점을 넘으면 초안이 사라졌다.
- 원인: WorkspaceShell이 Card와 VStack 사이에서 본문 부모 타입을 바꾸어 페이지를 다시 마운트했다.
- 수정: 같은 Card 부모를 유지하고 page·page-flat 변형과 배치 props만 바꾼다. 창 크기·셸 전환 중 초안 유지 검증을 추가했다. 키트는 revision 2다.
- 확인: 독립 로컬 예제의 목록·설정·상세, 1440×960·1024×800·390×844·320×740에서 화면과 관련 동작을 확인했다. 수정 후 breakpoint·셸 전환 시 초안이 유지됐다.
- 범위: 가상 데이터와 로컬 저장 예제다. 실제 서버 연동·실기기 키보드·원본 화면과의 픽셀 일치는 확인하지 않았다.

## 2026-11-05 · 페이지 Card와 위치 지정 모달

레퍼런스의 page 변형에 테두리가 빠졌고 공통 Dialog margin이 position의 top과 겹쳤다. page에 테두리를 명시하고 공통 margin을 제거했다. 사용자 정의 변형의 조건부 스타일과 위치·본문 스크롤을 실제 화면에서 확인하도록 지침을 보완했다.

- 페이지 구현 전 기존 Page의 슬롯과 공통 도구를 확인한다. 검색·조건·표시와 생성 동작을 뷰 알약으로 새로 그리지 않고 각 역할의 슬롯에 연결한다.

## 2026-11-07 · 키트와 카탈로그의 재정비

- 증상: 키트(`frontend/reference`)와 카탈로그 예제가 셸·페이지를 따로 구현했다. 예제는 사이드바·메뉴·검색을 직접 그린 1,100줄이 넘는 전역 CSS를 썼고, 키트의 테마는 경계선 두 단계가 하나로 합쳐지고 초점 색·점 무늬 토큰이 빠져 있었다. 문서 안 견본은 상단 테마 선택을 따르지 않았다.
- 원인: 실제 제품 구현을 옮기며 일부만 요약하고, 예제를 키트 위가 아니라 옆에 만들었다. 문서 견본 iframe은 Storybook 전역 값 변경을 받지 못한다.
- 수정: 키트를 foundations·composites·layouts·patterns로 나누고 예제와 Story가 키트만 쓰게 했다. 지침을 카탈로그의 여섯 범주에 맞춰 나누었다. 원본 제품에서 문서와 다르게 구현된 부분(분기점 혼용, 작성 양식의 초안 유실·닫기 확인 없음, 목록마다 다른 조건 소유·더 보기 표시, 초점 선을 hover 채움으로 대신한 메뉴 행)은 문서의 의도대로 공통 규칙을 정했다.
- 확인: 타입·정적 빌드·Storybook 상호작용 검사와 브라우저의 라이트·다크·데스크톱·휴대폰 확인. 실기기 키보드와 화면 낭독기는 확인하지 않았다.

## 2026-11-07 · Storybook을 걷고 가이드에 견본을 넣음

- 결정(사용자): 견본은 가이드 사이트의 MDX 안에 실제 키트 부품으로 넣는다. 정적 그림·캡처만 두는 안은 조작할 수 없고 키트가 바뀔 때마다 다시 떠야 해서 기각했다.
- 방식: 견본 파일(`*.samples.tsx`)은 CSF 형식을 유지하되 Storybook에 의존하지 않는다. 가이드는 견본을 iframe(`/samples/…`)으로 띄워 키트 CSS가 가이드 화면에 섞이지 않게 한다. 키트는 창 폭으로 휴대폰을 판정하므로 iframe을 실제 폭(1024·1280·390px)으로 그리고 좁은 본문 칸에서는 줄인다. 조작 검증은 견본에서 떼어 `*.test.tsx`로 옮기고 Vitest 브라우저 모드에서 실행한다.
- 서가 그리드 카드는 카드 위쪽에 종류별 바탕과 기울어진 종이를 두어 문서가 들어 있는 모습을 준다(이전 카탈로그의 카드 모양을 사용자가 남기기로 함). 바탕색은 자료 종류 구분에만 쓴다.
- 범주 정리(사용자): Examples (화면 예제)를 Playground (플레이그라운드)로 바꾸고 화면 템플릿을 계속 늘려 가는 곳으로 둔다. 미리보기 패널·생성 양식·서가는 템플릿(목록, 목록 + 미리보기, 상세, 작성, 설정)으로 옮겼다. 라우트 마스킹·데이터 상태·입력과 상호작용은 여러 템플릿이 지키는 계약이라 Patterns에 남기고, 그 견본은 템플릿을 해당 상태로 띄운다. 사용 패턴을 없애는 안(화면에 묶이지 않는 여는 방식을 견본 메뉴에서 찾을 수 없음)과 모두 템플릿으로 만드는 안(같은 계약이 여러 템플릿에 흩어짐)은 기각했다.
- 가이드 화면(사용자, 일단 시도): 키트의 기초 토큰(색·면·경계·강조·글꼴)만 Starlight에 입힌다. 토큰은 `theme.ts`에서 생성해 값이 두 곳으로 갈라지지 않게 한다. 가이드는 문서 사이트라 앱 셸 규칙(340px 사이드바, 52px 머리 줄)은 쓰지 않았다. 앱 셸까지 입히는 안은 Starlight의 검색·목차·문서 이동을 다시 만들어야 해서 미뤘다.
- 가이드 틀(사용자): 기초 토큰만 입힌 Starlight는 "고래밥 프론트 규칙에서 다루는 느낌이 아니다"는 판단으로 걷어냈다. 가이드 자체를 키트의 AppFrame·Page로 그리고, 본문은 읽는 화면이라 약 720px 열과 15px 본문을 쓴다. 검색은 Astryx CommandPalette, 문서 안 목차는 Outline으로 대신했다. 문서 사이트 유형의 규칙은 아직 정하지 않았으므로 이 틀은 앱 셸 규칙을 빌려 쓴 상태다.
- 메뉴 글자색(사용자, 키트 테마에서): 메뉴 글자가 본문과 같은 색이라 가이드처럼 메뉴가 40개를 넘으면 무겁게 보였다. 메뉴 글자는 보조 글자색, 포인터가 올라온 항목과 현재 항목만 본문 글자색으로 정했다. 가이드에서만 바꾸는 안은 키트와 가이드의 모양이 갈라져 기각했다.
- 글꼴 누락: 키트 테마는 Pretendard Variable을 이름으로만 부르고 글꼴 파일을 불러오지 않아 Windows에서 맑은 고딕으로 대체되었다(원본 제품보다 글자가 흐려 보임). 원본처럼 base.css에서 Pretendard 동적 분할판과 JetBrains Mono를 불러오게 고쳤다.
- 가이드 이동(사용자): 문서마다 페이지를 새로 불러와 테마 재삽입·셸 재마운트로 빈 화면과 사이드바 초기화가 생겼다. Astro 클라이언트 라우터로 셸을 유지하고 본문만 바꿔 끼우게 했다. React SPA로 다시 짜는 안은 작업이 크고 정적 HTML을 잃어 기각했다.
- 가이드 이동 뒤 글자 커짐: Astro 클라이언트 라우터가 이동할 때 새 문서에 없는 head 요소를 지우면서, Astryx가 실행 중에 넣은 테마 스타일(data-astryx-theme*)도 지웠다. 셸은 유지되어 다시 넣지 않으므로 글자 크기가 Astryx 기본값(17px)으로 돌아갔다. 옮기기 직전에 그 스타일에 유지 표시를 달아 남기게 했다. 키트로 만든 앱을 Astro 클라이언트 라우터 위에 올릴 때 같은 처리가 필요하다.
- 가이드 전환(사용자, 원본 제품의 전환 방식 참고): 데이터 상태 규칙(다음 화면이 준비될 때까지 지금 화면 유지, 180ms 넘을 때만 덮개, 160ms 교차 페이드)을 가이드에도 적용했다. 새 본문은 보이지 않게 겹쳐 두고 글꼴 조각과 부품 견본 높이가 정해진 뒤(최대 0.8초) 바꾼다. 큰 화면의 루트 글자 키움은 부품 견본 iframe에도 가이드의 루트 크기를 넘겨 맞췄다(앱 화면 견본은 셸이 창 폭으로 정하므로 제외).
- 견본 기기 전환(사용자): 휴대폰 견본을 따로 두지 않고, 가이드의 견본 틀 오른쪽 위에서 데스크톱·휴대폰을 바꿔 같은 견본을 본다. 내용이 같던 휴대폰 견본 13개를 지우고, 검사는 모든 견본을 두 기기로 그린다.
- 본문 칸 글자(사용자): 리치 에디터와 그 글을 읽는 상세 본문을 15px(`--text-large-size`)로 키웠다. Astryx 테마가 문단에 화면 글자 크기를 직접 주므로 문단은 칸의 크기를 따르게 했다.
- Playground에 문서 편집(리치 에디터·자동 저장)과 자료 올리기(올리기 칸·파일별 상태) 템플릿을 더했다.
- 본문 칸 목록 기호: 전역 reset이 목록 기호를 지워 리치 에디터의 글머리표·번호가 보이지 않았다(원래 있던 결함). 본문 칸에서 되살렸다.

## 2026-11-08 · 첫 화면(첫 방문 덮개·SSG)

- 증상: 앱 코드가 오기 전 빈 화면이 보였다. 원본 제품에는 빌드 때 index.html에 넣는 첫 방문 덮개가 있었으나 키트와 스킬로 옮기지 않았다.
- 결정(사용자): 첫 화면 규칙을 새로 적립한다. 업무 앱은 첫 방문 덮개, 공개 문서·랜딩은 SSG로 실제 본문을 넣는다. 덮개 그림은 제품마다 자기 표시로 바꾸며 원본 제품의 그림은 옮기지 않았다(키트 기본은 중립 그림).
- 수정: 스킬 data-states에 "첫 화면", motion에 덮개 걷기 시간을 적었다. 키트에 patterns/boot(BootCover, bootCover 플러그인, 덮개 색)를 두고 덮개 색이 테마 값과 같은지 검사한다. 가이드에도 같은 덮개를 넣었다.

## 2026-11-08 · 가이드를 React 스택으로

- 결정(사용자): 가이드를 Astro에서 키트와 같은 Vite + React + TanStack Router + MDX SPA로 옮겼다. Astro 때문에 둔 우회(셸 유지, 테마 스타일 붙잡기, 넘겨받을 때까지 감추기, 본문 옮겨 끼우기)가 사라지고, 전환은 라우터 대기 + 180ms 덮개 + 160ms 페이드로 키트 규칙 그대로 구현했다. 첫 화면은 키트의 bootCover·BootCover를 쓴다.
- 사이트는 플러그인 지침 전체를 보여 준다. 지침 문서는 스킬 Markdown을 원본 그대로 빌드한다(사본 없음). 문서별 정적 HTML(SSG)은 아직 없다. 공개할 때 프리렌더를 붙인다.

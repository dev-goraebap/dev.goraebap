# 제품 플러그인 관리

제품이 사용자에게 MCP 연결과 사용법을 제공할 때 적용한다. 저장소 개발용 스킬과 사용자에게 배포할 스킬은 읽는 사람과 목적이 다르므로 원본을 나눈다.

## 원본과 배포본

저장소 개발 규칙은 프로젝트 AGENTS.md(길면 `.agents/rules`)에 둔다. 사용자용 스킬은 제품이 관리하는 `plugins/<플러그인>/skills` 같은 별도 경로에 둔다. 사용자용 본문에 개발 팀의 서버 주소·프로젝트 키·이슈 처리 정책을 넣지 않는다. 제품 개발 팀도 공통 사용법은 그 원본을 읽고, 팀 설정과 기록 정책만 프로젝트 지침에 둔다.

지원할 에이전트가 여럿이면 스킬 본문은 함께 쓰고 manifest·마켓플레이스·연결 설정을 에이전트별로 만든다. 다른 설치 형식이 필요하면 허용한 원본 파일만 패키징한다. 생성된 배포본을 직접 고치지 않는다. 명령을 지원하지 않는 에이전트에서도 필요한 작업은 스킬로 사용할 수 있게 한다.

## 설치와 연결

사용자 범위 설치를 기본으로 안내한다. 설치한 플러그인이 제공하는 공통 사용법과 각 프로젝트가 채택한 작업 규칙을 구분한다. 설치만으로 저장소 규칙을 바꾸지 않는다.

주소·인증·설정 입력 방식은 각 에이전트의 현재 지원을 확인한다. 한 에이전트의 변수 치환이나 비밀값 저장 방식이 다른 에이전트에서도 작동한다고 가정하지 않는다. 필요한 설정만 온보딩에서 확인하고 토큰은 지원되는 로컬 비밀 저장 수단으로 받는다. 설치 명령이 성공한 뒤에는 실제 연결과 사용자 조회까지 별도로 확인한다.

## 변경과 검증

MCP 도구가 바뀌면 서버 계약과 사용자용 설명을 함께 맞춘다. 스킬에 없는 도구나 아직 제공하지 않는 기능을 약속하지 않는다. 패키지 버전과 서버의 호환 범위, 이름이 바뀐 경우 기존 사용자의 전환 방법을 기록한다.

배포 전에는 각 에이전트에서 패키지 등록·설치·스킬 발견을 확인한다. 연결·인증·권한도 실제로 확인하고 수행하지 못한 범위를 남긴다. 비밀값·개발 팀 설정·비공개 참고 자료가 패키지에 섞이지 않았는지 확인한다. 플러그인 갱신으로 프로젝트의 정책이나 연결 대상을 덮어쓰지 않는다.

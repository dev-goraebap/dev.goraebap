# 지침 개선

1. 실제 실패나 사용자 피드백을 근거로 빠진 규칙·잘못된 도구·놓친 검증 중 원인을 찾는다. 한 사례를 모든 프로젝트의 절대 규칙으로 만들지 않는다.
2. 다음 변경이 이 프로젝트만의 결정인지, 여러 프로젝트에 맞는 공통 개선인지 구분한다. 당장 구분할 수 없으면 이 프로젝트의 결정으로 먼저 둔다.
3. 이 프로젝트만의 결정은 프로젝트 AGENTS.md의 프로젝트 규칙 표에 이유와 함께 적는다([프로젝트 규칙](../../manage-workflow/references/project-rules.md)). 경고를 늘리기 전에 자동 검사나 구조로 실수를 막을 수 있는지 검토한다.
4. 같은 상황에서 결과가 달라지는지 확인한다. 경미한 문구 수정에 불필요한 전체 앱 검사를 요구하지 않는다.
5. 공통 개선은 플러그인 원본 수정으로 제안한다. 고칠 지침 파일, 바꿀 문장, 근거를 정리해 사용자에게 보이고, 원본은 사용자가 요청할 때 플러그인 저장소에서 고친다. [글쓰기 기준](../references/writing.md)을 따른다.
6. 원본에 반영되고 플러그인을 갱신하면 프로젝트 규칙 표의 같은 줄을 지운다.

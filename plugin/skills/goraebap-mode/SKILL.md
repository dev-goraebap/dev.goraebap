# 웹 플랫폼 작업 방식

프로젝트가 채택한 개발 방식이다. 현재 프로젝트의 AGENTS.md를 먼저 읽는다. AGENTS.md의 "프로젝트 규칙"은 이 플러그인의 지침보다 우선한다. 지침을 읽다가 프로젝트 규칙과 다른 곳을 만나면 프로젝트 규칙을 따른다. 작업 중에 지침과 다른 새 결정을 내리면 프로젝트 규칙 표에 이유와 함께 남긴다([프로젝트 규칙](../manage-workflow/references/project-rules.md)). 플러그인 원본과 다른 프로젝트는 자동으로 바꾸지 않는다.

## 시작

사용자가 원하는 결과를 짧게 설명하고 기존 변경·staging 상태를 확인한다. 제품 동작이 달라지면 관련 요구사항과 설계를 읽는다. 기록 위치와 이슈 도구는 프로젝트가 정한다. 연결되지 않은 도구를 필수로 가정하거나 조회만 하는 질문에 업무를 만들지 않는다.

작업에 맞는 플레이북 하나를 읽고, 계약·스키마 변경 같은 의존 단계만 함께 수행한다. 작은 수정은 필요한 단계만 적용한다.

| 작업 | 플레이북 |
| --- | --- |
| 코드·설계 설명, 근거 조사 | [조사](playbooks/investigate.md) |
| 새 기능·제품 동작 변경 | [기능](playbooks/feature.md) |
| 버그 재현·수정 | [버그](playbooks/bug-fix.md) |
| 동작을 유지하는 구조 변경 | [리팩터링](playbooks/refactor.md) |
| 반복 실수·작업 방식 개선 | [지침 개선](playbooks/evolve.md) |

## 필요한 지침만 읽기

아래 링크에서 필요한 지침만 읽는다. 관리 도구로 이름을 바꿔 설치하면 스킬 메타데이터와 지침 링크도 함께 바뀐다.

| 바꾸는 것 | 읽을 스킬 |
| --- | --- |
| React 화면·상태·라우트 | [프론트엔드](../frontend/SKILL.md) |
| UI 부품·테마·아이콘 | [디자인 시스템](../design-system/SKILL.md) |
| Java 모듈·도메인·서비스 | [백엔드](../backend/SKILL.md) |
| HTTP·오류·인증·생성 타입 | [API](../api/SKILL.md) |
| 스키마·마이그레이션 | [DB](../database/SKILL.md) |
| 시스템 경계·새 기술·운영 | [아키텍처](../architecture/SKILL.md) |

프론트엔드는 상태와 코드 구조, 디자인 시스템은 화면 표현을 다룬다. 백엔드는 도메인·서비스·트랜잭션, DB는 스키마·마이그레이션, API는 외부 HTTP 계약을 다룬다. 여러 영역을 바꾸면 관련 지침을 함께 읽는다. 규칙 본문은 담당 지침 한 곳에서 고치고 다른 지침에서는 연결한다.

스킬·참고 자료·문서를 작성하거나 고칠 때는 [글쓰기 기준](references/writing.md)을 읽는다. 스킬 본문과 예시에도 같은 기준을 적용한다.

## 진행과 완료

- 관례와 코드로 확인할 수 있는 것은 확인하고 진행한다. 제품 의미·팀 선택이 갈리는 부분만 질문한다.
- 데이터 소유권·입출력·실패 상태를 정한 뒤 구현한다. 추측한 재사용을 위해 계층을 늘리지 않는다.
- 도구와 모델은 실행 환경에서 제공하는 것을 사용한다. 특정 모델, 다중 에이전트, 자동 커밋·병합을 전제하지 않는다.
- [검증](references/verification.md)에 따라 바뀐 부분을 확인한다. 수행한 검증과 남은 제한을 구분해 답한다.
- 커밋·푸시·게시·배포는 사용자가 허용한 범위에서만 한다.

스킬 자체가 틀렸으면 [지침 개선](playbooks/evolve.md)으로 원인을 고친다.

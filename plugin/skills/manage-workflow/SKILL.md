# 프로젝트와 지침 연결

프로젝트는 지침 사본을 두지 않습니다. 지침의 원본은 사용자 범위에 설치한 goraebap-workflow 플러그인이고, 프로젝트에는 AGENTS.md 하나만 둡니다. AGENTS.md는 플러그인 지침을 따른다고 밝히고, 이 프로젝트만 다르게 하는 규칙을 적습니다. 플러그인을 갱신하면 모든 연결된 프로젝트가 새 지침을 따릅니다.

요청에 맞는 절차 하나를 수행합니다. 커밋·푸시·플러그인 설치는 사용자가 요청했을 때만 합니다.

| 요청 | 절차 |
| --- | --- |
| 새 프로젝트를 지침에 연결 | [연결](#연결) |
| 프로젝트만 다르게 하는 규칙 추가·정리 | [프로젝트 규칙](references/project-rules.md) |
| 예전 사본 방식(`.agents/skills`의 지침 사본·동기화 훅)에서 바꾸기 | [사본에서 전환](references/migrate-from-copies.md) |
| 프로젝트 규칙 중 공통으로 올릴 것 찾기 | [회수](#회수) |

## 연결

1. 현재 폴더의 Git 루트, status와 staging, 기존 AGENTS.md·CLAUDE.md·`.agents/skills`를 읽습니다. 다른 저장소는 바꾸지 않습니다.
2. 예전 사본(접두사가 붙은 `*-mode`·`*-frontend` 같은 지침 폴더, `scripts/sync-skills.mjs`, 동기화 시작 훅)이 있으면 연결 대신 [사본에서 전환](references/migrate-from-copies.md)을 따릅니다.
3. AGENTS.md에 아래 "개발 지침" 블록을 넣습니다. 파일이 없으면 만들고, 있으면 기존 프로젝트 설명과 팀 규칙을 보존한 채 블록만 더합니다. 최소 판은 설치된 플러그인의 판(`plugin.json`의 `version`)으로 적습니다.
4. 기존 AGENTS.md에 지침과 다른 결정이 이미 있으면 [프로젝트 규칙](references/project-rules.md) 표로 옮깁니다. 확인할 수 없는 의도는 추정하지 말고 사용자에게 묻습니다.
5. 바꾼 파일과 남은 확인 사항을 보고합니다.

```markdown
## 개발 지침

이 프로젝트는 goraebap-workflow 플러그인(0.5.0 이상)의 지침을 따릅니다. 작업을 시작할 때 goraebap-mode를 읽고, 바꾸는 영역의 지침(frontend·design-system·backend·api·database·architecture)을 함께 읽습니다. 아래 프로젝트 규칙이 지침과 다르면 프로젝트 규칙을 따릅니다.

## 프로젝트 규칙

| 지침 | 지침의 기준 | 이 프로젝트 | 이유 |
| --- | --- | --- | --- |
```

표가 비어 있으면 표 대신 "지침과 다르게 하는 것은 없습니다."라고 적습니다. 개인 설치 경로나 플러그인 내부 파일 경로는 AGENTS.md에 넣지 않습니다.

## 회수

프로젝트 규칙 중 다른 프로젝트에도 맞는 것을 찾습니다. 제품 고유의 업무 규칙, 회사 정보, 실험 중인 결정은 제외합니다. 후보마다 고칠 플러그인 지침 파일, 바꿀 문장, 이유를 정리해 사용자에게 제안합니다. 플러그인 원본은 사용자가 요청할 때 그 저장소에서 따로 고칩니다. 원본에 반영된 규칙은 프로젝트 규칙 표에서 지웁니다.

# 상태와 데이터 흐름

| 상태 | 소유자 |
| --- | --- |
| 서버 데이터·캐시 | TanStack Query |
| 경로·확정 필터·정렬·페이지·탭 | TanStack Router의 검증한 URL |
| 입력 초안·적용 전 필터·열림 상태 | 로컬 state 또는 해당 슬라이스 model |

- 조회를 소유한 슬라이스의 api에 요청·키·queryOptions를 함께 둡니다. loader와 페이지는 같은 옵션을 씁니다. 응답을 바꾸는 모든 인자를 키에 넣습니다.
- ensureQueryData가 최신 응답을 보장한다고 가정하지 않습니다. 최신 응답을 기다려야 하면 fetchQuery와 staleTime을 명시합니다.
- 서버 데이터와 수정 초안을 분리합니다. 백그라운드 재조회로 입력을 덮지 않습니다. 저장 충돌 시 초안을 유지하고 다시 읽기·재적용 방법을 제공합니다.
- 기본 변경 흐름은 mutation 성공 후 관련 키 무효화입니다. 저장 성공 후 재조회 실패를 저장 실패로 알리지 않습니다. 낙관적 갱신·명령 자동 재시도는 기본으로 켜지 않고 중복 실행·복구 비용을 확인해 선택합니다.
- 하위 부품이 페이지의 키를 직접 참조하지 않도록 콜백을 전달하거나 상태 소유자를 조정합니다.
- 초기 로딩·정상 빈 결과·조회 오류를 구분합니다. 계정·권한 전환 때 이전 범위의 캐시가 노출되지 않도록 조회 취소와 캐시 제거를 처리합니다.
- 큰 목록은 서버에서 필터·정렬·페이지를 처리합니다. 무한 목록은 보관 중인 조각 전체가 재조회되는 비용을 확인하고 목록 복귀·새 진입·갱신 정책을 따로 정합니다. 프로젝트에 없는 목록 도우미를 임의로 호출하지 않습니다.

필터를 확정할 때 URL 갱신·페이지 초기화·조회 키 변경을 같은 상태 전환으로 다룹니다. 적용 전 선택은 초안이며 취소하면 기존 URL을 유지합니다. 숫자·날짜·열거형과 기본값을 검증하고, 새로고침·링크 공유·뒤로가기에서도 같은 조건이 복원되는지 확인합니다. 칩·선택기·모바일 Sheet의 표현 규칙은 디자인 시스템 지침에 둡니다.

저장 중에도 편집할 수 있다면 저장 요청의 초안 판본과 현재 초안을 구분합니다. 늦게 도착한 성공 응답이 이후 입력을 초기화하지 않게 합니다. 연속 저장의 직렬화·충돌·재시도 정책을 정하고 문서나 계정이 바뀐 뒤 도착한 응답도 격리합니다. 읽기·편집 전환과 저장 표시 방식은 디자인 시스템 지침을 따릅니다.

# 고래밥 워크플로우 플러그인

웹 플랫폼 개발 지침을 배포한다. 식별자와 버전은 이 폴더의 package.json이 소유한다.

- skills는 지침의 원본이다. goraebap-mode가 작업 입구, manage-workflow가 프로젝트 연결·프로젝트 규칙·사본 전환·회수다.
- scripts와 tests는 지침 검사·배포본 생성·배포본 검증을 맡는다.
- dist는 두 에이전트의 생성 배포본이다. 직접 수정하지 않는다.

설치와 사용은 [플러그인 안내](docs/plugin-usage.md)를 따른다. 저장소 루트의 npm test, npm run check, npm run package:plugins는 이 폴더의 명령에 연결한다.

프론트엔드 구현·견본과 가이드 사이트(`kit/guide/`)는 [kit](../kit/README.md)에서 관리하며 배포하지 않는다. 스킬에는 사용 기준과 공개 코드 링크만 둔다. 루트의 마켓플레이스 연결 파일을 통해 plugin/dist의 생성본을 설치한다.

## 결정 기록

- 2026-11-09 · 호출 범위(사용자): 0.5.0에서 스킬 8개의 명시 호출 전용을 모두 풀었더니 영역 지침(frontend·design-system·backend·api·database·architecture)의 설명이 범용이라 goraebap-workflow를 쓰지 않는 프로젝트에서도 끼어들 수 있었다. 영역 지침 6개는 다시 명시 호출 전용(Claude `disable-model-invocation: true`, Codex `agents/openai.yaml`의 `allow_implicit_invocation: false`)으로 되돌리고, 입구인 goraebap-mode와 연결 도구인 manage-workflow만 자동 호출을 허용하되 설명문에 조건을 걸어 AGENTS.md에 goraebap-workflow를 따른다고 적은 프로젝트나 사용자가 이름으로 요청했을 때만 쓰게 했다. 영역 지침은 goraebap-mode가 링크로 파일을 읽어 쓰고, 사람은 `/goraebap-workflow:frontend`처럼 부를 수 있다. 감수한 것: "AGENTS.md가 있을 때만"은 설명문 조건이라 에이전트 판단에 기대며, 연결 안 된 프로젝트에서 영역 지침은 사람이 불러야 한다.
- 2026-11-09 · 지침 제안함(사용자): 프로젝트 작업 중 요청이 기존 지침과 부딪히면 에이전트가 그때만 한 번 예외·제안·지침대로 중 하나를 묻고, 제안이면 작업을 멈추지 않은 채 프로젝트 규칙 표의 이유 칸 끝에 `제안 중: <제안 파일 이름>`을 붙이고 로컬 제안함(`~/.goraebap/proposals/`)에 회사 정보를 일반 표현으로 바꾼 제안서를 쌓는다. goraebap-workflow 저장소 세션에서 사용자가 요청할 때 제안서를 검토해 반영하거나 버리고 `~/.goraebap/proposals/done/`으로 옮긴다. GitHub 이슈는 공개 저장소라 회사 작업 근거가 공개될 위험이 있어 기각했고, 프로젝트 세션에서 바로 PR을 올리는 안은 다른 저장소 체크아웃·글쓰기 역할 위임·판 올리기가 끼어 무거워 기각했다. 감수한 것: 제안함이 이 컴퓨터에만 있다.
- 2026-11-09 · 에셋 역할(사용자): 로고·아이콘 그림·일러스트·화면에 쓰는 이미지는 에이전트가 직접 만들지 않고 인계 문서 하나로 에셋 역할에 맡긴다. 프로젝트 규칙 → 사용자 설정 파일(`~/.claude/rules/goraebap-models.md`)의 `asset:` → `codex exec`(Codex 설정 모델) → 에이전트가 SVG만 직접 만드는 순서로 고른다. 감수한 것: Codex 사용 시 인계 문서와 참고 그림이 OpenAI 쪽 모델로 나가고, Codex가 없으면 래스터 이미지를 만들 수 없다.
- 2026-11-08 · 글쓰기 역할(사용자): 사람이 읽는 문서와 스킬·참고 자료 본문은 에이전트가 직접 쓰지 않고 글쓰기 역할에 맡긴다. pstack의 역할별 모델 설정을 본떠 사용자 설정 파일(`~/.claude/rules/goraebap-models.md`) → `agy` Gemini 4 Argon high → Claude `opus` 순서로 고르고, 프로젝트 규칙이 있으면 우선한다. 스킬에 모델을 고정하는 안은 다른 환경에서 깨져 기각했고, 문서마다 따로 부르는 안은 사용자가 인계 문서 하나로 정해 기각했다. 감수한 것: `agy` 사용 시 내용이 외부 모델로 나가고, Codex에서는 하위 에이전트 모델을 고르지 못해 세션 모델이 쓴다.
- 2026-11-08 · 사본 방식 폐지(사용자): 프로젝트에 지침 사본과 동기화 훅을 두던 방식을 걷어냈다. 지침을 쓰는 사람이 플러그인을 설치한 본인뿐이라 양쪽 관리가 비용만 늘렸다. 프로젝트는 AGENTS.md로 플러그인을 가리키고, 다른 결정만 "프로젝트 규칙" 표에 적는다. 지침은 에이전트가 스스로 불러 쓰도록 명시 호출 전용을 풀었다. 감수한 것: 플러그인 갱신이 모든 프로젝트에 바로 적용되고, 프로젝트 저장소만으로는 당시 지침 판을 알 수 없다(AGENTS.md의 최소 판으로만 남는다).
